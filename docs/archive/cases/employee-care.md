## 问题

HR 用日历记员工生日，人一多就漏；漏了的员工觉得公司不重视；入职周年也没人记得。

## 适用场景

- 适合：重视员工关怀、人数几十人以上的公司
- 不值得：几个人的小团队
- 前提：员工档案有生日和入职日期，员工同意

## 工具选型

| 方案                   | 特点     | 适用        |
| ---------------------- | -------- | ----------- |
| HR 系统自带关怀提醒    | 开箱即用 | 国内外都有  |
| 企业微信 / 钉钉 + 脚本 | 卡片消息 | ✅ 方案采用 |
| 飞书多维表格自动化     | 零代码   | 国内常用    |
| 日历提醒               | 现状     | 人多就漏    |

实现简单、效果好，是推广自动化最容易让员工有感的场景之一。

## 怎么做

- 每天读取员工的生日和入职日期，当天给本人发企业微信祝福卡片
- 提前一天提醒直属主管，方便当面祝福
- 入职满 1、3、5 年的发周年祝福，并提醒 HR 准备纪念品
- 每月初给行政一份当月生日名单，准备生日会

## 实施步骤

| 步骤 | 做什么               | 怎么验证           |
| ---- | -------------------- | ------------------ |
| 1    | 确认员工同意公开生日 | 有选择不提醒的选项 |
| 2    | 读取生日和入职日期   | 数据准确           |
| 3    | 设计祝福卡片         | HR 确认文案        |
| 4    | 发本人和提醒主管     | 测试账号收到       |
| 5    | 每月名单给行政       | 月初收到           |

## 关键代码

示例代码（简化），没有在生产环境运行：

```python
for emp in hr.active_employees():
    if (emp.birthday.month, emp.birthday.day) == (today.month, today.day) and emp.allow_birthday_notice:
        wecom.send_card(emp.userid, title="生日快乐！", desc=f"{emp.name}，祝你生日快乐。")
    years = today.year - emp.hire_date.year
    if (emp.hire_date.month, emp.hire_date.day) == (today.month, today.day) and years in (1, 3, 5, 10):
        wecom.send_card(emp.userid, title=f"入职 {years} 周年", desc="感谢你一路同行！")
```

## 效果指标

| 指标     | 做之前     | 预期效果（估算） |
| -------- | ---------- | ---------------- |
| 漏记生日 | 常见       | 零遗漏           |
| HR 投入  | 每天查日历 | 0                |
| 员工感受 | —          | 感到被重视       |

每个员工的生日和周年都不会被遗漏，HR 不用再记日子。

## 常见坑

- **有员工不希望被祝福生日**：隐私或文化原因。提供退出选项。
- **农历生日**：只按公历计算。档案里区分农历，转换后提醒。
- **离职员工还在名单**：档案没更新。只取在职员工。

## 面试怎么讲

30 秒讲法（方案思路；没有实际落地，面试时如实说明是设计过的方案）：

> 我会每天从 HR 系统读取在职员工的生日和入职日期，当天给本人发企业微信祝福卡片，提前一天提醒直属主管，入职满 1、3、5 年发周年祝福并提醒 HR 准备纪念品，每月初给行政一份生日名单。员工可以选择不接收生日提醒。

常见追问：

**问：为什么这种简单场景值得做？**

答：成本低、员工感受强，是让全公司感受到自动化价值、推动更多自动化的好起点。

**问：员工隐私怎么处理？**

答：生日属于个人信息，只在员工同意时使用，提供退出选项。

**问：企业微信卡片消息怎么发？**

答：通过自建应用调用消息接口，消息类型选 textcard 或模板卡片。

**被问到「能不能用 AI」时：** 日期用规则判断，AI 让祝福语更个性化。
