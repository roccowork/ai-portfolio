## 问题

客服每天大量电话问「货到哪了」；快递在中转站滞留好几天没人发现，等客户投诉才去查。

## 适用场景

- 适合：每天发货量较大的电商、贸易、制造企业
- 不值得：发货很少的
- 前提：快递单号能在发货时录入系统

## 工具选型

| 方案              | 特点                   | 适用        |
| ----------------- | ---------------------- | ----------- |
| 快递 100 / 快递鸟 | 聚合接口，覆盖多家快递 | 国内常用    |
| 快递公司开放平台  | 直接对接               | 单一快递    |
| AfterShip         | 跨境物流跟踪           | 外企 / 跨境 |
| 电商平台自带      | 平台订单               | 电商        |

发多家快递用聚合接口，订阅推送比轮询省资源。

## 怎么做

- 发货后自动用快递单号订阅物流轨迹（快递 100 等聚合接口或快递公司开放接口）
- 状态变化通过 Webhook 推送：已揽收、派送中、已签收时通知客户
- 超过 48 小时没有更新、退回、派送失败的标为异常件，通知客服主动处理
- 统计各快递公司、各线路的平均时效和异常率，用于选择快递

## 实施步骤

| 步骤 | 做什么         | 怎么验证           |
| ---- | -------------- | ------------------ |
| 1    | 发货时录入单号 | 单号和订单关联     |
| 2    | 订阅轨迹推送   | 状态变化能收到     |
| 3    | 客户通知       | 签收时客户收到消息 |
| 4    | 滞留和异常预警 | 测试滞留件被识别   |
| 5    | 时效统计       | 按快递和线路出报表 |

## 关键代码

示例代码（简化），没有在生产环境运行：

```python
@app.post("/express/callback")
def on_update(evt):
    ship = shipments.get(evt.tracking_no)
    ship.update(status=evt.status, last_event_at=evt.time)
    if evt.status == "签收":
        notify_customer(ship, "您的订单已签收")
    elif evt.status in ("退回", "派送失败"):
        alert_service(ship, f"异常：{evt.status}")
# 另有定时任务：超过 48 小时无更新的标为滞留
```

## 效果指标

| 指标             | 做之前     | 预期效果（估算） |
| ---------------- | ---------- | ---------------- |
| 「货到哪了」咨询 | 大量       | 明显减少         |
| 异常件发现       | 客户投诉后 | 48 小时内        |
| 选择快递         | 凭感觉     | 按时效和异常率   |

「货到哪了」的电话大幅减少，异常件在客户投诉前被处理。

## 常见坑

- **推送丢失**：回调失败。回调做幂等，定时轮询补漏。
- **单号录错**：手工录入。扫码录入，校验单号格式。
- **客户通知太频繁**：每个节点都通知。只在关键节点通知。

## AI 视角

**✨ AI 能增强**

- **AI 能做什么**：异常件生成给客户的说明和安抚话术
- **不该交给 AI**：状态判断确定
- **怎么落地**：AI 生成客服话术

## 面试怎么讲

30 秒讲法（方案思路；没有实际落地，面试时如实说明是设计过的方案）：

> 我会在发货时用快递单号订阅物流轨迹，状态变化通过 Webhook 推送：揽收、派送、签收时通知客户，超过 48 小时没更新、退回或派送失败的标为异常件，通知客服主动处理；再统计各快递公司和线路的时效、异常率，作为选择快递的依据。

常见追问：

**问：订阅推送和轮询的区别？**

答：推送是状态变化时对方通知你，实时且省资源；轮询是定时去查，简单但浪费且有延迟。推送 + 定时补漏最可靠。

**问：Webhook 为什么要幂等？**

答：同一个事件可能被推送多次，重复处理不能产生副作用。

**问：物流异常有哪些？**

答：滞留、退回、破损、地址错误、派送失败、丢件。

**被问到「能不能用 AI」时：** 物流状态是规则，AI 帮客服写异常件的沟通话术。
