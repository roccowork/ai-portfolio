## 问题

出故障时大家在群里讨论，真正操作的人在自己终端执行，别人看不到做了什么；简单的查询也要找有权限的人帮忙。

## 适用场景

- 适合：运维和开发协作多、故障处理需要多人配合的团队
- 不值得：只有一两个运维、操作很少的环境
- 前提：有统一的 IM（企业微信、飞书、Slack），操作已经有 API 或 GitOps

## 工具选型

| 方案                           | 特点                     | 适用            |
| ------------------------------ | ------------------------ | --------------- |
| 自建机器人 + 企业微信/飞书应用 | 完全可控                 | 国内常用        |
| Slack + 自定义 Bot / Hubot     | 生态成熟                 | 外企常用        |
| Argo CD Notifications          | 只做通知                 | 已用 Argo CD 时 |
| Errbot                         | Python 写的 ChatOps 框架 | 开源            |

自建机器人：命令固定、权限白名单，发布和回滚复用 GitOps，不让机器人直接持有集群写权限。

## 怎么做

- 机器人支持固定命令：`状态 <应用>`（副本、版本、最近告警）、`发布 <应用> <版本>`、`回滚 <应用>`
- 查询类命令所有人可用；发布、回滚只允许白名单成员，并且要求二次确认
- 发布和回滚不直接操作集群，而是改 GitOps 仓库的镜像标签，和正常发布走同一条路
- 所有命令和结果都留在群里，故障复盘时就是现成的时间线

## 实施步骤

| 步骤 | 做什么                                            | 怎么验证                     |
| ---- | ------------------------------------------------- | ---------------------------- |
| 1    | 定义命令清单：状态、发布、回滚、静默告警          | 文档列出每条命令和权限       |
| 2    | 创建企业微信应用，接收群消息回调                  | @机器人 能收到消息           |
| 3    | 实现查询类命令（调 Prometheus、Argo CD API）      | `状态 web` 返回副本数和版本  |
| 4    | 实现发布/回滚：改 GitOps 仓库，带白名单和二次确认 | 非白名单用户被拒绝           |
| 5    | 所有命令写审计日志                                | 能查到谁在什么时间执行了什么 |

## 关键代码

示例代码（简化），没有在生产环境运行：

```js
const [cmd, app, version] = text.trim().split(/\s+/);
if (cmd === '状态') return reply(await appStatus(app));
if (cmd === '回滚' && admins.has(userId)) {
  await gitops.revertLastDeploy(app); // git revert 最近一次 deploy 提交
  return reply(`已提交回滚 ${app}，Argo CD 同步中`);
}
```

## 效果指标

| 指标           | 做之前                     | 预期效果（估算）     |
| -------------- | -------------------------- | -------------------- |
| 操作透明度     | 个人终端里执行，别人看不到 | 全部在群里，全员可见 |
| 简单查询       | 找有权限的人帮忙           | 自己在群里查         |
| 故障复盘时间线 | 事后回忆                   | 群聊记录就是时间线   |

操作透明、协作方便；故障处理过程自动留痕。

## 常见坑

- **机器人被他人利用执行危险操作**：权限控制不严。按用户 ID 白名单；危险命令二次确认；机器人只改 Git 不直接改集群。
- **命令执行超时群里没反馈**：长任务同步执行。立即回复「已受理」，完成后再回复结果。
- **消息回调被伪造**：没校验签名。校验企业微信回调签名和来源。

## AI 视角

**🤖 AI 是核心**

- **AI 能做什么**：让人用自然语言下指令（「web 最近怎么了」），AI 翻译成查询并汇总回答
- **不该交给 AI**：发布、回滚等写操作仍走固定命令和白名单，AI 只能调用只读工具
- **怎么落地**：机器人接大模型的工具调用能力，只开放只读查询工具，写操作需要明确命令和二次确认

## 面试怎么讲

30 秒讲法（方案思路；没有实际落地，面试时如实说明是设计过的方案）：

> 我会做一个企业微信机器人：在群里发「状态 web」查副本、版本和最近告警；「发布」「回滚」只允许白名单成员并要二次确认，而且不是直接操作集群，而是改 GitOps 仓库，和正常发布走同一条路。所有命令和结果都留在群里，复盘时就是现成的时间线。

常见追问：

**问：ChatOps 的好处是什么？**

答：操作透明、协作方便、自动留痕；新人看群就能学会处理流程。

**问：机器人该不该有集群写权限？**

答：最好没有。发布回滚改 Git，由 Argo CD 执行；机器人只有只读查询权限，降低被滥用的风险。

**问：如何防止误操作？**

答：白名单、二次确认、危险命令只在指定群可用、全部记录审计。

**被问到「能不能用 AI」时：** ChatOps 加上 AI 后，大家可以用自然语言问「web 最近怎么样」，AI 去查指标和日志汇总，但写操作仍然是固定命令。
