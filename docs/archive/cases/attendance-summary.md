## 问题

HR 月底导出几千条打卡记录，在 Excel 里一条条核对请假、出差、调休，算加班时长，经常要花两三天。

## 适用场景

- 适合：员工几十人以上、考勤规则复杂（弹性、加班、调休）的公司
- 不值得：考勤系统自带报表已经够用的
- 前提：考勤和审批数据能通过 API 或导出获取

## 工具选型

| 方案                       | 特点           | 适用           |
| -------------------------- | -------------- | -------------- |
| Python + pandas + 考勤 API | 按公司规则计算 | ✅ 方案采用    |
| 钉钉 / 企业微信考勤报表    | 自带统计       | 规则简单时够用 |
| HR SaaS（北森、Moka）      | 考勤薪资一体   | 国内中大型     |
| Workday                    | 全球 HR        | 外企           |

自带报表处理不了的复杂规则（弹性时间、按审批抵扣），用 Python 按配置计算。

## 怎么做

- 通过企业微信或钉钉的考勤接口拉取全月打卡记录，同时拉取请假、出差、外出的审批记录
- pandas 按规则计算：9:00 后打卡算迟到（弹性 10 分钟）、工作日 19:00 后算加班、有审批的不算异常
- 生成部门汇总表和个人明细；异常记录先发给员工本人确认，减少月底争议
- 计算规则写成配置，制度调整时不用改代码

## 实施步骤

| 步骤 | 做什么                 | 怎么验证           |
| ---- | ---------------------- | ------------------ |
| 1    | 把考勤制度写成规则配置 | HR 确认规则        |
| 2    | 拉取打卡和审批记录     | 数据完整           |
| 3    | 计算迟到、缺卡、加班   | 和手工核对样本一致 |
| 4    | 异常先发给员工确认     | 员工收到异常清单   |
| 5    | 生成部门汇总表         | HR 拿到月度报表    |

## 关键代码

示例代码（简化），没有在生产环境运行：

```python
df["late"] = (df["first_punch"] > df["date"] + pd.Timedelta("9h10m")) & ~df["has_leave"]
df["overtime_h"] = ((df["last_punch"] - (df["date"] + pd.Timedelta("19h"))).dt.total_seconds() / 3600).clip(lower=0)
summary = df.groupby(["dept", "name"]).agg(迟到=("late", "sum"), 加班小时=("overtime_h", "sum"))
```

## 常见坑

- **跨天加班算错**：下班打卡在第二天凌晨。按班次而不是自然日归属。
- **审批和打卡时间对不上**：请半天假的边界。按审批的起止时间精确抵扣。
- **节假日调休**：周末上班日。引入法定节假日和调休表。

## 面试怎么讲

30 秒讲法（方案思路；没有实际落地，面试时如实说明是设计过的方案）：

> 我会通过企业微信或钉钉的考勤接口拉取全月打卡记录，同时拉取请假、出差、外出审批，用 pandas 按配置的规则计算迟到、缺卡和加班时长，有审批的不算异常。异常记录先发给员工本人确认，再生成部门汇总表给 HR。制度调整只改配置，不改代码。

常见追问：

**问：为什么规则要写成配置？**

答：考勤制度经常调整，写死在代码里每次都要改程序；配置化后 HR 也能看懂和确认。

**问：跨天加班怎么处理？**

答：按班次归属，凌晨的下班打卡算前一天的班次。

**问：数据隐私怎么保护？**

答：考勤数据只给 HR 和本人看，报表按权限分发，脚本运行环境做好访问控制。

**被问到「能不能用 AI」时：** 考勤关系到工资，必须用确定的规则计算。
