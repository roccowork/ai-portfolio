## 问题

HR 每次开在职证明都要打开旧文件改名字日期，容易留下上一个人的信息；批量签合同时一份份改更是费时。

## 适用场景

- 适合：HR、行政、销售经常出各种证明、合同、报价单的公司
- 不值得：一年只出几份文件的
- 前提：文件格式相对固定

## 工具选型

| 方案                                       | 特点                           | 适用        |
| ------------------------------------------ | ------------------------------ | ----------- |
| Python + docxtpl                           | 用 Word 模板，格式由 Word 控制 | ✅ 方案采用 |
| Word 邮件合并                              | 不用写代码                     | 简单批量    |
| 电子签平台模板（法大大、e 签宝、DocuSign） | 生成 + 签署                    | 国内 / 外企 |
| Carbone                                    | 开源报表模板引擎               | 多格式输出  |

docxtpl 让行政直接在 Word 里设计模板，开发只负责填数据，格式改动不用改代码。

## 怎么做

- 行政或 HR 用 Word 设计模板，需要替换的地方写成 `{{ name }}`、`{{ start_date }}`，格式完全由 Word 控制
- 数据从表格或 HR 系统读取，docxtpl 批量填充；支持条件段落（如试用期条款只在新员工合同里出现）
- 用 LibreOffice 无界面模式转成 PDF，按「类型-日期-序号」自动编号
- 员工可以在表单里申请证明，审批通过后自动生成并发送

## 实施步骤

| 步骤 | 做什么                       | 怎么验证             |

## 关键代码

示例代码（简化），没有在生产环境运行：

```python
from docxtpl import DocxTemplate

for emp in employees:
    doc = DocxTemplate("templates/在职证明.docx")
    doc.render({"name": emp.name, "dept": emp.dept, "start": emp.start_date, "no": next_no()})
    doc.save(out := f"out/在职证明-{emp.name}.docx")
subprocess.run(["soffice", "--headless", "--convert-to", "pdf", "--outdir", "out", *glob("out/*.docx")])
```

## 常见坑

- **占位符被 Word 拆分导致替换失败**：编辑时 Word 把文字拆成多段。在模板里一次性输入占位符，或用 docxtpl 推荐的写法。
- **转 PDF 后字体变了**：服务器没有对应中文字体。安装模板用到的字体。
- **证明被伪造**：PDF 可编辑。加编号和验证二维码，或电子签章。

## AI 视角

**✨ AI 能增强**

- **AI 能做什么**：根据要点起草非标准文书
- **不该交给 AI**：标准证明和合同用模板，确保格式和条款
- **怎么落地**：AI 起草非标文书，HR 审核

常见追问：

**问：为什么用 Word 模板而不是代码生成？**

答：格式由业务人员维护，改样式不用改代码；代码只负责数据。

**问：服务器上怎么把 Word 转 PDF？**

答：用 LibreOffice 的 headless 模式，注意安装中文字体。

**问：怎么防止证明被篡改？**

答：唯一编号可查验、二维码验证，或者使用电子签章。

**被问到「能不能用 AI」时：** 标准文书用模板，AI 帮起草非标准的文书。
