## 问题

官网被入侵后挂上博彩链接或篡改首页，往往是客户打电话来才发现，影响公司形象，政府和国企网站尤其敏感。

## 适用场景

- 适合：政府、国企、教育、金融网站，以及对品牌形象敏感的企业官网
- 不值得：内部系统、内容频繁变化的社区类网站
- 前提：能区分正常发布和异常变化（发布时更新基准）

## 工具选型

| 方案                   | 特点                       | 适用         |
| ---------------------- | -------------------------- | ------------ |
| 自写 Playwright 脚本   | 灵活，能看 JS 渲染后的内容 | ✅ 方案采用  |
| 网页防篡改系统（国产） | 驱动级保护 + 监控          | 国内政企常用 |
| 云 WAF 防篡改          | 缓存页面，被改时返回缓存   | 云上         |
| Uptime Kuma 关键字监控 | 检查页面包含特定文字       | 简单场景     |

自写脚本：能对比完整内容并截图留证；政府网站有合规要求时再配合专业的防篡改系统。

## 怎么做

- 选首页、关于我们、联系方式等关键页面，每 5 分钟用浏览器抓取（能看到 JS 渲染后的内容）
- 去掉时间、访问统计等动态部分后计算内容指纹，和基准版本比较
- 正常发布后自动更新基准（CI 部署成功时调用接口）；其他时间出现变化就告警，附上截图和文字差异
- 额外检查页面里有没有出现不在白名单里的外部链接域名

## 实施步骤

| 步骤 | 做什么                   | 怎么验证           |
| ---- | ------------------------ | ------------------ |
| 1    | 选关键页面并去掉动态内容 | 两次抓取的指纹一致 |
| 2    | 每 5 分钟抓取并比对      | 有变化时记录差异   |
| 3    | CI 部署成功时更新基准    | 正常发布不告警     |
| 4    | 外链白名单检查           | 出现陌生外链时告警 |
| 5    | 告警附截图和差异         | 群里能看到截图     |

## 常见坑

- **动态内容导致不停误报**：时间、访问量、随机推荐。比对前去掉这些部分。
- **只检查了首页**：攻击者改了二级页面。选多个关键页面；检查外链白名单。
- **CDN 缓存导致检测不到**：访问的是缓存。同时检查源站。

## AI 视角

**✨ AI 能增强**

- **AI 能做什么**：判断页面变化是正常更新还是可疑篡改（如出现博彩关键词）
- **不该交给 AI**：基准比对必须确定
- **怎么落地**：变化时把差异交给 AI 判断风险等级

## 面试怎么讲

30 秒讲法（方案思路；没有实际落地，面试时如实说明是设计过的方案）：

> 我会每 5 分钟用浏览器抓取官网的关键页面，去掉时间、统计等动态内容后计算指纹，和基准比对；CI 部署成功时自动更新基准，其他时间内容变化就告警，附上截图和文字差异。另外检查页面里有没有不在白名单里的外部链接，这能发现被挂黑链。

常见追问：

**问：网站被篡改常见的原因？**

答：CMS 或插件漏洞、弱口令后台、服务器被入侵、第三方脚本被污染。

**问：发现篡改后怎么处理？**

答：先恢复页面（从 Git 或备份重新部署），保留证据，排查入侵途径，修复漏洞，必要时上报。

**问：怎么从部署上减少篡改风险？**

答：静态站点、只读文件系统、最小权限、后台不对公网开放。本站的 nginx 容器就是只读根文件系统。

**被问到「能不能用 AI」时：** 比对是规则，AI 帮判断变化内容是否可疑，减少误报。
