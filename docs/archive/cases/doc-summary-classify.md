## 问题

客服每天上百封客户邮件、法务每周几十份合同，人工逐份阅读、分类、摘录关键信息，大部分时间花在「读」上。

## 适用场景

- 适合：每天进来大量非结构化文本（邮件、工单、合同、简历）的部门
- 不值得：量很少的
- 前提：有可用的大模型，数据合规（敏感内容的处理方式经过评估）

## 工具选型

| 方案                    | 特点           | 适用             |
| ----------------------- | -------------- | ---------------- |
| 大模型 API + 结构化输出 | 灵活           | 国内外都可用     |
| Dify 工作流             | 可视化编排     | 国内常用         |
| 传统 NLP 分类模型       | 需要标注数据   | 大规模、成本敏感 |
| RPA + AI 组件           | 和现有流程衔接 | 国内影刀等       |

大模型不需要标注数据就能分类和提取，结构化输出保证结果可被程序使用。

## 怎么做

- 大模型按固定的结构输出：一句话摘要、类别（投诉/咨询/退款）、紧急程度、关键字段（订单号、金额、到期日）
- 用结构化输出（JSON 模式）保证结果能被程序直接使用
- 按类别和紧急程度自动分发到对应的人或队列
- 每周抽查一部分结果，统计准确率；低置信度的转人工

## 实施步骤

| 步骤 | 做什么               | 怎么验证           |
| ---- | -------------------- | ------------------ |
| 1    | 确定输出结构和类别   | 业务方确认         |
| 2    | 准备几十份样本测试   | 准确率达到要求     |
| 3    | 接入数据源并自动分发 | 邮件进来自动分类   |
| 4    | 低置信度转人工       | 不确定的不自动处理 |
| 5    | 定期抽查并调整提示词 | 准确率稳定         |

## 关键代码

示例代码（简化），没有在生产环境运行：

```python
schema = {"summary": "str", "category": ["投诉", "咨询", "退款", "其他"],
          "urgency": ["高", "中", "低"], "order_id": "str|null"}
result = llm.extract(text=email.body, schema=schema,
                     instructions="只根据邮件内容填写，找不到的字段填 null")
route(result["category"], result["urgency"], email)
```

## 常见坑

- **分类不稳定**：提示词和类别定义模糊。给出类别定义和示例，用结构化输出。
- **敏感信息发给外部模型**：合同、个人信息外传。评估合规，必要时私有部署或先脱敏。
- **成本随量增长**：每份都用大模型。先用规则过滤简单的，只把需要的交给模型。

## AI 视角

**🤖 AI 是核心**

- **AI 能做什么**：摘要、分类、提取关键字段
- **不该交给 AI**：金额等关键字段需要校验，低置信度转人工
- **怎么落地**：见正文

## 面试怎么讲

30 秒讲法（方案思路；没有实际落地，面试时如实说明是设计过的方案）：

> 我会让大模型按固定结构处理进来的邮件和工单：一句话摘要、类别、紧急程度和订单号等关键字段，用结构化输出保证程序能直接使用，再按类别和紧急程度自动分发；低置信度的转人工，每周抽查准确率。人从逐份阅读变成看摘要和处理例外。

常见追问：

**问：为什么要用结构化输出？**

答：自由文本难以被程序解析；结构化输出（JSON Schema）保证字段和格式固定。

**问：大模型分类和传统分类模型怎么选？**

答：量小、类别常变、没有标注数据时用大模型；量大、类别稳定、成本敏感时训练专用模型。

**问：如何控制大模型的成本？**

答：规则先过滤、选合适的模型档位、缓存重复内容、批量处理。

**被问到「能不能用 AI」时：** 这个案例本身就是 AI，关键是结构化输出和低置信度转人工。
