## 问题

告警发到一个大群里，所有人都看到、所有人都以为别人会处理；半夜的严重告警没人接。

## 适用场景

- 适合：3 人以上的运维或 SRE 团队，需要 7×24 响应
- 不值得：只有一个运维，或者业务只在工作时间运行
- 前提：告警已经分级，严重告警确实需要立即处理

## 工具选型

| 方案                       | 特点                         | 适用            |
| -------------------------- | ---------------------------- | --------------- |
| Grafana OnCall             | 开源（已进入维护模式）/ 云版 | 和 Grafana 一体 |
| PagerDuty                  | 功能最全                     | 外企最常用      |
| Opsgenie                   | Atlassian 出品               | 外企常用        |
| 睿象云、PagerDuty 国内替代 | 电话、短信通道               | 国内常用        |

选专门的值班系统：排班、升级、电话通知、确认这些功能自己做成本高，而且电话通道需要运营商资质。

## 怎么做

- 排班表按周轮换（主值班 + 备份），节假日可以手动换班，换班记录可查
- Alertmanager 把告警发给值班系统（Grafana OnCall、PagerDuty 等），由它查当前值班人
- 严重告警打电话，一般告警发消息；5 分钟没人点「确认」就升级给二线，再没人就通知主管
- 每周生成值班报告：告警数量、确认时间、半夜被叫醒的次数，用来优化告警

## 实施步骤

| 步骤 | 做什么                              | 怎么验证               |
| ---- | ----------------------------------- | ---------------------- |
| 1    | 定排班规则：主值班 + 备份，每周轮换 | 排班表覆盖未来 4 周    |
| 2    | Alertmanager 接入值班系统           | 测试告警到达值班系统   |
| 3    | 配置升级策略：5 分钟未确认升级      | 不点确认时二线收到电话 |
| 4    | 严重告警走电话，一般告警走消息      | 分级通知生效           |
| 5    | 每周生成值班报告                    | 能看到告警数和响应时间 |

## 关键代码

示例代码（简化），没有在生产环境运行：

```yaml
# 升级策略示意
escalation:
  - { step: 1, notify: current_oncall, via: [phone, wecom] }
  - { step: 2, after: 5m, notify: secondary_oncall }
  - { step: 3, after: 15m, notify: team_lead }
```

## 效果指标

| 指标             | 做之前   | 预期效果（估算）     |
| ---------------- | -------- | -------------------- |
| 严重告警无人响应 | 经常发生 | 5 分钟未确认自动升级 |
| 确认时间         | 没有统计 | 每周报告可见         |
| 值班公平性       | 靠自觉   | 系统轮换、换班有记录 |

每条严重告警都有明确的负责人，响应时间可统计。

## 常见坑

- **值班人被大量无效告警轰炸**：告警没治理。只有严重告警走值班，其余发群；每周复盘无效告警。
- **换班后通知仍发给原来的人**：手动维护的通知名单没更新。通知名单只从排班系统读取。
- **电话被当成骚扰拦截**：号码没加白名单。值班人把通知号码加入通讯录。

## AI 视角

**✨ AI 能增强**

- **AI 能做什么**：值班人接到告警时，AI 先汇总相关指标、最近发布和类似历史事件
- **不该交给 AI**：谁值班、何时升级要按排班和规则，不能交给模型
- **怎么落地**：告警进入值班系统时附一份 AI 生成的上下文摘要

## 面试怎么讲

30 秒讲法（方案思路；没有实际落地，面试时如实说明是设计过的方案）：

> 我会用值班系统管理排班，主值班加备份按周轮换。Alertmanager 把严重告警发给值班系统，它查当前值班人并打电话，5 分钟没确认就升级给二线，再没人就通知主管；一般告警只发消息。每周统计告警数量、确认时间和半夜被叫醒的次数，用来持续治理告警。

常见追问：

**问：值班的告警应该满足什么标准？**

答：需要人立即处理、处理方法明确、对业务有影响。不满足的应该降级或删除。

**问：什么是 MTTA 和 MTTR？**

答：MTTA 是平均确认时间，MTTR 是平均恢复时间，是衡量值班和应急能力的核心指标。

**问：怎么减少半夜告警？**

答：告警治理（去重、抑制、提高阈值）、自动处置、修复反复出现的根因。

**被问到「能不能用 AI」时：** 值班最耗时的是收集上下文，AI 可以在告警到达时把相关信息先整理好。
