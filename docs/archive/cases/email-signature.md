## 问题

每个人的邮件签名五花八门：旧 Logo、离职前的职位、错误的电话。对外邮件看起来不专业，品牌更新时要挨个通知改。

## 适用场景

- 适合：对外邮件多、重视品牌形象的公司
- 不值得：员工很少对外发邮件的
- 前提：员工信息在 AD 或通讯录里是准确的

## 工具选型

| 方案                         | 特点                 | 适用         |
| ---------------------------- | -------------------- | ------------ |
| Exchange 传输规则            | 服务器端统一追加     | 微软邮箱     |
| PowerShell 生成 Outlook 签名 | 客户端签名，可编辑   | 本地 Outlook |
| Exclaimer / CodeTwo          | 商业签名管理         | 外企常用     |
| 企业邮箱后台统一签名         | 部分国产企业邮箱支持 | 国内         |

Microsoft 365 用传输规则在服务器端追加，所有客户端都生效；没有 Exchange 时脚本生成签名文件。

## 怎么做

- 签名模板由行政设计成 HTML，姓名、职位、部门、电话用占位符
- 每天从 AD 读取员工信息生成个人签名；Microsoft 365 用传输规则在服务器端统一追加，客户端不用设置
- 没有 Exchange 的，用脚本生成签名文件，通过组策略或登录脚本放到 Outlook 签名目录
- 员工信息在 AD 里更新后，第二天签名自动更新

## 实施步骤

| 步骤 | 做什么                           | 怎么验证                     |
| ---- | -------------------------------- | ---------------------------- |
| 1    | 行政设计 HTML 签名模板           | 在主流邮件客户端里显示正常   |
| 2    | 核对 AD 里的姓名、职位、电话     | 信息完整                     |
| 3    | 脚本按人生成签名                 | 每人一份 HTML                |

## 关键代码

示例代码（简化），没有在生产环境运行：

```powershell
$tpl = Get-Content signature.html -Raw -Encoding UTF8
Get-ADUser -Filter { Enabled -eq $true } -Properties title, department, telephoneNumber | ForEach-Object {
  $html = $tpl.Replace('{{name}}', $_.Name).Replace('{{title}}', $_.title).Replace('{{phone}}', $_.telephoneNumber)
  Set-Content "\\fs01\signatures$\$($_.SamAccountName).htm" $html -Encoding UTF8
}
```

## 常见坑

- **图片在收件人那里显示为附件**：图片以附件方式嵌入。用托管在网站上的图片链接。
- **回复邮件时签名重复追加**：传输规则没有排除回复。规则里检查正文是否已有签名。
- **AD 信息不全导致签名空字段**：部分员工没填电话。模板里对空字段整行隐藏。

## AI 视角

**⚙️ 规则就够**

- **AI 能做什么**：基本不需要
- **不该交给 AI**：签名内容来自 AD
- **怎么落地**：保持规则

## 面试怎么讲

30 秒讲法（方案思路；没有实际落地，面试时如实说明是设计过的方案）：

> 我会让行政设计一个 HTML 签名模板，姓名、职位、电话用占位符；脚本每天从 AD 读取员工信息生成个人签名。Microsoft 365 用传输规则在服务器端统一追加，客户端不用设置；没有 Exchange 的用登录脚本把签名文件放到 Outlook 的签名目录。员工信息在 AD 更新后第二天签名自动更新。

常见追问：

**问：服务器端签名和客户端签名的区别？**

答：服务器端在发送时追加，所有设备一致，用户不能改；客户端签名用户能看到和编辑，但每台设备要单独配置。

**问：签名里的图片怎么处理？**

答：用 HTTPS 托管的图片链接，避免作为附件；注意部分客户端默认不加载外部图片。

**问：为什么要从 AD 读取信息？**

答：AD 是唯一数据源，信息变化只改一处；也推动了 AD 数据的准确。

**被问到「能不能用 AI」时：** 签名统一用模板就够。
