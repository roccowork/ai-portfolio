## 问题

写故障复盘最花时间的是还原时间线：几点告警、几点有人发现、做了什么操作，要翻好几个系统的记录，经常记错。

## 适用场景

- 适合：有故障复盘制度的团队；复盘需要准确的时间线
- 不值得：故障很少、复盘很简单的环境
- 前提：告警、发布、操作记录都有可查询的来源（API 或日志）

## 工具选型

| 方案                       | 特点                   | 适用        |
| -------------------------- | ---------------------- | ----------- |
| 自写汇总脚本               | 按需对接各系统         | ✅ 方案采用 |
| incident.io / FireHydrant  | 故障管理平台，自动记录 | 外企常用    |
| PagerDuty 事件时间线       | 值班系统自带           | 外企        |
| 飞书/企业微信群 + 文档模板 | 最朴素                 | 国内常用    |

自写脚本：各公司数据源不同，用脚本把现有记录拼起来，比引入新平台成本低。

## 怎么做

- 输入故障开始和结束时间，脚本从各个系统拉取这段时间的记录：Prometheus 告警历史、Git 的部署提交、Argo CD 同步记录、堡垒机命令、值班群消息
- 按时间排序生成 Markdown 表格，自动标出「第一次告警」「第一次有人响应」「恢复时间」，算出发现时长和恢复时长
- 套用复盘模板（影响、根因、改进项），人只需补充分析
- ops-lab 的故障复盘模板就是这个格式

## 实施步骤

| 步骤 | 做什么                                                  | 怎么验证                 |
| ---- | ------------------------------------------------------- | ------------------------ |
| 1    | 列出数据源：告警历史、Git 部署、Argo CD、堡垒机、群消息 | 每个来源都能按时间段查询 |
| 2    | 写采集函数，统一成（时间、类型、内容）                  | 每个来源单独测试         |
| 3    | 排序生成 Markdown 时间线                                | 输出表格时间正确         |
| 4    | 自动计算发现时长、恢复时长                              | 和手工计算一致           |
| 5    | 套用复盘模板生成初稿                                    | 初稿可以直接补充分析     |

## 关键代码

示例代码（简化），没有在生产环境运行：

```python
events = []
events += [(a["startsAt"], "告警", a["labels"]["alertname"]) for a in alert_history(start, end)]
events += [(c.committed_datetime, "发布", c.summary) for c in repo.iter_commits(since=start, until=end)]
events += [(r["time"], "操作", f'{r["user"]}: {r["command"]}') for r in bastion_log(start, end)]
for t, kind, text in sorted(events):
    print(f"| {t:%H:%M:%S} | {kind} | {text} |")
```

## 常见坑

- **各系统时区不一致**：有的是 UTC、有的是本地时间。采集时统一转换成同一时区。
- **群消息太多淹没关键信息**：整段聊天都导入。只导入带关键词或特定人的消息，或者手动标记。
- **复盘变成追责**：时间线里有操作人。约定复盘不追究个人，关注流程和系统。

## AI 视角

**🤖 AI 是核心**

- **AI 能做什么**：把告警、发布、操作、群聊记录写成通顺的复盘初稿，提炼可能的根因和改进项
- **不该交给 AI**：根因结论和责任判断必须由人确认
- **怎么落地**：时间线脚本输出后交给模型生成复盘初稿，人修改确认

## 面试怎么讲

30 秒讲法（方案思路；没有实际落地，面试时如实说明是设计过的方案）：

> 我会写一个脚本，输入故障的开始和结束时间，从告警历史、Git 部署提交、Argo CD 同步记录、堡垒机命令和值班群消息里拉取这段时间的记录，统一时区后按时间排好，自动标出第一次告警、第一次响应和恢复时间，生成复盘文档初稿，人只需要补充根因和改进项。

常见追问：

**问：一份好的复盘包含什么？**

答：影响范围、时间线、根因、处理过程、做得好的和不好的、改进项（有负责人和期限）。

**问：为什么复盘不追责？**

答：追责会让人隐瞒信息，找不到真正的根因；复盘的目标是改进系统和流程。

**问：怎么衡量故障处理能力？**

答：发现时长（MTTD）、确认时长（MTTA）、恢复时长（MTTR），以及同类故障是否复发。

**被问到「能不能用 AI」时：** 复盘初稿是 AI 最擅长的：把几百条记录整理成时间线和叙述，人负责判断根因。
