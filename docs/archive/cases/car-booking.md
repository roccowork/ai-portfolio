## 问题

用车靠打电话找行政，车辆冲突经常发生；油费、过路费不知道该算哪个部门；车辆保养和年检容易忘。

## 适用场景

- 适合：有公务车辆和专职司机的公司
- 不值得：没有公车、员工打车报销的
- 前提：车辆和司机信息集中管理

## 工具选型

| 方案                            | 特点         | 适用        |
| ------------------------------- | ------------ | ----------- |
| 钉钉 / 飞书审批 + 多维表格      | 零代码       | 国内常用    |
| 车辆管理 SaaS（如企业用车平台） | 含定位和费用 | 国内        |
| 自写调度脚本                    | 按规则排车   | ✅ 方案采用 |
| 电话 + 表格                     | 现状         | 容易冲突    |

审批用 IM 自带的，排车和统计用多维表格 + 脚本；车辆多时再上专业平台。

## 怎么做

- 员工提交用车申请（时间、地点、人数），主管审批
- 系统按时间段检查车辆和司机空闲，自动分配并通知双方
- 用车结束司机登记里程和费用，按部门归集
- 车辆保险、年检、保养按日期和里程自动提醒

## 实施步骤

| 步骤 | 做什么                       | 怎么验证       |
| ---- | ---------------------------- | -------------- |
| 1    | 录入车辆、司机、保险年检日期 | 数据完整       |
| 2    | 配置用车审批                 | 主管能审批     |
| 3    | 实现自动排车                 | 冲突申请被拒绝 |
| 4    | 用车后登记里程和费用         | 按部门归集     |
| 5    | 保养年检提醒                 | 提前 30 天提醒 |

## 关键代码

示例代码（简化），没有在生产环境运行：

```python
def assign(req):
    free = [c for c in cars if c.seats >= req.people and not overlaps(c.bookings, req.start, req.end)]
    if not free:
        return notify(req.applicant, "该时间段没有可用车辆，请调整时间")
    car = min(free, key=lambda c: c.mileage_this_month)       # 均衡使用
    book(car, req)
    notify([req.applicant, car.driver], f"{req.start:%m-%d %H:%M} {car.plate} {req.destination}")
```

## 常见坑

- **临时变更没有同步**：电话改了时间。变更必须在系统里改。
- **司机不登记里程**：流程不便。手机上一键登记，或接车载定位。
- **紧急用车被流程卡住**：审批太慢。设紧急通道，事后补审批。

## 面试怎么讲

30 秒讲法（方案思路；没有实际落地，面试时如实说明是设计过的方案）：

> 我会让员工在线提交用车申请，主管审批后系统按时间段检查车辆和司机空闲，按人数自动分配车辆并通知申请人和司机；用车结束司机登记里程和费用，按部门归集；车辆保险、年检和保养按日期和里程提前提醒。

常见追问：

**问：排车算法怎么考虑公平？**

答：在满足座位和时间的车辆里，选本月里程最少的，均衡车辆使用。

**问：紧急用车怎么办？**

答：设紧急通道直接排车，事后补审批。

**问：车辆费用怎么管？**

答：里程、油费、过路费、维修按车和部门记录，月底汇总。
