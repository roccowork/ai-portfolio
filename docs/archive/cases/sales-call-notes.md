## 问题

销售每天打十几个电话、开几个会，拜访记录要么不写，要么只写一句「沟通顺利」。主管看不到真实情况，销售离职后客户信息全部丢失；客户说过的关键需求和顾虑，下次跟进时已经忘了。

## 适用场景

- 适合：销售团队 5 人以上、以电话和线上会议为主的 B2B 公司
- 不值得：交易简单、一次成交、不需要长期跟进的业务
- 前提：有 CRM；客户同意录音（通话前告知）；遵守当地的录音和个人信息法规

## 工具选型

| 方案                                   | 特点                           | 适用        |
| -------------------------------------- | ------------------------------ | ----------- |
| Gong、Salesforce Einstein Conversation | 成熟的会话智能平台             | 外企常用    |
| 飞书妙记、腾讯会议纪要 + CRM 集成      | 国内会议工具自带转写           | 国内常用    |
| 自写：转写 + 大模型 + CRM API          | 可按自己的销售方法定制提取字段 | ✅ 方案采用 |
| 销售手写                               | 现状                           | 不完整      |

国内用会议工具自带的转写，再自写一层：按公司的销售方法（如 BANT）提取字段并写入 CRM。

## 怎么做

- 会议工具或云呼叫中心自动录音并转写，通话开始时告知客户
- 转写文本交给大模型，按固定字段提取：客户需求、痛点、预算、决策人和流程、时间线、顾虑和异议、竞品、约定的下一步
- 提取结果推送给销售确认（企业微信卡片），销售可以修改后点「确认」
- 确认后自动更新 CRM 的商机字段，按「下一步」创建跟进任务和提醒
- 主管每周收到团队摘要：哪些商机有进展、哪些客户提到了竞品、常见异议是什么

## 实施步骤

| 步骤 | 做什么                                 | 怎么验证           |
| ---- | -------------------------------------- | ------------------ |
| 1    | 确认录音告知话术和法律要求             | 法务确认           |
| 2    | 定义提取字段（按公司的销售方法）       | 销售主管认可       |
| 3    | 用 20 段历史录音试提取，销售评估准确性 | 大部分字段无需修改 |
| 4    | 对接 CRM：确认后更新商机、建任务       | CRM 里能看到       |
| 5    | 每周团队摘要发给主管                   | 主管使用           |

## 关键代码

示例代码（简化），没有在生产环境运行：

```python
FIELDS = {"needs": "客户需求", "pain": "痛点", "budget": "预算", "decision_maker": "决策人",
          "timeline": "时间线", "objections": "顾虑和异议", "competitors": "提到的竞品",
          "next_steps": "约定的下一步（含日期和负责人）"}

notes = llm.complete(EXTRACT_PROMPT.format(fields=FIELDS, transcript=transcript),
                     response_format="json")  # 没提到的字段留空，不推测
card = wecom.confirm_card(rep, notes)  # 销售确认或修改
if card.confirmed:
    crm.update_opportunity(opp_id, card.notes)
    for step in card.notes["next_steps"]:
        crm.create_task(opp_id, step["action"], due=step["date"], owner=rep)
```

## 效果指标

| 指标           | 做之前                 | 预期效果（估算）       |
| -------------- | ---------------------- | ---------------------- |
| 拜访记录完整度 | 大部分没写或只有一句话 | 每次通话都有结构化记录 |
| 销售写记录时间 | 每次 10～15 分钟       | 1 分钟确认             |
| 跟进遗漏       | 常见                   | 自动建跟进任务         |

销售把时间花在客户身上，主管看到真实的商机进展，客户信息不再随销售离职而丢失。

## 常见坑

- **未告知客户就录音**：法律风险。通话前告知，遵守当地法规；客户拒绝就不录。
- **AI 推测客户没说的内容**：提取出不存在的预算。要求没提到就留空，销售确认后才写入。
- **销售抵触被「监控」**：觉得每句话都被检查。强调目的是帮销售省时间，主管只看汇总，不逐条检查。
- **转写质量差**：方言、专业术语识别错误。添加行业热词，关键信息以销售确认为准。

## AI 视角

**🤖 AI 是核心**

- **AI 能做什么**：语音转文字，从半小时的对话里提炼出结构化的销售信息，识别异议和竞品，汇总团队洞察
- **不该交给 AI**：写入 CRM 前的确认；对客户的承诺和报价
- **怎么落地**：AI 起草，销售确认后才写入 CRM

常见追问：

**问：什么是 BANT？**

答：Budget（预算）、Authority（决策权）、Need（需求）、Timeline（时间线），常用的销售线索评估方法。

**问：为什么要销售确认，不直接写入？**

答：AI 可能理解错或推测，CRM 数据要准确；确认只需要一分钟，同时让销售对记录负责。

**问：录音有什么合规要求？**

答：要告知对方并取得同意，录音和转写按个人信息保护要求存储、设权限、定期删除，具体以当地法律为准。

**被问到「能不能用 AI」时：** 这个案例本身就是 AI；关键是告知客户、AI 起草、销售确认。
