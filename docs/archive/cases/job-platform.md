## 问题

几十上百台服务器，批量操作靠 for 循环 + SSH：谁执行了什么、结果是否成功都没有记录，脚本散落在个人电脑上，权限也控制不了。

## 适用场景

- 适合：几十台以上服务器、多人做批量操作的团队
- 不值得：几台机器、一个人维护的环境
- 前提：常用操作已经写成脚本或 playbook

## 工具选型

| 方案                        | 特点                       | 适用         |
| --------------------------- | -------------------------- | ------------ |
| AWX（Ansible Tower 开源版） | Ansible 原生，有权限和审计 | 国内外都常用 |
| Semaphore                   | 更轻量的 Ansible 界面      | 小团队       |
| 蓝鲸作业平台                | 国产，功能全               | 国内常用     |
| Rundeck                     | 支持各种脚本               | 外企常用     |

选 AWX 或 Semaphore：复用已有的 Ansible playbook，界面、权限、审计都有，不用自己开发。

## 怎么做

- 常用操作写成 Ansible playbook 放进 Git：清理日志、重启服务、查看端口、分发配置文件
- 用 AWX（或更轻的 Semaphore）把 playbook 做成作业模板：选主机组、填参数、点执行，实时看每台机器的输出
- 按角色授权：开发只能对测试环境执行只读作业，生产变更作业需要审批
- 每次执行谁、什么时间、对哪些机器、结果如何都保留记录；国内常见的蓝鲸作业平台是同一类产品

## 实施步骤

| 步骤 | 做什么                                 | 怎么验证                              |
| ---- | -------------------------------------- | ------------------------------------- |
| 1    | playbook 放进 Git 仓库                 | 仓库里有清理日志、重启服务等 playbook |
| 2    | 部署 AWX/Semaphore，关联仓库和主机清单 | 能看到 playbook 列表                  |
| 3    | 创建作业模板：参数、目标组             | 在界面上执行成功                      |
| 4    | 配置角色权限                           | 开发只能对测试环境执行只读作业        |
| 5    | 开启执行记录和通知                     | 每次执行有记录，失败通知              |

## 关键代码

示例代码（简化），没有在生产环境运行：

```yaml
# 作业模板引用的 playbook：重启指定服务并确认已启动
- hosts: '{{ target }}'
  become: true
  tasks:
    - ansible.builtin.service: { name: '{{ svc }}', state: restarted }
    - ansible.builtin.command: systemctl is-active {{ svc }}
      changed_when: false
```

## 效果指标

| 指标     | 做之前                   | 预期效果（估算）   |
| -------- | ------------------------ | ------------------ |
| 批量操作 | for 循环 + SSH，没有记录 | 界面执行，全程记录 |
| 权限     | 共用 root                | 按人按环境授权     |
| 新人上手 | 要学命令                 | 选模板、填参数     |

批量操作有界面、有权限、有记录，新人也能安全地执行标准操作。实验 05、06 写过的 playbook 都可以直接做成作业模板。

## 常见坑

- **一次对所有机器执行，出错影响全部**：没有分批。设置 serial 分批执行，先跑一台。
- **作业模板参数被乱填**：参数没校验。用下拉选项限制取值。
- **平台的 SSH 密钥泄露风险**：平台持有所有机器的密钥。平台本身做好加固和审计，密钥只授权必要的用户。

## AI 视角

**✨ AI 能增强**

- **AI 能做什么**：用自然语言选择作业模板和填参数；根据需求生成新的 playbook 初稿
- **不该交给 AI**：高风险作业的执行要人确认，参数要校验
- **怎么落地**：平台里加 AI 助手推荐模板，生成的新 playbook 走评审

## 面试怎么讲

30 秒讲法（方案思路；没有实际落地，面试时如实说明是设计过的方案）：

> 我会把常用的批量操作写成 Ansible playbook 放进 Git，用 AWX 或 Semaphore 做成作业模板：选主机组、填参数、点执行，实时看每台机器的输出。按角色授权，开发只能对测试环境执行只读作业；每次执行都有记录。高风险操作用 serial 分批，先跑一台确认没问题再继续。

常见追问：

**问：Ansible 的 serial 有什么用？**

答：控制每批执行的主机数，滚动执行，避免一次操作所有机器出错影响全部。

**问：作业平台和 CI/CD 的区别？**

答：CI/CD 面向代码发布；作业平台面向日常运维操作（巡检、清理、重启、分发文件）。

**问：怎么保证批量操作的安全？**

答：权限控制、审批、分批执行、预检查、--check 演练、全程审计。

**被问到「能不能用 AI」时：** 作业平台可以加 AI 助手推荐模板，但新生成的 playbook 必须评审后才能上架。
