## 问题

质检靠人眼：一个质检员一天看几千个零件，几个小时后注意力下降，细小的划痕、缺件漏检；不同质检员的标准也不一样。漏检的不良品流到客户那里，造成退货和索赔；招质检员越来越难。

## 适用场景

- 适合：外观缺陷是主要质量问题、产量大、人工质检成本高的产线（电子、汽配、包装、纺织、食品）
- 不值得：产量很小、缺陷种类无法定义、或者缺陷只能靠手感和功能测试发现的
- 前提：缺陷能通过拍照看出来；能收集到足够的缺陷样本图片；产线有剔除机构或能停线

## 工具选型

| 方案                                        | 特点                           | 适用            |
| ------------------------------------------- | ------------------------------ | --------------- |
| 传统机器视觉（Halcon、海康 VisionMaster）   | 规则算法，稳定，适合尺寸和定位 | 规则明确的检测  |
| 深度学习目标检测（YOLO 系列）               | 识别多种已知缺陷               | ✅ 方案采用     |
| 无监督异常检测（PatchCore 等）              | 只需要良品图片，发现未知缺陷   | ✅ 缺陷样本少时 |
| 商业 AI 质检平台（海康、百度、Cognex ViDi） | 软硬件一体，有现场实施         | 国内外都有      |

尺寸、定位用传统视觉，外观缺陷用深度学习；缺陷样本少时先用只需要良品的异常检测，积累样本后再训练检测模型。

## 怎么做

- **成像**：在关键工位装工业相机和合适的光源（光源决定了缺陷能不能拍清楚），由传感器触发拍照，保证每个产品的位置和光照一致
- **数据**：收集良品和各类缺陷图片，质检专家标注缺陷类型和位置；缺陷样本少时先用异常检测
- **训练**：训练检测模型，用独立的测试集评估漏检率和误检率；漏检率优先（宁可多剔除复核，不能放过不良品）
- **部署**：模型部署在产线旁的边缘计算盒，单张图片推理在几十毫秒内完成，不依赖网络
- **执行**：判定为缺陷时通过 PLC 触发剔除，缺陷图片和类型写入 MES，关联批次和工位
- **持续改进**：剔除的产品由质检员复核，误判的图片回流重新标注训练；缺陷统计接入 SPC，发现工艺漂移

## 实施步骤

| 步骤 | 做什么                                 | 怎么验证                   |
| ---- | -------------------------------------- | -------------------------- |
| 1    | 确定检测工位和缺陷类型，评估成像方案   | 缺陷在图片里清晰可见       |
| 2    | 采集并标注图片（良品 + 各类缺陷）      | 每类缺陷有足够样本         |
| 3    | 训练模型，用测试集评估                 | 漏检率、误检率达到验收标准 |
| 4    | 部署到边缘设备，和人工并行运行 2～4 周 | 和人工结果对比             |
| 5    | 对接 PLC 剔除和 MES                    | 缺陷品被剔除，数据可追溯   |
| 6    | 误判回流，定期重新训练                 | 误检率持续下降             |

## 关键代码

示例代码（简化），没有在生产环境运行：

```python
from ultralytics import YOLO

model = YOLO("defect-v3.pt")  # 划痕、缺件、错印、脏污 4 类
THRESHOLD = {"scratch": 0.35, "missing": 0.25, "misprint": 0.4, "stain": 0.5}  # 漏检优先，阈值偏低

for frame in camera.on_trigger():
    result = model(frame.image, imgsz=1280)[0]
    defects = [b for b in result.boxes if b.conf >= THRESHOLD[result.names[int(b.cls)]]]
    if defects:
        plc.write("REJECT", 1)  # 剔除
        mes.record(frame.serial, station="ST-05", defects=defects, image=frame.image)
    else:
        plc.write("PASS", 1)
```

## 效果指标

| 指标       | 做之前           | 预期效果（估算）     |
| ---------- | ---------------- | -------------------- |
| 漏检率     | 受疲劳和经验影响 | 稳定，不随时间下降   |
| 检测标准   | 因人而异         | 统一                 |
| 质检人力   | 每个工位专人盯   | 复核剔除品、分析数据 |
| 缺陷可追溯 | 记录不全         | 每个缺陷有图片和批次 |

具体效果取决于缺陷类型和成像条件，以试运行数据为准。质检员从重复的盯看转为复核和工艺分析。

## 常见坑

- **只关注模型，不重视光源和成像**：缺陷拍不清楚，模型再好也没用。先做成像验证，光源方案往往决定成败。
- **缺陷样本太少**：某些缺陷一个月才出现几次。先用只需要良品的异常检测，同时积累缺陷样本。
- **实验室准确率高，上线后下降**：产线的光照、灰尘、产品批次变化。上线前在真实产线并行运行，定期回流重新训练。
- **误检太多被关掉**：剔除太多良品，产线抱怨。阈值按缺陷类型分别调，误检的由人复核放行，持续改进。
- **只剔除不分析**：缺陷数据没有用来改进工艺。缺陷统计接入 SPC，按工位、班次、原料批次分析。

## AI 视角

**🤖 AI 是核心**

- **AI 能做什么**：识别规则算法难以描述的外观缺陷（形状不规则的划痕、脏污、纹理异常），速度和一致性超过人眼
- **不该交给 AI**：验收标准的制定、批次放行的最终决定、新缺陷类型的判定
- **怎么落地**：先做成像验证，再小规模试点和人工并行，误判回流持续训练，缺陷数据用于改进工艺

常见追问：

**问：漏检和误检哪个更重要？**

答：一般漏检更重要，不良品流到客户代价更大；所以阈值偏低，多剔除的由人复核。具体按行业和缺陷的严重程度平衡。

**问：为什么部署在边缘而不是云端？**

答：产线要求毫秒级响应，不能依赖网络；图片量大，上传成本高；数据不出工厂。

**问：传统机器视觉和深度学习怎么选？**

答：尺寸测量、定位、读码这类规则明确的用传统视觉，稳定可解释；形态多变的外观缺陷用深度学习。两者常常一起用。

**被问到「能不能用 AI」时：** 这个案例本身就是 AI；但成败往往取决于成像和数据，而不是模型。
