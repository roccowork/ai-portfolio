## 问题

「帮我开个端口」靠口头或聊天，网管手动在防火墙上加；规则越积越多，没人知道哪些还在用，临时开的永远不会关。

## 适用场景

- 适合：网络和安全策略多、变更频繁、需要审计的公司
- 不值得：规则很少、几乎不变的环境
- 前提：防火墙或安全组有 API

## 工具选型

| 方案                 | 特点               | 适用         |
| -------------------- | ------------------ | ------------ |
| 自写表单 + 云 API    | 按公司流程         | ✅ 方案采用  |
| Tufin / AlgoSec      | 防火墙策略管理平台 | 外企大型企业 |
| Terraform 管理安全组 | 规则即代码         | 云上         |
| ITSM 工单 + 人工执行 | 流程有了但仍手工   | 常见现状     |

自写：申请字段固定、风险规则明确，审批通过后调 API 下发，到期自动回收。

## 怎么做

- 申请表固定字段：源地址、目标地址、端口、用途、使用期限（默认 30 天）
- 提交时自动检查：禁止对 0.0.0.0/0 开放 22、3306、6379 等高危端口；和已有规则重复的直接提示
- 审批通过后调用云安全组 API（或防火墙厂商 API）下发，规则描述里写上申请单号和到期日
- 每天检查到期规则，提前 3 天提醒申请人续期，不续期自动删除

## 实施步骤

| 步骤 | 做什么                         | 怎么验证                   |
| ---- | ------------------------------ | -------------------------- |
| 1    | 定义申请字段和默认期限 30 天   | 表单只能填合法的 IP 和端口 |
| 2    | 风险检查规则                   | 对公网开放 3306 被拒绝     |
| 3    | 审批流对接                     | 高风险需要安全负责人审批   |
| 4    | 下发规则，描述里写单号和到期日 | 安全组里能看到规则和单号   |
| 5    | 每天检查到期规则并回收         | 到期未续的规则被删除       |

## 关键代码

示例代码（简化），没有在生产环境运行：

```python
RISKY = {22, 3389, 3306, 6379, 9200}
if req.source == "0.0.0.0/0" and req.port in RISKY:
    reject(req, "高危端口不允许对公网开放")
rule_id = sg.authorize(port=req.port, source=req.source,
                       description=f"{req.ticket} 到期 {req.expire:%Y-%m-%d}")
```

## 效果指标

| 指标       | 做之前                       | 预期效果（估算）   |
| ---------- | ---------------------------- | ------------------ |
| 开端口耗时 | 找网管，几小时到几天（估算） | 审批后几分钟       |
| 规则来源   | 不清楚                       | 每条有单号和申请人 |
| 临时规则   | 永久遗留                     | 到期自动回收       |

每条规则都有申请人、用途和期限，规则数量不再只增不减。

## 常见坑

- **规则冲突或重复**：多人申请相同规则。提交时检查已有规则，重复的直接提示。
- **自动删除了还在用的规则**：申请人没续期。到期前多次提醒，删除前先通知。
- **API 凭据权限过大**：能修改所有安全组。只授权管理特定安全组。

## AI 视角

**✨ AI 能增强**

- **AI 能做什么**：把自然语言申请转成规则，并检查和现有规则的冲突
- **不该交给 AI**：高危端口拦截规则必须确定
- **怎么落地**：AI 辅助填表和冲突检查，审批照常

## 面试怎么讲

30 秒讲法（方案思路；没有实际落地，面试时如实说明是设计过的方案）：

> 我会把开端口变成申请表：源地址、目标、端口、用途、期限，默认 30 天。提交时自动检查，禁止对 0.0.0.0/0 开放 22、3306、6379 等高危端口；审批通过后调云安全组或防火墙 API 下发，规则描述里写单号和到期日；每天检查到期规则，提前提醒续期，不续期自动删除。

常见追问：

**问：防火墙规则为什么会越来越多？**

答：只加不删：临时开的忘了关，没人知道哪些还在用。所以每条规则都要有负责人和期限。

**问：安全组的有状态是什么意思？**

答：允许了入方向的请求，返回的流量自动放行，不需要再配出方向规则。

**问：最小权限在网络上怎么体现？**

答：只开放需要的端口，源地址尽量精确到 IP 或网段，不用 0.0.0.0/0。

**被问到「能不能用 AI」时：** AI 帮员工把「我要访问某系统」转成具体规则，审批照常。
