## 问题

安全设备每天产生几百条告警，人工逐条查询 IP 信誉、找资产负责人、登录防火墙封禁，处理不过来，真正的攻击被淹没。

## 适用场景

- 适合：有安全设备和安全运营人员、告警量大的公司
- 不值得：没有 SIEM 和安全告警来源的环境
- 前提：防火墙、WAF、身份系统有 API

## 工具选型

| 方案                       | 特点                   | 适用     |
| -------------------------- | ---------------------- | -------- |
| Shuffle                    | 开源 SOAR              | 开源     |
| Wazuh 主动响应             | 开源 SIEM 自带简单响应 | 开源     |
| Splunk SOAR / Cortex XSOAR | 商业 SOAR              | 外企常用 |
| 奇安信、深信服 SOAR        | 国产                   | 国内常用 |

先用开源 Shuffle + Wazuh 搭起流程；告警量和合规要求上来后再考虑商业平台。

## 怎么做

- 告警进入 SOAR 平台后先自动富化：查询威胁情报（IP 信誉）、资产信息（这台机器是谁的、重要程度）
- 按剧本处置：高置信的恶意 IP 自动在 WAF/防火墙封禁 24 小时；疑似账号被盗自动强制下线并要求重置密码
- 高风险动作（隔离生产主机）需要安全人员一键确认
- 每一步自动记录到工单，形成完整的处置记录

## 关键代码

示例代码（简化），没有在生产环境运行：

```yaml
# 剧本示意：Web 攻击告警
trigger: waf_alert
steps:
  - enrich: { threat_intel: '{{ alert.src_ip }}', asset: '{{ alert.dst_host }}' }
  - if: '{{ intel.score >= 80 }}'
    then: [{ firewall_block: { ip: '{{ alert.src_ip }}', ttl: 24h } }]
  - create_ticket: { severity: '{{ alert.severity }}', owner: '{{ asset.owner }}' }
```

## 常见坑

- **误封正常用户或合作方 IP**：情报误报。白名单、封禁设过期时间、置信度阈值。
- **自动隔离影响业务**：处置动作过激。高风险动作必须人工确认。
- **剧本过时**：攻击手法变化。定期复盘剧本效果。

## AI 视角

**🤖 AI 是核心**

- **AI 能做什么**：读告警、日志、情报，判断是否真实攻击并给出处置建议
- **不该交给 AI**：高风险处置（隔离主机）必须人确认
- **怎么落地**：剧本里加 AI 研判步骤，低风险自动、高风险人工确认

## 面试怎么讲

30 秒讲法（方案思路；没有实际落地，面试时如实说明是设计过的方案）：

> 我会把高频安全告警的处置写成剧本：告警进来先自动查询威胁情报和资产负责人，高置信的恶意 IP 自动在 WAF 封禁 24 小时，疑似账号被盗自动强制下线；隔离生产主机这类高风险动作需要安全人员一键确认；每一步都记录到工单。安全人员只做判断，不做重复操作。

常见追问：

**问：SIEM 和 SOAR 的区别？**

答：SIEM 负责收集、关联、告警；SOAR 负责编排和自动化处置。

**问：自动封禁怎么避免误伤？**

答：白名单、只处理高置信告警、封禁设过期时间、可以一键解封。

**问：什么是威胁情报？**

答：关于恶意 IP、域名、文件哈希的信誉数据，用来判断告警是否真实。

**被问到「能不能用 AI」时：** 安全告警研判是 AI 的强项，但高风险处置必须人确认。
