## 问题

- 财务月底拿着银行流水和日记账逐笔打勾，找未达账项，手工编余额调节表
- 每天导出订单、做透视表、截图发群
- HR 通知 IT 手工开账号，员工离职后账号常常忘了停用

## 适用场景

- 适合：财务、HR、销售每天、每月有大量重复 Excel 工作的中小企业
- 不值得：已经有 ERP、HR 系统自带这些功能的公司
- 前提：数据能从系统导出成 Excel，或者有接口

## 工具选型

| 方案                       | 特点                       | 适用                  |
| -------------------------- | -------------------------- | --------------------- |
| Python + pandas + openpyxl | 灵活、免费，Excel 原生图表 | ✅ 本站实现           |
| RPA（影刀、UiPath）        | 录制操作，非技术人员也能做 | 国内影刀、外企 UiPath |
| Excel Power Query / VBA    | 不用装别的软件             | 财务人员常用          |
| 低代码（n8n、宜搭）        | 拖拽流程                   | 适合审批、通知类      |

选 Python：对账、报表、账号同步都需要复杂逻辑和测试，代码比录制的 RPA 稳定，也方便在 CI 里测试。

## 怎么做

- **银行对账**：金额相同、方向相同才配对；日期允许相差几天，先配同一天的再逐步放宽；同一天多笔同金额时用摘要相似度挑最像的。配不上的就是未达账项，自动编余额调节表，对不平时退出码为 2，定时任务据此提醒财务
- **销售日报 / 周报**：生成带原生 Excel 图表的报表，摘要推到企业微信 / 钉钉群（支持加签），邮件附 Excel
- **入离职账号**：以 HR 花名册为准比对 LDAP / 企业微信，像 Terraform 一样先 plan 再 apply；停用不删除，数据可恢复；每一步追加写审计记录
- 测试不访问任何外部服务：群机器人用本地假服务器，LDAP 用 ldap3 自带的模拟服务器；CI 在 Windows 和 Linux 上都跑

def match(bank, book, max_days=3):
    """先配日期相同的，再逐步放宽到 max_days 天；一笔只配一次"""
    for gap in range(max_days + 1):
        for i, b in bank.iterrows():
            if i in used_bank:
                continue
            candidates = [j for j in by_amount.get(round(b["金额"], 2), [])
                          if j not in used_book and abs((book.at[j, "日期"] - b["日期"]).days) == gap]
            if candidates:
                j = max(candidates, key=lambda j: _similarity(b, book.loc[j]))
                used_bank.add(i); used_book.add(j); pairs.append((i, j))
    return pairs

## 常见坑

- **同一天多笔同金额的流水配错**：只按金额和日期配对时会随便配一笔。再用摘要相似度挑最像的一笔。
- **Excel 日期列读出来是数字**：单元格是数值格式（Excel 序列号）。读取时统一转换日期类型，并在测试里覆盖。

## AI 视角

**✨ AI 能增强**

- **AI 能做什么**：对账差异给出可能原因（手续费、跨期）
- **不该交给 AI**：配对和金额计算必须确定

## 面试怎么讲

30 秒讲法：

> 我写了一个办公自动化工具包，三个功能：银行对账按金额和方向配对、日期逐步放宽，配不上的就是未达账项，自动生成余额调节表；销售日报生成带原生图表的 Excel 并推到企业微信或钉钉群；入离职账号以 HR 花名册为准比对 LDAP，像 Terraform 一样先 plan 再 apply，停用不删除。测试不访问任何外部服务，CI 在 Windows 和 Linux 上都跑。目前用的是演示数据。

常见追问：

**问：什么是未达账项？**

答：一方已入账、另一方还没入账的款项，比如银行已扣的手续费企业还没记账。余额调节表把它们加减后两边应该相等。

**问：账号同步为什么先 plan 再 apply？**

答：账号操作影响大，先列出将要新建、停用的账号让人确认，避免花名册填错导致批量误操作。

**问：Python 和 RPA 怎么选？**

答：有接口或能导出数据、逻辑复杂的用 Python；只能在界面上操作、逻辑简单的用 RPA。

**被问到「能不能用 AI」时：** 对账配对必须确定，AI 帮解释差异可能是什么原因。
