## 问题

关注的信息散落在十几个网站和公众号，每天刷来刷去浪费时间，重要的版本发布还是会错过。

## 适用场景

- 适合：需要持续跟进技术动态的人
- 不值得：信息源很少的
- 前提：信息源提供 RSS（大多数博客和 GitHub Releases 都有）

## 工具选型

| 方案                | 特点                      | 适用           |
| ------------------- | ------------------------- | -------------- |
| FreshRSS / Miniflux | 自建 RSS 阅读器           | 开源           |
| Feedly / Inoreader  | RSS 服务                  | 海外常用       |
| Python 脚本 + 推送  | 自定义摘要                | ✅ 方案采用    |
| RSSHub              | 给没有 RSS 的网站生成订阅 | 开源，国内常用 |

自建阅读器适合每天浏览；只想看摘要就用脚本汇总推送。没有 RSS 的网站用 RSSHub 生成。

## 怎么做

- 把关注的技术博客、GitHub 项目发布（Releases 的 Atom 源）、新闻源加入 RSS 订阅列表
- 每天早上抓取过去 24 小时的新文章，按 URL 去重，按主题分组
- 每组只列标题和一句摘要（可以用文章自带摘要，或者让大模型生成）
- 汇总成一条消息推到企业微信或 Telegram，感兴趣的再点开

## 实施步骤

| 步骤 | 做什么               | 怎么验证           |
| ---- | -------------------- | ------------------ |
| 1    | 整理订阅源列表       | 按主题分组         |

## 常见坑

- **信息太多又变成负担**：订阅源太多。控制数量，按主题限制条数。
- **网站没有 RSS**：公众号等。用 RSSHub 生成订阅。
- **时区导致漏文章**：发布时间是 UTC。统一时区比较。

## AI 视角

**🤖 AI 是核心**

- **AI 能做什么**：给每篇文章写一句摘要，按你的兴趣排序
- **不该交给 AI**：订阅源由自己选
- **怎么落地**：抓取后交给 AI 摘要

常见追问：

**问：RSS 和 Atom 的区别？**

答：都是订阅格式，Atom 更新更规范；feedparser 两种都能解析。

**问：GitHub 项目怎么订阅版本发布？**

答：项目 Releases 页面后加 .atom 就是订阅地址。

**问：怎么避免信息过载？**

答：少而精的订阅源、按主题限制条数、定期清理。

**被问到「能不能用 AI」时：** AI 让每天的信息摘要真正读得懂，而不只是标题。
