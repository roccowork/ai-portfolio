## 问题

服务器、接口都正常，用户却登录不了（前端报错、第三方登录挂了）。只有从用户视角检查才能发现。

## 适用场景

- 适合：有登录、下单等关键流程的对外网站和 App 后端
- 不值得：纯 API、没有用户界面的内部服务——接口探测就够了
- 前提：有专用的测试账号，测试操作不会产生真实交易

## 工具选型

| 方案                         | 特点                   | 适用        |
| ---------------------------- | ---------------------- | ----------- |
| Playwright / Puppeteer 自写  | 流程完全自定义         | ✅ 方案采用 |
| Grafana Synthetic Monitoring | 托管，多地域探测       | 外企常用    |
| Uptime Kuma                  | 简单的 HTTP/关键字探测 | ✅ 本站已用 |
| 阿里云云拨测、听云           | 国内多地域、多运营商   | 国内常用    |

选 Playwright：能模拟真实用户的完整操作（登录、点击、等待元素），失败时有截图，能发现接口探测发现不了的前端问题。

## 怎么做

- 用 Playwright 写关键路径脚本：打开首页、登录测试账号、搜索、打开详情页
- 每步耗时推到 Prometheus Pushgateway，超过阈值或失败就告警
- 失败时保存截图和浏览器控制台日志，附在告警消息里，一眼看到页面坏在哪
- 测试账号单独建，只有只读权限

## 实施步骤

| 步骤 | 做什么                               | 怎么验证                       |
| ---- | ------------------------------------ | ------------------------------ |
| 1    | 梳理关键路径，创建测试账号           | 测试账号只有只读或测试数据权限 |
| 2    | 写 Playwright 脚本，每步计时         | 本地运行能完整走通             |
| 3    | 打包成镜像，CronJob 每 5 分钟运行    | Pushgateway 里有每步耗时       |
| 4    | 配置告警：失败或超时                 | 故意改坏页面元素时触发告警     |
| 5    | 失败时上传截图到对象存储并附在告警里 | 告警消息里能点开截图           |

## 常见坑

- **页面改版导致脚本误报**：选择器依赖了样式类名。用 data-testid 或按文字/角色定位。
- **测试账号被风控锁定**：频繁登录触发安全策略。和安全团队报备，加白名单。
- **只在一个地点探测**：看不到地域性问题。多个地域部署探测点。

## AI 视角

**✨ AI 能增强**

- **AI 能做什么**：页面改版后自动修复失效的选择器；失败截图交给多模态模型判断页面哪里坏了
- **不该交给 AI**：拨测成功与否要靠确定的断言，不能让模型判断「看起来正常」
- **怎么落地**：失败时把截图交给模型生成描述附在告警里

## 面试怎么讲

30 秒讲法（方案思路；没有实际落地，面试时如实说明是设计过的方案）：

> 我会用 Playwright 写关键路径脚本：打开首页、登录测试账号、搜索、打开详情页，每步计时推到 Pushgateway，失败或超时就告警，并附上截图和浏览器控制台日志。选择器用 data-testid，避免页面改样式就误报。本站用 Uptime Kuma 做了简单的页面和证书拨测，这是它的进阶版。

常见追问：

**问：拨测和普通监控有什么区别？**

答：普通监控看服务器和接口；拨测从用户视角走完整流程，能发现前端报错、第三方登录失败这类问题。

**问：怎么避免误报？**

答：失败重试一次再告警、稳定的选择器、多个探测点同时失败才算故障。

**问：拨测会不会产生脏数据？**

答：用专门的测试账号和测试商品，不做支付等真实交易，定期清理测试数据。

**被问到「能不能用 AI」时：** 拨测断言要确定，AI 用来看失败截图描述「页面哪里坏了」，加快定位。
