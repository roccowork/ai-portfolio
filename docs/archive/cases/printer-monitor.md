## 问题

墨粉总是在急着打合同时用完；打印机卡纸、缺纸也要等员工来报修。

## 适用场景

- 适合：网络打印机多、耗材经常临时断供的公司
- 不值得：只有一两台打印机的
- 前提：打印机联网并开启 SNMP

## 工具选型

| 方案                       | 特点           | 适用        |
| -------------------------- | -------------- | ----------- |
| Python + SNMP              | 零成本         | ✅ 方案采用 |
| 打印机厂商管理软件         | 品牌专用       | 单一品牌    |
| Zabbix 打印机模板          | 已有 Zabbix 时 | 国内常用    |
| 打印管理服务（租赁商提供） | 厂商代管       | 租赁打印机  |

标准 Printer-MIB 适用于大多数品牌，一个脚本就能管住所有打印机。

## 怎么做

- 网络打印机基本都支持标准 Printer-MIB，Python 用 SNMP 读取每个耗材的当前量和最大量
- 余量低于 15% 发企业微信给行政，附型号和耗材编号；同一个耗材 3 天内只提醒一次
- 打印机报错（卡纸、缺纸、离线）通知 IT
- 每月统计各打印机的打印页数，评估是否需要调整位置或租赁方案

## 实施步骤

| 步骤 | 做什么                 | 怎么验证                   |
| ---- | ---------------------- | -------------------------- |
| 1    | 整理打印机清单和 IP    | 清单完整                   |
| 2    | 开启 SNMP 并测试读取   | snmpget 能读到墨粉余量     |
| 3    | 脚本读取余量和错误状态 | 输出每台打印机的耗材百分比 |
| 4    | 低于 15% 通知行政      | 行政收到提醒               |
| 5    | 每月统计打印页数       | 有月度报告                 |

## 关键代码

示例代码（简化），没有在生产环境运行：

```python
# prtMarkerSuppliesLevel / prtMarkerSuppliesMaxCapacity（RFC 3805）
level = snmp_get(ip, "1.3.6.1.2.1.43.11.1.1.9.1.1")
maxc = snmp_get(ip, "1.3.6.1.2.1.43.11.1.1.8.1.1")
if maxc > 0 and level / maxc < 0.15:
    notify(f"{name} 墨粉剩 {level / maxc:.0%}，请准备更换")
```

## 常见坑

- **余量返回 -3 或 -2**：打印机不支持精确值（-3 表示还有余量）。对特殊值单独处理。
- **一台打印机有多个耗材**：只读了第一个。遍历所有耗材索引。
- **SNMP 读取超时**：打印机休眠。重试，并在休眠时间外检查。

常见追问：

**问：SNMP 是什么？**

答：简单网络管理协议，设备通过它暴露状态信息，管理端用 get/walk 读取。

**问：OID 是什么？**

答：对象标识符，每个监控项对应一个唯一的数字路径，比如墨粉余量在 Printer-MIB 的 prtMarkerSuppliesLevel。

**问：为什么要统计打印量？**

答：评估是否需要调整打印机布局、租赁方案，或者推动无纸化。
