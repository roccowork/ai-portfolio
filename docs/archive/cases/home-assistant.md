## 问题

各品牌智能设备各有一个 App，不能联动；出门忘关电器、家里漏水没人知道。

## 适用场景

- 适合：家里有多个品牌智能设备、喜欢折腾的人
- 不值得：只有一两个智能设备的
- 前提：有一台常开的小主机（树莓派、旧电脑、NAS）

## 工具选型

| 方案                     | 特点               | 适用         |
| ------------------------ | ------------------ | ------------ |
| Home Assistant           | 开源，支持设备最多 | 国内外都常用 |
| 米家 / 涂鸦 App          | 单一生态，简单     | 国内常用     |
| Apple 家庭 / Google Home | 生态内联动         | 海外常用     |
| Node-RED                 | 可视化流程         | 配合 HA      |

Home Assistant 把不同品牌设备统一起来，规则可以写成配置文件放进 Git。

## 怎么做

- Home Assistant 部署在家里的小主机或树莓派上，接入不同品牌的设备（Zigbee 网关、Wi-Fi 设备、米家等）
- 规则示例：手机定位离家后关闭所有灯和指定插座；日落后有人回家自动开灯；漏水传感器触发时关闭水阀并推送
- 数据保存在本地，不依赖厂商云，断网也能运行
- 配置文件放进 Git 管理，和运维的「配置即代码」一样

## 实施步骤

| 步骤 | 做什么                                  | 怎么验证         |
| ---- | --------------------------------------- | ---------------- |
| 1    | 在小主机上部署 Home Assistant（Docker） | 网页能打开       |
| 2    | 接入设备（Zigbee 网关、米家集成）       | 设备状态可见     |
| 3    | 写自动化规则                            | 手动触发测试通过 |
| 4    | 配置手机 App 通知和定位                 | 离家时收到通知   |
| 5    | 配置文件放 Git，定期备份                | 重装后能恢复     |

## 关键代码

示例代码（简化），没有在生产环境运行：

```yaml
automation:
  - alias: 漏水自动关阀
    trigger:
      - platform: state
        entity_id: binary_sensor.kitchen_leak
        to: 'on'
    action:
      - service: valve.close_valve
        target: { entity_id: valve.main_water }
      - service: notify.mobile_app_phone
        data: { message: '厨房检测到漏水，已关闭总水阀' }
```

## 常见坑

- **定位不准导致误触发**：手机定位漂移。加延迟和多条件（Wi-Fi 断开 + 定位）。
- **厂商云接口变更导致设备失联**：依赖厂商云。优先选本地协议（Zigbee、Matter）。
- **对外暴露 Home Assistant 被入侵**：直接开放公网端口。用 VPN 或 Tailscale 远程访问。

## AI 视角

**✨ AI 能增强**

- **AI 能做什么**：用自然语言控制家里设备，或者根据习惯自动推荐规则
- **不该交给 AI**：安全相关（关水阀、门锁）必须确定的规则
- **怎么落地**：Home Assistant 已支持接入大模型做语音助手

> 我在家里用 Home Assistant 把不同品牌的设备统一起来：手机离家自动关灯和指定插座，漏水传感器触发时关闭总水阀并推送手机。数据在本地运行，配置文件放进 Git 管理，和运维的配置即代码一样。

常见追问：

**问：Zigbee 和 Wi-Fi 设备的区别？**

答：Zigbee 低功耗、组网稳定，需要网关；Wi-Fi 设备直接连路由器，耗电大，多了会占用路由器连接数。

**问：Matter 是什么？**

答：新的智能家居统一标准，让不同品牌设备能互联。

**问：远程访问怎么做才安全？**

答：不直接暴露公网端口，用 VPN、Tailscale 或官方云服务。

**被问到「能不能用 AI」时：** 安全相关的规则必须确定，AI 用来做自然语言控制。
