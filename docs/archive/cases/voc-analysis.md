## 问题

客户的声音散落在电商评价、应用商店评论、客服工单、问卷开放题里，每月几千条。没人能全部读完，只能偶尔抽看几条；产品经理凭感觉排优先级，「最近差评变多了」说不清是因为什么。一个新出现的问题（比如某次更新后闪退）要等投诉堆积起来才被重视。

## 适用场景

- 适合：每月有上千条客户反馈、多渠道收集的 C 端或电商企业
- 不值得：反馈很少、产品经理能全部读完的
- 前提：各渠道的反馈能导出或通过接口获取

## 工具选型

| 方案                                | 特点                   | 适用        |
| ----------------------------------- | ---------------------- | ----------- |
| Qualtrics、Medallia                 | 专业客户体验管理平台   | 外企常用    |
| 国产 VOC 平台、电商平台自带评价分析 | 中文和电商场景         | 国内常用    |
| 自写：大模型归类 + 向量聚类 + 报表  | 可定制分类体系，成本低 | ✅ 方案采用 |
| 人工抽样阅读                        | 现状                   | 以偏概全    |

自写的核心是一套稳定的分类体系：AI 按固定的主题打标签，才能做趋势对比；再用聚类发现分类体系之外的新问题。

## 怎么做

- **收集**：每天从各渠道拉取新反馈，统一字段（渠道、时间、评分、内容、产品版本），去掉重复和无意义的内容（「好评」「默认好评」）
- **归类**：大模型按固定分类体系打标签：产品模块（物流、包装、质量、价格、客服、App 体验）、情绪（正面 / 中性 / 负面）、具体问题点；一条反馈可以有多个标签
- **发现新问题**：对负面反馈做向量聚类，出现了不属于已有分类、且数量在增长的簇，就标为「新问题」，附代表性原文
- **报告**：每周自动生成客户之声报告——各主题的数量和情绪变化、差评原因排名、新出现的问题、典型原文，发给产品、运营和管理层
- 紧急信号（如「过敏」「起火」「泄露」）实时通知相关负责人

## 实施步骤

| 步骤 | 做什么                              | 怎么验证                 |
| ---- | ----------------------------------- | ------------------------ |
| 1    | 和产品、客服一起定分类体系          | 覆盖 90% 以上的反馈      |
| 2    | 对接各渠道数据，统一字段            | 每天自动收集             |
| 3    | 人工标注 300 条，评估 AI 归类准确率 | 准确率达到可用水平       |
| 4    | 负面反馈聚类，发现新问题            | 回放历史能发现当时的问题 |
| 5    | 每周报告和紧急信号通知              | 产品经理用报告排优先级   |

## 关键代码

示例代码（简化），没有在生产环境运行：

```python
TAXONOMY = {"物流": ["慢", "破损", "丢件"], "质量": ["做工", "色差", "故障"],
            "App": ["闪退", "卡顿", "登录"], "客服": ["态度", "响应慢"], "价格": ["贵", "降价"]}

for batch in chunks(new_feedback, 50):  # 批量处理降低成本
    labels = llm.complete(LABEL_PROMPT.format(taxonomy=TAXONOMY, items=batch), response_format=LABEL_SCHEMA)
    db.save_labels(labels)
    for x in labels:
        if x.urgent:  # 安全、健康类关键信号
            notify(OWNERS[x.topic], f"紧急反馈：{x.text}")

clusters = cluster(embed(db.negative(days=7, topic="其他")))
new_issues = [c for c in clusters if c.size >= 10 and c.growth > 2]  # 新出现且在增长
```

## 效果指标

| 指标       | 做之前           | 预期效果（估算） |
| ---------- | ---------------- | ---------------- |
| 反馈覆盖率 | 抽看几十条       | 全部归类         |
| 差评原因   | 凭感觉           | 有排名和趋势     |
| 新问题发现 | 投诉堆积后才重视 | 一周内发现       |
| 报告制作   | 人工整理，半天   | 自动生成         |

产品决策从「凭感觉」变成「看数据」，新问题在扩大前就被发现。

## 常见坑

- **分类体系经常改**：无法做趋势对比。分类体系稳定，新问题先放在「其他」里观察，确认后再加入。
- **反讽和隐晦表达识别错**：「这物流真是快，等了半个月」。抽样复核，把误判的例子加进提示词。
- **只看数量不看影响**：小众问题数量少但很严重。关键词实时通知，报告里附严重程度。
- **报告没人看**：发了没行动。报告里每个问题指定负责部门，下周跟进处理进度。

## AI 视角

**🤖 AI 是核心**

- **AI 能做什么**：读懂口语化、带情绪的反馈，按主题归类，识别反讽，从大量文本里发现新的问题模式，写出报告摘要
- **不该交给 AI**：分类体系的制定、问题优先级的决策、对客户的回应
- **怎么落地**：固定分类体系保证可比，AI 负责归类和总结，聚类发现新问题，人负责决策和行动

## 面试怎么讲

30 秒讲法（方案思路；没有实际落地，面试时如实说明是设计过的方案）：

> 我会每天把电商评价、应用商店评论、客服工单、问卷开放题统一收集，用大模型按固定分类体系打标签：产品模块、情绪、具体问题。对负面反馈做向量聚类，出现新的、在增长的问题簇就标出来。每周自动生成客户之声报告，包括差评原因排名、趋势、新问题和典型原文；安全类关键词实时通知负责人。先人工标注 300 条评估准确率。

常见追问：

**问：为什么要固定分类体系，不让 AI 自由总结？**

答：自由总结每次结果不一样，无法做周与周的对比；固定分类才能看趋势，新问题用聚类单独发现。

**问：怎么控制成本？**

答：先去重和过滤无意义内容，批量处理，用较便宜的模型做归类，只对报告摘要用更强的模型。

**问：VOC 分析的结果怎么推动改进？**

答：每个问题指定负责部门，跟踪处理进度，改进后观察对应主题的差评是否下降，形成闭环。

**被问到「能不能用 AI」时：** 这个案例本身就是 AI；固定分类保证可比，AI 负责读懂和归类。
