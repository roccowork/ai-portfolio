## 问题

员工电脑补丁全靠自觉，有的半年没更新；一次性全推又怕补丁有问题导致大面积蓝屏。

## 适用场景

- 适合：Windows 电脑和服务器几十台以上的公司
- 不值得：全部是云桌面或已经由 MSP 托管补丁的
- 前提：有 WSUS 或 Intune；电脑加入域

## 工具选型

| 方案                                  | 特点           | 适用     |
| ------------------------------------- | -------------- | -------- |
| WSUS + 组策略                         | 免费，本地部署 | 国内常用 |
| Intune（Windows Update for Business） | 云管理，更新环 | 外企常用 |
| SCCM / MECM                           | 功能最全，较重 | 大型企业 |
| 第三方补丁（PDQ、ManageEngine）       | 也管第三方软件 | 中小企业 |

有 Intune 用更新环，没有就 WSUS + 组策略；都按「测试组先装、一周后全员」的节奏。

## 怎么做

- 分组：IT 和少量志愿者为测试组，补丁发布当天自动批准给测试组；一周没问题再批准给全员
- 有 Intune 的用 Windows Update for Business 的更新环（ring）实现，没有的用 WSUS + 组策略
- 每周用 PowerShell 汇总每台电脑最近一次安装补丁的时间和待重启状态，超过 30 天没更新的列出来提醒本人
- 设置非工作时间的自动重启窗口，减少打扰

## 实施步骤

| 步骤 | 做什么                     | 怎么验证               |
| ---- | -------------------------- | ---------------------- |
| 1    | 分组：测试组和全员组       | 组策略按组生效         |
| 2    | 补丁发布日自动批准给测试组 | 测试组当天安装         |
| 3    | 一周无问题批准全员         | 全员在维护窗口安装     |
| 4    | 设置非工作时间自动重启     | 不再白天强制重启       |
| 5    | 每周合规报告               | 列出 30 天未更新的电脑 |

## 关键代码

示例代码（简化），没有在生产环境运行：

```powershell
Get-ADComputer -Filter { Enabled -eq $true } | ForEach-Object {
  $last = Invoke-Command -ComputerName $_.Name -ErrorAction SilentlyContinue {
    (Get-HotFix | Sort-Object InstalledOn -Descending | Select-Object -First 1).InstalledOn
  }
  [pscustomobject]@{ Computer = $_.Name; LastPatch = $last }
} | Where-Object { $_.LastPatch -lt (Get-Date).AddDays(-30) }
```

## 效果指标

| 指标         | 做之前       | 预期效果（估算） |
| ------------ | ------------ | ---------------- |
| 补丁覆盖率   | 不知道       | 每周可见         |
| 问题补丁影响 | 可能全员蓝屏 | 只影响测试组     |
| 白天强制重启 | 经常发生     | 安排在非工作时间 |

补丁覆盖率可量化，问题补丁只影响测试组。IT 体检工具里的「补丁」检查项就是它的单机版。

## 常见坑

- **远程办公电脑不连 WSUS**：WSUS 在内网。改用 Intune 或允许从微软更新，WSUS 只做审批。
- **WSUS 磁盘占满**：同步了所有产品和语言。只同步需要的产品和语言，定期清理。
- **补丁装了但没重启，不算生效**：用户一直不重启。合规报告里统计待重启，设置截止日期强制重启。

## 面试怎么讲

30 秒讲法（方案思路；没有实际落地，面试时如实说明是设计过的方案）：

> 我会把电脑分成测试组和全员组：微软发布补丁当天自动批准给测试组，一周没问题再批准给全员；有 Intune 用更新环实现，没有就用 WSUS 加组策略。自动重启安排在非工作时间。每周用 PowerShell 汇总每台电脑最近一次装补丁的时间和待重启状态，超过 30 天没更新的提醒本人。

常见追问：

**问：微软的补丁星期二是什么？**

答：每月第二个星期二发布安全更新，企业通常据此安排测试和部署节奏。

**问：为什么要分批推送补丁？**

答：补丁偶尔有兼容性问题，先在小范围验证，避免大面积故障。

**问：紧急漏洞怎么处理？**

答：跳过常规周期，评估后尽快推送；无法立即打补丁时先做临时缓解。

**被问到「能不能用 AI」时：** AI 帮我读微软每月的补丁说明，总结已知问题。
