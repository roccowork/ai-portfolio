## 问题

勒索病毒拿到管理员权限后，会先删除能访问到的备份再加密数据。备份和生产用同一套账号，等于没有备份。

## 适用场景

- 适合：担心勒索病毒的公司——几乎所有公司
- 不值得：备份已经存在完全离线介质（磁带离线保存）的
- 前提：存储支持对象锁定（S3 兼容存储大多支持）

## 工具选型

| 方案                          | 特点                   | 适用                     |
| ----------------------------- | ---------------------- | ------------------------ |
| S3 对象锁定（合规模式）       | 保留期内任何人不能删除 | AWS、MinIO、部分国产存储 |
| restic / Veeam 配合不可变存储 | 备份软件支持           | 国内外都用               |
| 离线磁带 / 冷备硬盘           | 物理隔离               | 传统                     |
| 云厂商备份保险库              | 托管不可变备份         | 云上                     |

对象锁定合规模式：连 root 账号都不能在保留期内删除，是对抗勒索最有效的手段之一。

## 怎么做

- 备份存储使用 S3 对象锁定（Object Lock，合规模式）：每个备份对象写入后 30 天内任何人都无法删除或修改
- 备份程序用的账号只有写入权限，没有删除权限；管理账号单独保管并开启两步验证
- 保留至少一份离线或异地副本（3-2-1 原则：3 份数据、2 种介质、1 份异地）
- 每月从锁定的备份里做一次恢复演练

## 实施步骤

| 步骤 | 做什么                         | 怎么验证                      |
| ---- | ------------------------------ | ----------------------------- |
| 1    | 创建开启对象锁定的桶           | 桶属性显示 Object Lock 已开启 |
| 2    | 设置默认保留 30 天（合规模式） | 尝试删除对象失败              |
| 3    | 备份账号只给写入权限           | 用该账号删除被拒绝            |
| 4    | 备份软件写入锁定桶             | 新快照带保留期                |
| 5    | 每月从锁定桶恢复演练           | 能完整恢复                    |

## 关键代码

示例代码（简化），没有在生产环境运行：

```bash
# 创建开启对象锁定的桶，默认保留 30 天（合规模式下保留期内无法删除）
aws s3api create-bucket --bucket corp-backup --object-lock-enabled-for-bucket
aws s3api put-object-lock-configuration --bucket corp-backup --object-lock-configuration \
  '{"ObjectLockEnabled":"Enabled","Rule":{"DefaultRetention":{"Mode":"COMPLIANCE","Days":30}}}'
```

## 效果指标

| 指标           | 做之前 | 预期效果（估算）  |
| -------------- | ------ | ----------------- |
| 勒索后备份被删 | 可能   | 保留期内无法删除  |
| 恢复能力       | 不确定 | 每月验证          |
| 3-2-1 原则     | —      | 满足异地 + 不可变 |

即使服务器和管理员账号都被攻破，30 天内的备份仍然完整可用。本站的 restic 备份到 R2，是这个方案的基础版本。

## 常见坑

- **保留期设错无法缩短**：合规模式下连管理员都不能改短。先用治理模式测试，确认后再用合规模式。
- **存储费用增长**：保留期内旧数据不能删。合理设置保留期，配合生命周期转低频存储。
- **restic prune 失败**：prune 要删除被锁定的对象。备份软件要支持不可变存储的方式（如只追加、按保留期清理）。

## 面试怎么讲

30 秒讲法（方案思路；没有实际落地，面试时如实说明是设计过的方案）：

> 勒索病毒拿到管理员权限后会先删备份。我会把备份写进开启对象锁定合规模式的存储桶，默认保留 30 天，保留期内连管理员都删不掉；备份程序的账号只有写入权限，没有删除权限；再保留一份离线或异地副本，满足 3-2-1。每月从锁定的备份里做恢复演练。

常见追问：

**问：治理模式和合规模式的区别？**

答：治理模式下有特殊权限的用户可以删除或修改保留期；合规模式下任何人（包括 root）在保留期内都不能删除。

**问：3-2-1-1-0 原则是什么？**

答：3 份数据、2 种介质、1 份异地、1 份不可变或离线、0 恢复错误（定期验证）。

**问：怎么发现备份被篡改？**

答：restic check 校验仓库完整性；监控备份大小和数量的异常变化。

**被问到「能不能用 AI」时：** 不可变备份是存储层机制，不需要 AI。
