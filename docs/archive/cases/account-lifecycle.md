## 问题

IT 收到入职通知后一个个系统手动建号，容易漏；离职员工的账号几个月后还能登录，是最常见的安全隐患之一。

## 适用场景

- 适合：员工几十人以上、有多个系统账号的公司；等保和审计要求账号及时回收的
- 不值得：几个人的小团队
- 前提：HR 系统或花名册能作为唯一数据来源

## 工具选型

| 方案                                    | 特点                     | 适用                     |
| --------------------------------------- | ------------------------ | ------------------------ |
| PowerShell + AD + 各系统 API            | 完全可控                 | 国内中小企业常用         |
| Microsoft Entra ID（Azure AD）+ HR 集成 | 云身份，自动同步         | 外企常用                 |
| Okta / Authing                          | 身份平台，SSO + 生命周期 | 外企 Okta / 国内 Authing |
| n8n 流程编排                            | 串联多个系统             | ✅ 可选                  |

以 HR 系统为唯一来源，身份平台或脚本同步到各系统；所有系统尽量接 SSO，减少需要单独开关的账号。

## 怎么做

- 以 HR 系统为唯一来源：新员工记录出现即建号，离职日期到达即禁用（不立即删除，保留 30 天给交接）
- AD：按部门放进对应 OU、加入部门组，自动获得共享盘和打印机权限；随机初始密码首次登录必须修改
- 邮箱、企业微信、VPN 通过各自 API 同步开通或禁用；全部完成后给主管发一份清单
- 每月对账：AD 里启用但 HR 里已离职的账号列出来，人工确认

## 实施步骤

| 步骤 | 做什么                                       | 怎么验证                       |
| ---- | -------------------------------------------- | ------------------------------ |
| 1    | 确定数据来源和字段（工号、部门、入离职日期） | HR 能导出或提供接口            |
| 2    | AD 建号、进 OU、加组                         | 新员工自动获得部门权限         |
| 3    | 邮箱、企业微信、VPN 同步开通                 | 各系统都有账号                 |
| 4    | 离职日期到达自动禁用，30 天后删除            | 离职员工当天无法登录           |
| 5    | 每月对账                                     | 列出 AD 启用但 HR 已离职的账号 |

## 关键代码

示例代码（简化），没有在生产环境运行：

```powershell
$dept = $emp.Department
New-ADUser -Name $emp.Name -SamAccountName $emp.Login `
  -Path "OU=$dept,OU=Staff,DC=corp,DC=local" `
  -AccountPassword (ConvertTo-SecureString $tmpPwd -AsPlainText -Force) `
  -ChangePasswordAtLogon $true -Enabled $true
Add-ADGroupMember -Identity "GRP-$dept" -Members $emp.Login
```

## 效果指标

| 指标           | 做之前                 | 预期效果（估算）         |
| -------------- | ---------------------- | ------------------------ |
| 新员工账号就绪 | 入职后 1～2 天（估算） | 入职当天                 |
| 离职账号停用   | 经常遗漏               | 离职当天                 |
| 审计证据       | 零散                   | 每个账号有开通和禁用记录 |

新员工第一天就能登录全部系统；离职当天账号就停用，审计时能拿出每个账号的开通和禁用记录。

## 常见坑

- **HR 数据错误导致误禁用**：花名册填错日期。批量操作先 plan，异常数量超过阈值时停下等人确认。
- **离职禁用后数据无法交接**：直接删除账号。先禁用并转移邮箱和文件，30 天后再删除。
- **有系统没接入**：新采购的 SaaS 没纳入流程。采购流程要求接入 SSO 或提供接口。

## AI 视角

**⚙️ 规则就够**

- **AI 能做什么**：基本不需要
- **不该交给 AI**：账号开通和禁用必须确定、可审计
- **怎么落地**：保持规则

## 面试怎么讲

30 秒讲法（方案思路；没有实际落地，面试时如实说明是设计过的方案）：

> 我会以 HR 系统为唯一来源：新员工记录出现就在 AD 建号、按部门放进 OU 和组，自动获得共享盘和打印机权限，同时开通邮箱、企业微信、VPN；离职日期到达自动禁用，30 天后再删除，留出交接时间。批量操作先 plan 再 apply，每月对账一次。我做的办公自动化工具里已经实现了花名册比对 LDAP 的部分。

常见追问：

**问：为什么离职先禁用而不是直接删除？**

答：删除不可恢复，邮件和文件需要交接，审计也需要保留记录；禁用一段时间后再删除。

**问：什么是 SSO？有什么好处？**

答：单点登录，一个账号登录所有系统；离职时只需禁用一个账号，安全且方便。

**问：AD 的 OU 和组有什么区别？**

答：OU 用于组织结构和下发组策略，组用于授权；权限应该授给组，而不是个人。

**被问到「能不能用 AI」时：** 权限变更必须确定可审计，不用 AI 做决定。
