## 问题

热销商品断货了才发现，补货要等两周；滞销商品却越压越多，占用资金和仓库。

## 适用场景

- 适合：有库存的零售、电商、制造企业
- 不值得：没有实物库存的业务
- 前提：能从 ERP 或进销存系统获取库存和销量

## 工具选型

| 方案                                    | 特点             | 适用         |
| --------------------------------------- | ---------------- | ------------ |
| Python 脚本 + ERP 数据                  | 按自己的规则计算 | ✅ 方案采用  |
| ERP 自带安全库存预警（金蝶、用友、SAP） | 和业务系统一体   | 国内外都常用 |
| 电商平台库存工具                        | 平台自带         | 电商         |
| BI 看板                                 | 可视化           | 管理层       |

ERP 自带的通常是固定安全库存；按销量动态计算可售天数和建议采购量，需要自己算。

## 怎么做

- 每天从 ERP 读取各仓库库存和近 30 天的日均销量
- 可售天数 = 库存 / 日均销量；低于「采购周期 + 安全天数」就预警
- 建议采购量 = 日均销量 ×（采购周期 + 安全天数 + 下次补货间隔）- 当前库存 - 在途数量
- 同时列出 90 天无销量的滞销商品，提醒清理

## 实施步骤

| 步骤 | 做什么                        | 怎么验证            |
| ---- | ----------------------------- | ------------------- |
| 1    | 获取库存、在途、近 30 天销量  | 数据完整            |
| 2    | 计算日均销量和可售天数        | 和人工核算一致      |
| 3    | 按采购周期 + 安全天数判断预警 | 即将断货的被列出    |
| 4    | 计算建议采购量                | 采购员认可建议      |
| 5    | 列出滞销商品                  | 90 天无销量的被列出 |

## 效果指标

| 指标     | 做之前       | 预期效果（估算） |
| -------- | ------------ | ---------------- |
| 断货     | 卖断了才发现 | 提前预警         |
| 积压     | 越压越多     | 滞销清单         |
| 采购决策 | 凭经验       | 按数据建议       |

减少断货和积压，采购从凭经验变成按数据下单。

## 常见坑

- **促销期间销量异常导致误判**：日均销量被拉高或拉低。剔除促销期数据，或按季节调整。
- **新品没有历史销量**：无法计算。新品用同类商品数据或人工设定。
- **多仓库调拨没考虑**：只看单仓库。先看其他仓库能否调拨。

## AI 视角

**✨ AI 能增强**

- **AI 能做什么**：用预测模型预测销量，替代简单平均
- **不该交给 AI**：库存数据必须准确
- **怎么落地**：先用平均，再引入预测

## 面试怎么讲

30 秒讲法（方案思路；没有实际落地，面试时如实说明是设计过的方案）：

> 我会每天从 ERP 读取各仓库的库存、在途数量和近 30 天销量，算出日均销量和可售天数；可售天数低于「采购周期 + 安全天数」就预警，并给出建议采购量。同时列出 90 天没有销量的滞销商品，提醒清理。

常见追问：

**问：安全库存怎么定？**

答：考虑需求波动和到货时间的不确定性，常用：安全库存 = 日均销量 × 安全天数，或者用标准差计算。

**问：什么是再订货点？**

答：库存降到这个数量时就该下单：日均销量 × 采购周期 + 安全库存。

**问：为什么要剔除促销数据？**

答：促销期间销量不代表平时需求，会导致建议采购量偏大。

**被问到「能不能用 AI」时：** 采购建议可以用 AI 销量预测提高准确度。
