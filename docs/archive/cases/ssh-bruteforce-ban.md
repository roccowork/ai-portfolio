## 问题

公网服务器每天被扫几千次 SSH 密码，日志刷屏；只要有一个弱口令账号就会被攻破。

## 适用场景

- 适合：所有有公网 IP、开放 SSH 的服务器
- 不值得：SSH 不对公网开放（只通过 VPN 或堡垒机访问）的
- 前提：已经禁止密码登录（根本措施）

## 工具选型

| 方案           | 特点                  | 适用       |
| -------------- | --------------------- | ---------- |
| fail2ban       | 老牌，支持多种服务    | 国内外通用 |
| CrowdSec       | 社区共享恶意 IP 情报  | 新兴       |
| sshguard       | 轻量                  | 简单场景   |
| 云安全组白名单 | 只允许指定 IP 访问 22 | 最彻底     |

最彻底的是安全组只对固定 IP 开放 22；做不到时用 fail2ban 自动封禁，减少日志噪音和攻击面。

## 怎么做

- 根本措施先做：禁止密码登录和 root 登录，只用密钥（实验 01 和本站服务器都已做）
- fail2ban 读取 SSH 认证日志，同一 IP 10 分钟内失败 5 次就用 nftables 封 1 小时
- 开启 recidive 规则：一天内被封 3 次的 IP 封一周
- 每天汇总被封 IP 数和来源国家发到群里；公司出口 IP 加白名单，避免误封自己

## 实施步骤

| 步骤 | 做什么                         | 怎么验证                           |
| ---- | ------------------------------ | ---------------------------------- |
| 1    | 禁止密码登录和 root 登录       | 只能用密钥登录                     |
| 2    | 安装 fail2ban，配置 sshd jail  | `fail2ban-client status sshd` 正常 |
| 3    | 设置阈值和封禁时间             | 测试 IP 多次失败后被封             |
| 4    | 开启 recidive 长期封禁         | 屡犯 IP 被封一周                   |
| 5    | 公司出口 IP 加白名单，每日汇总 | 白名单 IP 不会被封                 |

## 关键代码

示例代码（简化），没有在生产环境运行：

```ini
[sshd]
enabled  = true
backend  = systemd
maxretry = 5
findtime = 10m
bantime  = 1h
ignoreip = 127.0.0.1/8 203.0.113.10

[recidive]
enabled  = true
bantime  = 1w
```

## 效果指标

| 指标             | 做之前     | 预期效果（估算）     |
| ---------------- | ---------- | -------------------- |
| SSH 爆破日志     | 每天几千条 | 大部分被拦截         |
| 弱口令被攻破风险 | 存在       | 密钥登录 + 封禁      |
| 日志噪音         | 大         | 真正的异常更容易看到 |

大量扫描被挡在门外，日志干净了，真正的异常更容易发现。

## 常见坑

- **把自己封了**：自己多次输错。白名单加公司出口 IP；云控制台留有救援登录方式。
- **fail2ban 读不到日志**：Ubuntu 22.04 后 sshd 日志在 journald。backend 设为 systemd。
- **只有 fail2ban 没禁用密码登录**：以为封 IP 就安全了。根本措施是密钥登录，fail2ban 只是减少噪音。

## AI 视角

**⚙️ 规则就够**

- **AI 能做什么**：基本不需要
- **不该交给 AI**：封禁规则必须确定
- **怎么落地**：保持规则

## 面试怎么讲

30 秒讲法（方案思路；没有实际落地，面试时如实说明是设计过的方案）：

> 根本措施是禁止 SSH 密码登录和 root 登录，只用密钥，实验 01 和本站服务器都已经做了。在此之上用 fail2ban：同一 IP 10 分钟内失败 5 次封 1 小时，一天内被封 3 次的封一周；公司出口 IP 加白名单。新系统 sshd 日志在 journald 里，backend 要设成 systemd。

常见追问：

**问：只靠 fail2ban 安全吗？**

答：不够。攻击者可以换 IP 慢速尝试；必须禁用密码登录，最好 SSH 只对 VPN 或堡垒机开放。

**问：fail2ban 是怎么封 IP 的？**

答：监控日志匹配失败记录，超过阈值后调用 iptables/nftables 添加拒绝规则，到期自动删除。

**问：除了 SSH 还能保护什么？**

答：Nginx 登录接口、邮件服务等任何会记录失败日志的服务。

**被问到「能不能用 AI」时：** fail2ban 规则就够了。
