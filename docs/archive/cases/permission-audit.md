## 问题

共享盘用了几年，权限越加越乱：有的目录所有人可写、有的直接授权给个人、离职员工还在权限列表里。等保、ISO 审计时需要证明「最小权限」。

## 适用场景

- 适合：使用 Windows 文件服务器共享盘多年的公司；有等保或 ISO 27001 审计的
- 不值得：文件都在 SaaS 网盘、权限由平台管理的
- 前提：有读取所有共享目录 ACL 的账号

## 工具选型

| 方案                       | 特点                     | 适用        |
| -------------------------- | ------------------------ | ----------- |
| PowerShell Get-Acl         | 零成本                   | ✅ 方案采用 |
| Netwrix Auditor            | 商业，权限审计和变更追踪 | 外企常用    |
| ShareGate / Varonis        | 数据访问治理             | 大型企业    |
| AccessEnum（Sysinternals） | 微软免费工具             | 临时检查    |

PowerShell 足以导出 ACL；规则判断和报告用脚本实现，按部门分发确认。

## 怎么做

- PowerShell 遍历共享根目录下 3 层文件夹，用 Get-Acl 导出每个目录的授权（用户/组、权限、是否继承）
- 对照 AD：标出已禁用账号、Everyone/Authenticated Users 有写权限、直接授权给个人（应该授权给组）
- 按部门输出 Excel，每季度发给部门负责人确认，确认结果存档作为审计证据
- 只读扫描，不改任何权限

## 实施步骤

| 步骤 | 做什么                              | 怎么验证                              |
| ---- | ----------------------------------- | ------------------------------------- |
| 1    | 确定扫描范围（共享根目录到第 3 层） | 清单得到部门确认                      |

| 5    | 确认结果存档，下季度对比            | 有历次审计记录                        |

## 关键代码

示例代码（简化），没有在生产环境运行：

```powershell
Get-ChildItem $root -Directory -Depth 2 | ForEach-Object {
  $path = $_.FullName
  (Get-Acl $path).Access | Where-Object { -not $_.IsInherited } | ForEach-Object {
    [pscustomobject]@{ Path = $path; Who = $_.IdentityReference; Rights = $_.FileSystemRights }
  }
} | Export-Csv acl.csv -Encoding UTF8 -NoTypeInformation
```

## 常见坑

- **扫描大目录很慢**：逐个文件读取 ACL。只扫描到目录层级，跳过继承权限。
- **SID 无法解析**：账号已删除，只剩 SID。把无法解析的 SID 单独列出，通常可以直接清理。
- **扫描时修改了权限**：用了 Set-Acl 或工具误操作。脚本只读，评审时确认没有写操作。

## 面试怎么讲

30 秒讲法（方案思路；没有实际落地，面试时如实说明是设计过的方案）：

> 我会用 PowerShell 遍历共享根目录下 3 层文件夹，用 Get-Acl 导出所有非继承的授权，再对照 AD 标出风险：已禁用账号仍有权限、Everyone 可写、直接授权给个人而不是组。按部门生成 Excel，每季度发给部门负责人确认，确认结果存档作为审计证据。整个过程只读，不改任何权限。

常见追问：

**问：为什么权限要授给组而不是个人？**

答：人员变动时只需调整组成员，不用逐个目录改权限；也便于审计。

**问：AGDLP 原则是什么？**

答：账号放进全局组，全局组放进域本地组，域本地组授予权限，是 AD 授权的推荐方式。

**问：共享权限和 NTFS 权限的关系？**

答：两者都生效，取最严格的；常见做法是共享权限给 Everyone 完全控制，用 NTFS 权限精细控制。

**被问到「能不能用 AI」时：** AI 可以给权限精简建议，但修改必须人确认。
