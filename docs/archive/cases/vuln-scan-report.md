## 问题

等保测评前临时抱佛脚：几十台服务器一台台检查补丁、SSH、密码策略，整改完下次又忘了。

## 适用场景

- 适合：服务器较多、有等保测评或安全审计的公司
- 不值得：全部是不可变容器、按镜像扫描的环境
- 前提：控制机能 SSH 到所有服务器（Ansible）

## 工具选型

| 方案                      | 特点                        | 适用           |
| ------------------------- | --------------------------- | -------------- |
| Lynis                     | 开源 Linux 基线检查         | 国内外都用     |
| OpenSCAP + CIS 基线       | 标准化合规检查              | 外企、合规要求 |
| Nessus / 绿盟、启明扫描器 | 网络漏洞扫描                | 商业           |
| Wazuh                     | 开源 SIEM，含基线和漏洞检测 | 开源           |

Lynis 单个脚本、只读，配合 Ansible 批量运行；需要标准化合规报告时用 OpenSCAP 的 CIS 基线。

## 怎么做

- 用 Ansible 在所有服务器上运行 Lynis（或 OpenSCAP 的 CIS 基线），只读检查，结果拉回控制机
- Python 汇总：每台机器的得分、高危项（如允许 root 密码登录、缺少安全补丁、开放了不必要的端口）
- 生成 Excel 整改清单，按高 → 中 → 低排序，附修复命令；下个月自动复查是否已整改
- 和实验 01 的 SSH 加固、实验 06 的 baseline role 配合：发现问题后用同一个 role 统一修复

## 实施步骤

| 步骤 | 做什么                            | 怎么验证             |
| ---- | --------------------------------- | -------------------- |
| 1    | Ansible 批量安装或分发 Lynis      | 所有机器可运行       |
| 2    | 只读运行并拉回报告                | 控制机上有每台的报告 |
| 3    | Python 汇总评分和高危项           | 有一份全局 Excel     |
| 4    | 附修复建议，用 baseline role 修复 | 高危项整改完成       |
| 5    | 下月复查对比                      | 整改项不再出现       |

## 关键代码

示例代码（简化），没有在生产环境运行：

```yaml
- name: 运行 Lynis 基线检查（只读）
  ansible.builtin.command: lynis audit system --quick --no-colors --report-file /tmp/lynis.dat
  changed_when: false
- name: 拉回报告
  ansible.builtin.fetch:
    { src: /tmp/lynis.dat, dest: 'reports/{{ inventory_hostname }}.dat', flat: true }
```

## 常见坑

- **报告项太多无从下手**：几百条建议。按风险分级，先处理高危和对外暴露的。
- **修复导致业务中断**：直接按建议改配置（如关闭端口）。先在测试机验证，用 Ansible 分批修复。
- **扫描本身影响性能**：高峰期运行。安排在低峰期。

## AI 视角

**✨ AI 能增强**

- **AI 能做什么**：把技术报告改写成整改清单，按业务影响排序
- **不该交给 AI**：扫描结果必须来自工具
- **怎么落地**：报告附 AI 生成的整改优先级说明

## 面试怎么讲

30 秒讲法（方案思路；没有实际落地，面试时如实说明是设计过的方案）：

> 我会用 Ansible 在所有服务器上只读运行 Lynis，把报告拉回控制机，用 Python 汇总每台的得分和高危项，比如允许 root 密码登录、缺少安全补丁、开放了不必要的端口，生成按风险排序的整改清单，附修复命令；修复用和实验 06 一样的 baseline role，下个月自动复查。

常见追问：

**问：等保 2.0 对主机安全有哪些常见要求？**

答：身份鉴别（密码复杂度、登录失败处理）、访问控制、安全审计、入侵防范（最小安装、补丁）、恶意代码防范。

**问：漏洞扫描和基线检查的区别？**

答：漏洞扫描找已知漏洞（CVE）；基线检查看配置是否符合安全标准。

**问：发现高危漏洞怎么处理？**

答：评估是否可被利用（是否对外暴露）、打补丁或升级、无法立即修复时临时缓解（关闭端口、WAF 规则）。

**被问到「能不能用 AI」时：** AI 帮我把几百条扫描结果按业务影响排出整改优先级。
