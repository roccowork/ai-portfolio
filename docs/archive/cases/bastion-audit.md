## 问题

多人共用 root 密码登录服务器，出了事故查不到是谁做的；离职员工手里还有密码；等保要求有操作审计。

## 适用场景

- 适合：服务器多、运维人员多、有等保或审计要求的公司
- 不值得：一两台服务器、一个人维护
- 前提：能限制服务器只接受堡垒机的登录

## 工具选型

| 方案                     | 特点                   | 适用     |
| ------------------------ | ---------------------- | -------- |
| JumpServer               | 国产开源，最常用       | 国内常用 |
| Teleport                 | 开源，证书认证，云原生 | 外企常用 |
| 云厂商堡垒机             | 托管                   | 云上     |
| SSH + 审计日志（auditd） | 零成本，但无录像       | 最简单   |

JumpServer 国内资料多、支持 LDAP 和录像；外企或云原生环境 Teleport 更现代（短期证书，不存密码）。

## 怎么做

- 服务器只允许堡垒机的 IP 登录，员工用公司账号（LDAP）+ 两步验证登录堡垒机，不再知道服务器密码
- 按人、按机器组授权，临时权限设置过期时间
- 会话全程录像，命令单独记录可搜索；`rm -rf /`、`drop database`、`shutdown` 等高危命令实时发告警，可配置为需要审批
- 和入职离职自动化联动：账号禁用后堡垒机权限立即失效

## 实施步骤

| 步骤 | 做什么                               | 怎么验证                   |
| ---- | ------------------------------------ | -------------------------- |
| 1    | 部署堡垒机，对接 LDAP 和两步验证     | 员工能用公司账号登录       |
| 2    | 服务器只允许堡垒机 IP 登录           | 直接 SSH 被拒绝            |
| 3    | 按人、按机器组授权                   | 员工只看到自己有权限的机器 |
| 4    | 开启录像和命令记录，配置高危命令规则 | 执行 rm -rf 时收到告警     |
| 5    | 和账号生命周期联动                   | 离职禁用后无法登录堡垒机   |

## 关键代码

示例代码（简化），没有在生产环境运行：

```yaml
# 高危命令规则（示意，各产品配置方式不同）
command_filters:
  - name: high-risk
    action: alert_and_confirm
    patterns: ['rm\s+-rf\s+/', '(?i)drop\s+(database|table)', 'mkfs', 'shutdown|reboot']
```

## 效果指标

| 指标       | 做之前              | 预期效果（估算） |
| ---------- | ------------------- | ---------------- |
| 操作可追溯 | 共用 root，查不到人 | 每条命令对应到人 |
| 离职收权限 | 改所有服务器密码    | 禁用一个账号     |
| 等保审计   | 缺材料              | 录像和日志齐全   |

操作可追溯到人，满足等保的审计要求，离职收权限不再遗漏。

## 常见坑

- **堡垒机成为单点**：堡垒机挂了无法运维。高可用部署，保留受控的应急通道。
- **员工绕过堡垒机**：服务器还开放了其他登录方式。安全组只放行堡垒机 IP，定期检查。
- **录像占用大量存储**：长时间会话。设置保留期，归档到对象存储。

## AI 视角

**🤖 AI 是核心**

- **AI 能做什么**：分析操作录像和命令记录，识别异常行为（深夜批量导出数据）
- **不该交给 AI**：是否违规的判定和处置需要人
- **怎么落地**：AI 对会话记录做行为分析，可疑会话推给安全人员

## 面试怎么讲

30 秒讲法（方案思路；没有实际落地，面试时如实说明是设计过的方案）：

> 我会部署 JumpServer 这类堡垒机，员工用公司账号加两步验证登录，服务器只允许堡垒机的 IP 连接，员工不再知道服务器密码。按人按机器组授权，会话全程录像，高危命令实时告警；和入离职流程联动，账号禁用后权限立即失效。满足等保的操作审计要求。

常见追问：

**问：堡垒机的四 A 是什么？**

答：账号（Account）、认证（Authentication）、授权（Authorization）、审计（Audit）。

**问：Teleport 和传统堡垒机的区别？**

答：Teleport 用短期证书代替长期密码和密钥，过期自动失效，减少凭据泄露风险。

**问：如何防止绕过堡垒机？**

答：服务器防火墙只放行堡垒机 IP，关闭其他登录方式，定期扫描检查。

**被问到「能不能用 AI」时：** 堡垒机记录量巨大，人看不过来，AI 适合做异常行为识别。
