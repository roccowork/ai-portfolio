## 问题

开发人员各自用不同的 AI 工具，有的用个人账号把公司代码贴进网页版聊天；有人用得很好，有人觉得「AI 写的都不能用」；老板问「买 AI 工具到底提效多少」，没人答得上来。

## 适用场景

- 适合：10 人以上的研发团队，准备或已经在用 AI 编程工具
- 不值得：代码绝对不能出内网、又没有私有部署模型条件的
- 前提：管理层愿意为工具付费；有代码托管平台（GitHub、GitLab）

## 工具选型

| 方案                                   | 特点                                 | 适用       |
| -------------------------------------- | ------------------------------------ | ---------- |
| GitHub Copilot Business / Enterprise   | 和 GitHub 深度集成，管理后台完善     | 外企常用   |
| Claude Code                            | 命令行 Agent，能跨文件改代码、跑测试 | 外企常用   |
| Cursor                                 | AI 原生编辑器                        | 国内外都有 |
| 通义灵码、文心快码、腾讯云 AI 代码助手 | 国产，支持私有化部署                 | 国内常用   |

不追求只用一个：补全类和 Agent 类可以并存。关键是企业版（代码不用于训练、有管理后台）和统一的项目规范。

## 怎么做

- **试点**：选 2～3 个工具，在 2 个小组试用 4 周，记录完成需求的时间、PR 数量、开发者满意度
- **统一采购和登录**：买企业版，用公司 SSO 登录，离职自动回收；禁止用个人账号处理公司代码
- **安全管控**：合同确认代码不用于训练；管理后台排除含密钥、客户数据的仓库；提交前仍有密钥扫描
- **项目规范文件**：每个仓库写一份 `CLAUDE.md` / `AGENTS.md` / `.github/copilot-instructions.md`：技术栈、目录结构、怎么跑测试、代码规范、禁止事项。AI 每次都会读，输出质量明显提高
- **规则不变**：AI 写的代码和人写的一样走 PR、CI、代码审查，作者对代码负责
- **培训和统计**：内部分享好用的用法；从管理后台拉取活跃人数、建议采纳率，结合 PR 周期时间看提效

## 实施步骤

| 步骤 | 做什么                             | 怎么验证                  |
| ---- | ---------------------------------- | ------------------------- |
| 1    | 试点 2～3 个工具，记录试点前后数据 | 有一份对比报告            |
| 2    | 采购企业版，接入 SSO               | 只能用公司账号登录        |
| 3    | 确认数据条款，排除敏感仓库         | 法务、安全确认            |
| 4    | 主要仓库添加规范文件               | AI 生成的代码符合项目规范 |
| 5    | 培训，建立内部经验分享             | 活跃使用率                |
| 6    | 每月出使用和效能报告               | 管理层能看到投入产出      |

## 关键代码

示例（简化）。仓库根目录的 `CLAUDE.md`，AI 每次开始工作前都会读：

```markdown
# 项目说明

- Go 1.24 + PostgreSQL 16，入口 cmd/server/main.go
- 跑测试：make test（必须全部通过才能提交）
- 数据库变更只能新增 migrations/ 下的文件，不能改已有的
- 日志用 slog，禁止 fmt.Println
- 不要修改 deploy/ 和 .github/ 下的文件
```

## 效果指标

| 指标                     | 做之前   | 预期效果（估算）          |
| ------------------------ | -------- | ------------------------- |
| 用个人账号处理公司代码   | 无法管控 | 只能用企业版              |
| 提效有没有数据           | 说不清   | 每月报告：使用率、PR 周期 |
| 重复性编码（样板、测试） | 手写     | 大部分由 AI 起草          |

提效幅度因团队而异，以试点数据为准；更重要的是把「各用各的」变成「安全、可管理、可衡量」。

## 常见坑

- **只买不管**：发了账号就结束，用的人很少。要有培训、规范文件和内部分享。
- **以为 AI 写的不用审查**：AI 写的代码出了问题。规则不变，作者负责，照常审查和测试。
- **用代码行数衡量提效**：AI 让代码变多不等于变好。看需求交付周期、PR 周期、缺陷率。
- **规范文件写成长篇**：AI 抓不住重点。只写 AI 容易做错的事，简短具体。

## AI 视角

**🤖 AI 是核心**

- **AI 能做什么**：补全代码、按描述写函数和测试、跨文件重构、解释陌生代码、排查报错
- **不该交给 AI**：架构决策、最终的代码审查批准、涉及安全和权限的代码不经人审就合并
- **怎么落地**：企业版 + SSO + 规范文件 + 原有的 PR 流程，AI 是加速器，不是绕过流程的捷径

## 面试怎么讲

30 秒讲法（方案思路；没有实际落地，面试时如实说明是设计过的方案）：

> 我会先选两三个 AI 编程工具在小组试点四周，记录交付时间和满意度；然后采购企业版接 SSO，确认代码不用于训练，排除敏感仓库；每个仓库写一份 CLAUDE.md 这类规范文件，告诉 AI 技术栈、怎么跑测试、哪些不能改；AI 写的代码照常走 PR 和 CI。每月从管理后台拉使用数据，结合 PR 周期时间给管理层出报告。

常见追问：

**问：怎么衡量 AI 编程助手的效果？**

答：看需求交付周期、PR 从打开到合并的时间、缺陷率和开发者满意度；不看代码行数。

**问：代码安全怎么保证？**

答：用企业版（合同约定不训练）、SSO 登录、排除敏感仓库、提交前扫描密钥；要求极高的用私有部署模型。

**问：规范文件为什么重要？**

答：AI 不了解项目的约定，规范文件让它每次都按项目的方式写代码，减少返工。

**被问到「能不能用 AI」时：** 这个案例就是让团队用好 AI；我自己的仓库也都有 CLAUDE.md。
