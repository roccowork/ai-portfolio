## 问题

财务每月手工录入几百张发票：抄金额、抄发票号、查有没有重复报销，费时又容易错。

## 适用场景

- 适合：发票量大（每月几百张以上）的财务部门
- 不值得：每月几十张发票的
- 前提：以电子发票为主（PDF/OFD），纸质发票需要 OCR

## 工具选型

| 方案                                 | 特点                       | 适用        |
| ------------------------------------ | -------------------------- | ----------- |
| pdfplumber + 正则                    | 电子发票直接读文本，零成本 | ✅ 方案采用 |
| 云 OCR（百度、腾讯、阿里票据识别）   | 识别纸质发票，按次收费     | 国内常用    |
| 费控系统（汇联易、每刻、SAP Concur） | 报销全流程                 | 国内 / 外企 |
| 税务平台查验                         | 验证发票真伪               | 必须        |

全电发票时代大部分是电子发票，直接读 PDF 文本就够；纸质发票再接云 OCR。

## 怎么做

- 员工把发票发到 invoice@ 邮箱，脚本用 IMAP 定时拉取附件，文件名按发件人和日期重命名归档
- 电子发票 PDF 直接提取文本（pdfplumber），用正则取发票号码、开票日期、价税合计、销售方名称；纸质发票照片走 OCR
- 发票号码查重，已报销过的直接标红；金额、日期异常的转人工
- 按人汇总成报销 Excel，附件路径写进表格，财务只需抽查

## 实施步骤

| 步骤 | 做什么                       | 怎么验证               |
| ---- | ---------------------------- | ---------------------- |
| 1    | 建发票收集邮箱，定时拉取附件 | 附件按人归档           |

| 3    | 纸质发票走 OCR               | 照片能识别出字段       |
| 4    | 查重和异常检查               | 重复报销被标红         |

## 常见坑

- **不同地区发票版式不同**：正则匹配失败。用多个样本测试，匹配失败的转人工。
- **OFD 格式读不了**：全电发票可能是 OFD。用支持 OFD 的库或转换工具。
- **发票真伪**：识别不等于验真。对接税务平台查验接口。

## AI 视角

**🤖 AI 是核心**

- **AI 能做什么**：识别各种版式的发票和收据，提取字段
- **不该交给 AI**：金额、税号必须校验，发票真伪要查验
- **怎么落地**：多模态模型识别，规则校验，税务平台验真

常见追问：

**问：电子发票为什么不需要 OCR？**

答：PDF 里本身就有文本层，直接提取比 OCR 准确得多。

**问：怎么防止重复报销？**

答：以发票号码（全电发票是 20 位号码）作为唯一键，登记已报销的发票。

**问：识别出来的发票就是真的吗？**

答：不一定，还要通过税务平台的查验接口验证真伪。

**被问到「能不能用 AI」时：** 多模态模型能识别各种版式的票据，但金额要校验、真伪要查验。
