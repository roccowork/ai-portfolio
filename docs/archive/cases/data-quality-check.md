## 问题

上游系统改了字段、跑批漏了一天的数据，报表照样发出去，老板看到的销售额少了一半，开会才发现数据错了。

## 适用场景

- 适合：有数据仓库、定期给管理层出报表的公司
- 不值得：数据量小、只有几张表的
- 前提：有跑批流程，能在其后插入检查步骤

## 工具选型

| 方案               | 特点             | 适用             |
| ------------------ | ---------------- | ---------------- |
| dbt tests          | 和 SQL 建模一体  | 外企数据团队常用 |
| Great Expectations | Python，规则丰富 | 国内外都用       |
| Soda               | 声明式质量检查   | 开源             |
| 自写 SQL 检查      | 零依赖           | 简单场景         |

用 dbt 建模的直接用 dbt tests；没有 dbt 的用 Great Expectations 或自写 SQL。

## 怎么做

- 为关键表写质量规则：主键唯一、关键字段不为空、金额在合理范围、今天的行数和最近 7 天平均相比波动不超过 30%
- 规则在跑批后自动执行，用 dbt tests 或 Great Expectations 实现
- 严重规则失败时阻止报表发布，发「数据延迟」通知，而不是发错误的报表
- 每条规则有负责人，失败时通知到人

## 实施步骤

| 步骤 | 做什么                 | 怎么验证                     |
| ---- | ---------------------- | ---------------------------- |
| 1    | 挑出关键表和关键字段   | 清单得到业务确认             |
| 2    | 编写质量规则           | 规则在测试数据上验证         |
| 3    | 接入跑批流程           | 跑批后自动执行               |
| 4    | 严重失败阻止发布并告警 | 故意制造缺失数据时报表不发布 |
| 5    | 每周复盘失败记录       | 规则持续完善                 |

## 关键代码

示例代码（简化），没有在生产环境运行：

```yaml
# dbt：订单表的质量规则
models:
  - name: fct_orders
    columns:
      - name: order_id
        tests: [unique, not_null]
      - name: amount
        tests:
          - dbt_utils.accepted_range: { min_value: 0, max_value: 1000000 }
```

## 效果指标

| 指标             | 做之前   | 预期效果（估算） |
| ---------------- | -------- | ---------------- |
| 错误数据流到报表 | 偶尔发生 | 发布前拦截       |
| 数据问题发现     | 开会时   | 跑批后几分钟     |
| 数据可信度       | 被质疑   | 有规则保障       |

错误数据在报表发布前被拦住，数据的可信度提高。

## 常见坑

- **规则太严格频繁误报**：正常的业务波动（节假日）也触发。波动规则考虑周期性，节假日单独处理。
- **只检查格式不检查业务逻辑**：规则都是非空、唯一。加入业务规则，如订单金额等于明细之和。
- **失败后没人处理**：没有负责人。每条规则指定负责人。

## AI 视角

**✨ AI 能增强**

- **AI 能做什么**：根据历史数据自动建议质量规则
- **不该交给 AI**：规则本身要确定可测
- **怎么落地**：AI 建议规则，人审核后加入

## 面试怎么讲

30 秒讲法（方案思路；没有实际落地，面试时如实说明是设计过的方案）：

> 我会给关键表写数据质量规则：主键唯一、关键字段不为空、金额在合理范围、今天的行数和最近 7 天平均相比波动不超过 30%，在跑批后自动执行；严重规则失败时阻止报表发布，发「数据延迟」通知并通知规则负责人。宁可晚发也不发错的数。

常见追问：

**问：数据质量有哪些维度？**

答：完整性、唯一性、准确性、一致性、及时性、有效性。

**问：为什么要检查行数波动？**

答：上游漏数据、重复跑批时，格式规则都能通过，只有行数异常能发现。

**问：数据问题谁负责？**

答：每张关键表有数据负责人，质量规则失败时通知到他。

**被问到「能不能用 AI」时：** AI 可以根据数据分布建议质量规则，规则确定后仍是确定性检查。
