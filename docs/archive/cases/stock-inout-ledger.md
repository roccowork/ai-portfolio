## 问题

仓库用纸质单据记录出入库，月底再录入系统，库存数永远不准；发错货、少发货要等客户投诉才知道。

## 适用场景

- 适合：有仓库、物料种类多的贸易、电商、制造企业
- 不值得：库存很少、品种单一的
- 前提：愿意给物料和库位贴码

## 工具选型

| 方案                   | 特点         | 适用       |
| ---------------------- | ------------ | ---------- |
| WMS（如富勒、旺店通）  | 仓储管理系统 | 国内常用   |
| ERP 仓储模块 + PDA     | 和财务一体   | 中大型企业 |
| 进销存 SaaS + 手机扫码 | 轻量         | 中小企业   |
| 纸质单据               | 现状         | 不准确     |

中小企业用进销存 SaaS + 手机扫码就能实现；规模大了上 WMS。

## 怎么做

- 所有物料贴条码，库位贴库位码
- 收货时扫描采购单和物料码，数量和采购单不一致的当场提示
- 拣货时按出库单扫码，扫错物料或数量不对的立即提示，防止发错货
- 每次扫码实时更新库存，系统库存就是实际库存；定期循环盘点抽查

## 实施步骤

| 步骤 | 做什么             | 怎么验证           |
| ---- | ------------------ | ------------------ |
| 1    | 物料编码和贴码     | 每种物料有唯一条码 |
| 2    | 库位规划和贴码     | 每个库位有码       |
| 3    | 收货扫码对照采购单 | 数量不符时提示     |
| 4    | 拣货扫码对照出库单 | 扫错时提示         |
| 5    | 循环盘点           | 账实相符率提高     |

## 关键代码

示例代码（简化），没有在生产环境运行：

```python
def scan_pick(order, barcode, qty):
    line = order.line_for(barcode)
    if line is None:
        return beep("这个物料不在出库单上")
    if line.picked + qty > line.qty:
        return beep(f"超出出库数量：需要 {line.qty}，已拣 {line.picked}")
    line.picked += qty
    stock.move(barcode, from_loc=line.location, to_loc="待发区", qty=qty)
```

| 指标       | 做之前         | 预期效果（估算） |
| ---------- | -------------- | ---------------- |
| 库存准确率 | 月底才对账     | 实时             |
| 发错货     | 客户投诉才知道 | 出库前拦截       |
| 盘点       | 月底大盘点     | 循环抽盘         |

库存实时准确，发错货在出库前就被拦住。

## 常见坑

- **员工嫌麻烦不扫码**：流程增加了动作。扫码设备好用、流程简单，系统库存作为考核依据。
- **条码损坏无法识别**：标签质量差。用耐用标签，提供手工输入并记录。
- **一物多码或一码多物**：编码不规范。统一物料编码规则。

## 面试怎么讲

30 秒讲法（方案思路；没有实际落地，面试时如实说明是设计过的方案）：

> 我会给物料和库位贴码，仓库收货时扫码对照采购单，数量不一致当场提示；拣货时按出库单扫码，扫错物料或数量超出立即提示，防止发错货；每次扫码实时更新库存，再配合循环盘点抽查，系统库存就是实际库存。

常见追问：

**问：什么是循环盘点？**

答：不停产，每天抽查一部分库位，一段时间覆盖全部，代替年终大盘点。

**问：先进先出怎么实现？**

答：按批次和入库时间管理，拣货时系统推荐最早的批次。

**问：WMS 和 ERP 的区别？**

答：ERP 管库存数量和金额，WMS 管仓库里的具体作业（库位、上架、拣货、波次）。

**被问到「能不能用 AI」时：** 出入库记账必须确定。
