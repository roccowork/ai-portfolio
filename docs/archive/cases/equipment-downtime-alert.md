## 问题

设备停了要等巡线的人发现，一停就是半小时；停机原因靠口头报告，月底算设备效率时数据不全。

## 适用场景

- 适合：有自动化设备和生产线的工厂
- 不值得：纯手工作业、没有可采集设备的
- 前提：设备有通信接口（PLC 支持 OPC UA/Modbus），和 OT 部门协调好网络

## 工具选型

| 方案                                     | 特点           | 适用        |
| ---------------------------------------- | -------------- | ----------- |
| 工业 IoT 平台（如树根互联、ThingWorx）   | 完整方案       | 国内外都有  |
| Node-RED / Telegraf + InfluxDB + Grafana | 开源组合       | ✅ 方案采用 |
| MES 系统设备模块                         | 和生产管理一体 | 中大型工厂  |
| SCADA                                    | 现场监控       | 工控        |

开源组合成本低、和 IT 监控技术栈相通；规模大或需要和 MES 深度集成时用专业平台。

## 怎么做

- 通过工业网关用 OPC UA 或 Modbus 读取设备的运行状态、产量计数、故障码，写入时序数据库
- 运行状态变为停机并持续 5 分钟、或者产量节拍明显变慢时，通知班组长和设备维护
- 恢复后班组长在手机上选择停机原因（缺料、故障、换型、计划停机）
- 按设备、班次统计停机时间和原因，计算设备综合效率（OEE）

## 实施步骤

| 步骤 | 做什么                      | 怎么验证           |
| ---- | --------------------------- | ------------------ |
| 1    | 和设备、OT 人员确认采集点位 | 有点位表           |
| 2    | 部署工业网关并隔离网络      | IT 和 OT 网络分区  |
| 3    | 采集写入时序数据库          | Grafana 能看到状态 |
| 4    | 配置停机告警                | 模拟停机时收到告警 |
| 5    | 停机原因登记和 OEE 统计     | 有月度报表         |

## 效果指标

| 指标         | 做之前                   | 预期效果（估算） |
| ------------ | ------------------------ | ---------------- |
| 停机发现     | 巡线发现，半小时（估算） | 5 分钟内         |
| 停机原因记录 | 口头，不完整             | 每次登记         |
| 设备效率     | 算不清                   | OEE 可量化       |

停机几分钟内有人处理，停机原因有数据，设备效率可量化。

## 常见坑

- **采集影响 PLC 运行**：轮询太频繁。合理的采集间隔，只读不写。
- **IT 网络和生产网络打通带来安全风险**：直接互联。网络分区、单向数据流、网关隔离。
- **计划停机被当成故障**：没区分。排班和换型计划接入，计划停机不告警。

## AI 视角

**✨ AI 能增强**

- **AI 能做什么**：根据设备数据预测故障（预测性维护）
- **不该交给 AI**：停机告警必须确定
- **怎么落地**：积累数据后训练预测模型，先做告警再做预测

## 面试怎么讲

30 秒讲法（方案思路；没有实际落地，面试时如实说明是设计过的方案）：

> 我会通过工业网关用 OPC UA 或 Modbus 只读采集设备的运行状态、产量计数和故障码，写入 InfluxDB 或 Prometheus；停机持续 5 分钟或节拍明显变慢就通知班组长和设备维护，恢复后在手机上登记停机原因；按设备和班次统计停机时间、计算 OEE。生产网络和办公网络分区隔离。

常见追问：

**问：OEE 是什么？**

答：设备综合效率 = 可用率 × 性能率 × 良品率，衡量设备真正有效生产的时间比例。

**问：OPC UA 和 Modbus 的区别？**

答：Modbus 简单老牌，只有寄存器地址；OPC UA 是现代标准，有数据模型、安全认证，适合跨厂商集成。

**问：IT 和 OT 网络为什么要隔离？**

答：生产网络安全事故会直接导致停产，需要分区、最小访问、单向数据流。

**被问到「能不能用 AI」时：** 先把停机告警做准，数据积累后再用 AI 做预测性维护。
