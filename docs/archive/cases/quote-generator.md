## 问题

销售用旧报价单改，价格用错、算错合计，折扣随意给；报价单格式五花八门，事后也查不到给客户报过什么价。

## 适用场景

- 适合：产品和价格规则较多、销售人数多的 B2B 公司
- 不值得：产品很少、价格固定的
- 前提：价格表能集中维护

## 工具选型

| 方案                                     | 特点       | 适用        |
| ---------------------------------------- | ---------- | ----------- |
| CRM 自带报价（Salesforce CPQ、纷享销客） | 和商机一体 | 国内外都有  |
| Python + Word 模板                       | 灵活       | ✅ 方案采用 |
| Excel 模板 + 公式                        | 零成本     | 小团队      |
| 低代码平台                               | 拖拽表单   | 国内常用    |

CRM 有报价模块的直接用；没有的用模板生成，重点是价格表集中和折扣审批。

## 怎么做

- 价格表集中维护（产品、单价、阶梯价、最低折扣），销售不能改
- 销售在表单里选产品和数量，系统自动计算小计、税额、合计
- 折扣超出销售权限时自动发起审批，审批通过才能生成
- 用 Word 模板生成 PDF 报价单，自动编号，记录到 CRM 的客户下面

## 实施步骤

| 步骤 | 做什么               | 怎么验证             |
| ---- | -------------------- | -------------------- |
| 1    | 整理价格表和折扣权限 | 财务和销售负责人确认 |
| 2    | 设计报价单 Word 模板 | 格式统一             |
| 3    | 实现计算和审批规则   | 超权限折扣触发审批   |
| 4    | 生成 PDF 并编号      | 每份唯一编号         |
| 5    | 记录到 CRM           | 客户下能看到历史报价 |

## 关键代码

示例代码（简化），没有在生产环境运行：

```python
for line in quote.lines:
    p = prices[line.sku]
    line.unit = p.tier_price(line.qty)
    line.amount = round(line.unit * line.qty * (1 - line.discount), 2)
quote.total = sum(l.amount for l in quote.lines)
if max(l.discount for l in quote.lines) > rep.max_discount:
    start_approval(quote)
```

## 常见坑

- **价格表更新不及时**：改价后没同步。价格表设生效日期，由专人维护。
- **含税不含税混乱**：计算口径不一致。模板里明确写含税价和税率。
- **报价被随意修改后发出**：PDF 可编辑。生成后不可编辑，修改需重新生成。

## AI 视角

**✨ AI 能增强**

- **AI 能做什么**：根据客户需求描述推荐产品组合
- **不该交给 AI**：价格和折扣计算必须确定，不能让 AI 算价格
- **怎么落地**：AI 推荐产品，价格由价格表计算

常见追问：

**问：什么是 CPQ？**

答：Configure-Price-Quote，配置、定价、报价一体的销售工具。

**问：折扣审批为什么重要？**

答：随意折扣直接影响利润，审批让折扣有依据、可追溯。

**问：报价单为什么要编号？**

答：便于追溯和对账，客户下单时能对应到具体报价。

**被问到「能不能用 AI」时：** 价格必须由规则计算，AI 只推荐产品组合。
