## 问题

SaaS 厂商只保证服务可用，不保证你的数据不被误删：回收站一般 30 天后清空，员工离职删号后数据也没了。

## 适用场景

- 适合：使用 Microsoft 365、Google Workspace 或企业邮箱的公司，有合规保留要求
- 不值得：已经购买了厂商的备份服务
- 前提：租户管理员授权应用访问

## 工具选型

| 方案                           | 特点               | 适用        |
| ------------------------------ | ------------------ | ----------- |
| 自写 Graph API 脚本            | 灵活，成本低       | ✅ 方案采用 |
| Veeam Backup for Microsoft 365 | 专业产品           | 外企常用    |
| Microsoft 365 Backup（官方）   | 微软自己的备份服务 | 新          |
| 厂商归档（诉讼保留）           | 合规保留，不是备份 | 法律合规    |

自写脚本：小公司成本低，直接备份到自己的存储；数据量大或有合规要求再上专业产品。

## 怎么做

- 用应用身份调 Microsoft Graph API，按用户增量拉取邮件和 OneDrive 文件（delta 接口，只拉变化的部分）
- 存到 NAS，再用 restic 加密备份到异地，保留 1 年
- 员工离职时先导出归档再删账号，归档单独长期保存
- 国内企业换成企业微信 / 飞书 / 钉钉的开放接口，思路相同

## 实施步骤

| 步骤 | 做什么                                 | 怎么验证                     |
| ---- | -------------------------------------- | ---------------------------- |
| 1    | Azure 注册应用，授予只读邮件和文件权限 | 管理员同意后能获取令牌       |
| 2    | 按用户 delta 增量拉取邮件和 OneDrive   | 第二次运行只拉取变化         |
| 3    | 存到 NAS，restic 加密异地              | 异地有快照                   |
| 4    | 离职流程增加导出归档                   | 离职账号删除前有归档         |
| 5    | 季度恢复演练                           | 能恢复指定用户指定日期的邮件 |

```python
url = f"https://graph.microsoft.com/v1.0/users/{user}/mailFolders/inbox/messages/delta"
while url:
    r = session.get(url, headers={"Authorization": f"Bearer {token}"}).json()
    for m in r.get("value", []):
        save_message(user, m)
    url = r.get("@odata.nextLink")
    delta_link = r.get("@odata.deltaLink", delta_link)
```

| 指标         | 做之前                 | 预期效果（估算） |
| ------------ | ---------------------- | ---------------- |
| 误删邮件找回 | 回收站 30 天后无法找回 | 按日期恢复       |

误删邮件、离职交接都能按日期找回。需要企业租户的管理员授权，只做方案。

## 常见坑

- **API 被限流**：请求太快。遵守 Retry-After，分批、错峰运行。
- **应用权限过大**：授予了读写全部。只申请只读权限，密钥放在密钥管理里。
- **备份中含大量敏感信息**：邮件备份等同于全公司数据。加密存储，严格限制访问。

## AI 视角

**✨ AI 能增强**

- **AI 能做什么**：在备份的邮件里用自然语言检索（「去年和某客户的合同邮件」）
- **不该交给 AI**：备份范围和保留策略按合规要求确定
- **怎么落地**：对备份建立向量索引，提供检索；注意数据权限

常见追问：

**问：SaaS 不是已经有冗余了吗，为什么还要备份？**

答：厂商保证服务可用，不保证你的误删、离职删号、勒索加密的数据能找回；这是共担责任模型。

**问：delta 查询是什么？**

答：只返回上次同步以来变化的数据，适合增量备份，节省时间和 API 配额。

**问：备份数据怎么保护？**

答：加密、异地、最小访问权限、访问审计，备份本身就是高敏感数据。

**被问到「能不能用 AI」时：** 备份数据可以用 AI 检索，比如离职交接时快速找到关键邮件，但要严格控制权限。
