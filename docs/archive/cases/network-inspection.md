## 问题

网络问题常常是慢慢变坏的：网线老化导致错包增长、光模块衰减。等到断网才发现，已经影响业务。

## 适用场景

- 适合：有自有机房或办公网络、交换机几十台以上的公司
- 不值得：全部上云、没有自有网络设备的
- 前提：网络设备开启 SNMP（v2c 或 v3），能从监控服务器访问

## 工具选型

| 方案                       | 特点                   | 适用         |
| -------------------------- | ---------------------- | ------------ |
| Prometheus snmp_exporter   | 和服务器监控统一       | 国内外都常用 |
| Zabbix                     | SNMP 模板丰富          | 国内最常用   |
| LibreNMS                   | 网络监控专用，自动发现 | 开源         |
| 厂商网管（华为 eSight 等） | 功能全                 | 单一品牌     |

选 snmp_exporter：和服务器、K8s 用同一套 Prometheus 和告警通道，网络和系统告警在一个地方。

## 怎么做

- 用 Prometheus 的 snmp_exporter 采集交换机 IF-MIB（接口流量、错包、up/down）和厂商私有 MIB（CPU、内存、光功率）
- 规则：错包 1 小时内持续增长、核心端口 down、光功率低于 -20 dBm、CPU 持续 80% 以上
- Grafana 做每台设备的看板；每天早上把异常项汇总发到企业微信
- 和服务器监控在同一套 Prometheus 里，告警走同一个通道

## 实施步骤

| 步骤 | 做什么                                | 怎么验证               |
| ---- | ------------------------------------- | ---------------------- |
| 1    | 设备开启 SNMP（优先 v3）并限制来源 IP | snmpwalk 能读到数据    |
| 2    | 用 generator 生成 snmp_exporter 配置  | 能采集接口和 CPU       |
| 3    | Prometheus 按设备清单采集             | 看板上有每台设备的数据 |
| 4    | 配置告警：错包增长、端口 down、光功率 | 模拟拔线时告警         |
| 5    | 每日异常汇总推送                      | 群里收到网络日报       |

## 关键代码

示例代码（简化），没有在生产环境运行：

```yaml
- alert: InterfaceErrorsGrowing
  expr: increase(ifInErrors[1h]) > 100
  for: 30m
  annotations:
    summary: '{{ $labels.instance }} 端口 {{ $labels.ifDescr }} 错包持续增长，检查网线或光模块'
```

## 常见坑

- **采集太频繁导致交换机 CPU 升高**：SNMP walk 大量 OID。只采集需要的 OID，间隔 1 分钟以上。
- **接口计数器回绕**：32 位计数器在高速端口很快溢出。使用 64 位计数器（ifHCInOctets）。
- **SNMP v2c 团体字被嗅探**：明文传输。优先用 v3，限制访问来源。

## AI 视角

**✨ AI 能增强**

- **AI 能做什么**：解读设备日志和告警，给出可能原因
- **不该交给 AI**：采集和阈值保持规则

## 面试怎么讲

30 秒讲法（方案思路；没有实际落地，面试时如实说明是设计过的方案）：

> 我会用 Prometheus 的 snmp_exporter 采集交换机的接口流量、错包、端口状态和 CPU，以及光模块的收发光功率。告警规则看趋势：错包 1 小时内持续增长、核心端口 down、光功率低于 -20 dBm；每天早上把异常汇总发到群里。网络告警和服务器告警走同一个通道。

常见追问：

**问：SNMP v2c 和 v3 的区别？**

答：v2c 用明文团体字，没有加密；v3 支持用户认证和加密，更安全。

**问：端口错包增长可能是什么原因？**

答：网线或水晶头质量问题、光模块衰减、双工不匹配、干扰。

**问：为什么要用 64 位计数器？**

答：32 位计数器在千兆以上端口几十秒就会回绕，计算出的流量不准。

**被问到「能不能用 AI」时：** 网络巡检是规则，AI 帮读设备日志给出原因。
