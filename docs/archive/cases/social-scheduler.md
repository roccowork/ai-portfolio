## 问题

运营要卡着时间点手动发内容，周末和节假日也得守着；各平台的阅读数据还要一个个后台去抄。

## 适用场景

- 适合：运营多个新媒体账号、内容需要排期的团队
- 不值得：偶尔发几条内容的
- 前提：平台提供开放接口，有开发者权限

## 工具选型

| 方案                 | 特点           | 适用        |
| -------------------- | -------------- | ----------- |
| 平台开放 API + 脚本  | 可控           | ✅ 方案采用 |
| 新榜、壹伴等运营工具 | 国内新媒体常用 | 国内        |
| Buffer / Hootsuite   | 多平台排期     | 外企常用    |
| 平台自带定时发布     | 最简单         | 单平台      |

平台自带定时发布最简单；多平台统一排期和数据回填时用脚本 + 表格。

## 怎么做

- 内容排期放在多维表格：平台、发布时间、标题、正文、图片、状态
- 每 5 分钟检查一次到点的内容，调用各平台开放接口发布（公众号可先建草稿再发布），成功后把状态改为已发布并记录链接
- 发布失败（审核不通过、接口限流）通知运营
- 第二天自动回填阅读、点赞数据，每周汇总效果

## 实施步骤

| 步骤 | 做什么                      | 怎么验证                           |
| ---- | --------------------------- | ---------------------------------- |
| 1    | 设计排期表                  | 平台、时间、标题、正文、图片、状态 |
| 2    | 申请各平台开发者权限        | 能调用发布接口                     |
| 3    | 每 5 分钟检查到点内容并发布 | 测试内容按时发出                   |
| 4    | 失败通知运营                | 审核不通过时收到通知               |
| 5    | 次日回填阅读数据            | 表格里有阅读数                     |

## 关键代码

示例代码（简化），没有在生产环境运行：

```python
for post in sheet.rows(status="待发布"):
    if post.publish_at > now:
        continue
    try:
        url = platforms[post.platform].publish(post.title, post.body, post.images)
        sheet.update(post.id, status="已发布", url=url)
    except PublishError as e:
        sheet.update(post.id, status="失败")
        notify(f"{post.platform} 发布失败：{post.title}，{e}")
```

运营不用守点发布，数据自动汇总。需要各平台的开发者权限。

## 常见坑

- **接口权限不足**：个人号或未认证账号接口受限。使用认证的企业账号。
- **重复发布**：任务重试。发布后立即更新状态，按 ID 去重。
- **内容审核不通过**：敏感词。发布前做敏感词检查。

## AI 视角

**🤖 AI 是核心**

- **AI 能做什么**：生成文案、配图建议、按平台风格改写同一内容
- **不该交给 AI**：发布审核和敏感内容把关需要人
- **怎么落地**：AI 生成初稿，运营审核后进入排期

## 面试怎么讲

30 秒讲法（方案思路；没有实际落地，面试时如实说明是设计过的方案）：

> 我会把内容排期放在多维表格里，写清平台、发布时间、标题、正文和图片；脚本每 5 分钟检查到点的内容，调用平台开放接口发布，成功后改状态并记录链接，失败通知运营。第二天自动回填阅读、点赞数据，每周汇总效果。

常见追问：

**问：为什么要回填数据？**

答：形成「发布 - 效果」闭环，知道什么内容、什么时间效果好。

**问：如何防止重复发布？**

答：发布后立即更新状态，任务按内容 ID 去重。

**问：多平台发布有什么难点？**

答：各平台接口、格式、审核规则都不同，要分别适配。

**被问到「能不能用 AI」时：** 内容生成是 AI 的强项，但发布前必须人审核。
