## 问题

纸质或聊天里的采购审批：找不到人签字、不知道卡在哪一步、审批完采购不知道、买回来的东西没登记。

## 适用场景

- 适合：审批多、流程跨部门、需要跟踪进度的公司
- 不值得：几个人的小团队，口头确认就够了
- 前提：公司统一使用飞书、钉钉或企业微信

## 工具选型

| 方案                       | 特点               | 适用           |
| -------------------------- | ------------------ | -------------- |
| 飞书 / 钉钉 / 企业微信审批 | 自带表单和条件分支 | 国内最常用     |
| n8n 后续流转               | 审批后的自动化     | ✅ 方案采用    |
| Power Automate             | 微软生态           | 外企常用       |
| 泛微、致远 OA              | 传统 OA            | 国内中大型企业 |

审批用 IM 平台自带的（员工最熟悉），审批后的自动化用 n8n 接 Webhook 实现。

## 怎么做

- 用飞书或钉钉自带的审批表单，按金额设置条件分支：5000 元以下主管审批，以上加财务和总经理
- 审批结束的事件通过 Webhook 推给 n8n：写入采购台账、通知采购员、在群里同步
- 采购员确认到货后，电脑等固定资产自动写入资产表并关联使用人
- 每月汇总各部门采购金额

## 实施步骤

| 步骤 | 做什么                   | 怎么验证                 |
| ---- | ------------------------ | ------------------------ |
| 1    | 设计采购表单和条件分支   | 不同金额走不同审批人     |
| 2    | 配置审批结束 Webhook     | 审批通过后 n8n 收到事件  |
| 3    | 写入采购台账并通知采购员 | 台账多一行，采购收到消息 |
| 4    | 到货确认后写入资产表     | 资产表关联使用人         |
| 5    | 每月汇总采购金额         | 各部门有月度汇总         |

## 常见坑

- **Webhook 丢失导致后续流程没执行**：网络抖动。定时对账：查询审批列表补处理遗漏的。
- **重复处理同一个审批**：Webhook 重试。用审批单号去重。
- **审批人离职导致流程卡住**：审批人写死为个人。审批人用角色或部门负责人。

## AI 视角

**✨ AI 能增强**

- **AI 能做什么**：审批前生成申请摘要和历史采购对比
- **不该交给 AI**：审批路由和决定必须按规则和人
- **怎么落地**：AI 摘要附在审批单

## 面试怎么讲

30 秒讲法（方案思路；没有实际落地，面试时如实说明是设计过的方案）：

> 我会用飞书或钉钉自带的审批表单，按金额设条件分支：5000 元以下主管审批，以上加财务和总经理。审批结束的事件通过 Webhook 推给 n8n，写入采购台账、通知采购员；到货确认后，电脑这类固定资产自动写入资产表并关联使用人。Webhook 处理按审批单号去重，并定时对账防止遗漏。

常见追问：

**问：Webhook 和轮询的区别？**

答：Webhook 是事件发生时对方主动推送，实时；轮询是定时去查，简单但有延迟。可靠的做法是 Webhook + 定时对账。

**问：什么是幂等处理？**

答：同一个事件处理多次结果一样，比如按单号去重，避免重试导致重复下单。

**问：审批流设计要注意什么？**

答：审批人用角色而不是个人、设置超时提醒、条件清晰、记录完整。

**被问到「能不能用 AI」时：** 审批由人和规则决定，AI 给审批人一份摘要和历史对比。
