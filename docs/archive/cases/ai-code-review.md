## 问题

审查者时间有限，PR 常常排队一两天；简单的问题（空指针、漏处理错误、SQL 拼接）占用了审查时间，真正重要的设计问题反而没精力看。

## 适用场景

- 适合：PR 多、审查人手紧张的团队
- 不值得：代码不能离开内网且没有私有模型的
- 前提：有可用的大模型（云端或私有部署），已有 CI

## 工具选型

| 方案                                     | 特点               | 适用         |
| ---------------------------------------- | ------------------ | ------------ |
| Claude Code Review / GitHub Copilot 审查 | 开箱即用           | 外企常用     |
| CodeRabbit                               | 第三方 AI 审查服务 | 国内外都有   |
| 自写 Action + 大模型 API                 | 可控，可接私有模型 | ✅ 方案采用  |
| SonarQube                                | 规则式静态分析     | 国内外都常用 |

规则式静态分析（SonarQube）和 AI 审查互补：规则查确定的问题，AI 看上下文和逻辑。

## 怎么做

- PR 打开或更新时触发 CI，取出 diff 和相关文件上下文，交给大模型按清单审查：潜在缺陷、安全问题、错误处理、可读性
- 结果以行内评论的形式发到 PR，按严重程度分级，只报有把握的问题，避免刷屏
- 代码不能外传的公司用私有部署的模型，或者只发送 diff 不发送完整代码库
- AI 意见只是第一轮，合并仍需要人工批准

## 实施步骤

| 步骤 | 做什么                     | 怎么验证             |
| ---- | -------------------------- | -------------------- |
| 1    | 确定审查清单和输出格式     | 清单评审通过         |
| 2    | CI 获取 diff 和上下文      | 能看到完整 diff      |
| 3    | 调用模型并解析结果         | 输出结构化的问题列表 |
| 4    | 发行内评论，按严重程度过滤 | PR 上出现评论        |
| 5    | 收集误报反馈，调整提示词   | 误报率逐步下降       |

## 关键代码

示例代码（简化），没有在生产环境运行：

```yaml
on: { pull_request: { types: [opened, synchronize] } }
jobs:
  review:
    runs-on: ubuntu-latest
    permissions: { contents: read, pull-requests: write }
    steps:
      - uses: actions/checkout@v7
        with: { fetch-depth: 0 }
      - run: git diff origin/${{ github.base_ref }}...HEAD > pr.diff
      - run: python review.py pr.diff # 调用模型，把结果写成 PR 行内评论
```

| 指标                 | 做之前                 | 预期效果（估算） |

## 常见坑

- **评论太多没人看**：把风格建议也当成问题。只报中高严重度、有把握的问题。
- **代码泄露风险**：把私有代码发给外部服务。只发送 diff、使用企业协议或私有部署模型。
- **大 PR 超出上下文**：diff 太长。按文件分批审查，或要求拆小 PR。

## AI 视角

**🤖 AI 是核心**

- **AI 能做什么**：读 diff 找缺陷、安全问题，给出修改建议
- **不该交给 AI**：合并的批准必须由人做
- **怎么落地**：见正文：CI 调用模型发行内评论

## 面试怎么讲

30 秒讲法（方案思路；没有实际落地，面试时如实说明是设计过的方案）：

> 我会在 PR 打开和更新时触发一个 CI 任务，取出 diff 和相关文件交给大模型，按清单审查潜在缺陷、安全问题和错误处理，结果以行内评论发到 PR，只报中高严重度、有把握的问题。AI 只做第一轮，合并仍需要人工批准；代码敏感的公司用私有部署模型或只发送 diff。

常见追问：

**问：AI 审查能代替人工吗？**

答：不能。它擅长发现局部缺陷，不了解业务背景和整体设计；最终责任在人。

**问：怎么降低误报？**

答：明确清单、要求给出证据（具体行和触发条件）、只报高置信问题、收集反馈迭代提示词。

**问：静态分析和 AI 审查怎么配合？**

答：静态分析覆盖确定性规则，零误报优先；AI 补充需要理解上下文的问题。

**被问到「能不能用 AI」时：** 这个案例本身就是 AI，关键是只报有把握的问题、最终由人批准。
