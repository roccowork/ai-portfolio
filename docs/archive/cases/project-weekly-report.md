## 问题

项目经理每周五花一两个小时写周报：翻任务系统、问各人进度、复制粘贴；周报和任务系统里的实际状态还经常对不上。

## 适用场景

- 适合：用任务系统管理项目、需要定期汇报的团队
- 不值得：任务不在系统里管理的
- 前提：任务状态在系统里及时更新

## 工具选型

| 方案                   | 特点         | 适用        |
| ---------------------- | ------------ | ----------- |
| Jira 仪表盘 + 自动化   | 原生能力     | 外企常用    |
| 飞书项目 / TAPD        | 国产项目管理 | 国内常用    |
| Python 读 API 生成周报 | 按模板       | ✅ 方案采用 |
| 手写周报               | 现状         | 耗时        |

任务系统里的数据是事实来源，周报从中生成才能保证一致；项目经理的价值在判断和协调。

## 怎么做

- 从任务系统读取本周完成的任务、进行中的任务、已延期的任务和新增的风险/阻塞
- 计算整体进度：按里程碑统计完成比例，和计划对比
- 按模板生成周报：本周完成、下周计划、延期项和原因、需要协调的事项
- 项目经理只补充判断和需要决策的事项，然后发出

## 实施步骤

| 步骤 | 做什么                 | 怎么验证       |
| ---- | ---------------------- | -------------- |
| 1    | 统一任务状态和标签用法 | 团队约定       |
| 2    | 读取 API 统计数据      | 和系统看板一致 |
| 3    | 设计周报模板           | 干系人认可     |
| 4    | 自动生成草稿           | 周五下午生成   |

## 关键代码

示例代码（简化），没有在生产环境运行：

```python
jql = f'project = {key} AND updated >= startOfWeek()'
issues = jira.search_issues(jql, maxResults=500)
done = [i for i in issues if i.fields.status.name == "Done" and i.fields.resolutiondate >= week_start]
overdue = [i for i in issues if i.fields.duedate and i.fields.duedate < today and i.fields.status.name != "Done"]
blocked = [i for i in issues if "阻塞" in [l for l in i.fields.labels]]
```

## 效果指标

| 指标           | 做之前             | 预期效果（估算） |
| -------------- | ------------------ | ---------------- |
| 写周报         | 一两个小时（估算） | 几分钟审核       |
| 周报和实际一致 | 经常不一致         | 来自同一数据     |
| 延期项可见     | 藏在细节里         | 单独列出         |

周报从手写一两个小时变成审核几分钟，内容和任务系统一致。

## 常见坑

- **任务状态没及时更新**：周报数据不准。周四提醒成员更新任务。
- **周报全是数字没有判断**：只有自动内容。项目经理必须补充风险和需要决策的事项。
- **API 分页导致数据不全**：只取了第一页。处理分页。

## AI 视角

**✨ AI 能增强**

- **AI 能做什么**：把任务数据写成通顺的周报叙述，提炼风险
- **不该交给 AI**：进度数据必须来自任务系统
- **怎么落地**：AI 写周报叙述，项目经理审核

## 面试怎么讲

30 秒讲法（方案思路；没有实际落地，面试时如实说明是设计过的方案）：

> 我会在每周五下午从 Jira 或飞书项目读取本周完成、进行中、延期的任务和标了「阻塞」的风险，按里程碑计算进度并和计划对比，按模板生成周报草稿；项目经理只补充判断和需要决策的事项，然后发给干系人。周报和任务系统永远一致。

常见追问：

**问：周报应该写什么？**

答：进度（和计划对比）、风险和问题、需要的支持和决策、下周计划；少写过程，多写结论。

**问：JQL 是什么？**

答：Jira 的查询语言，类似 SQL，用来筛选任务。

**问：怎么保证任务数据及时？**

答：站会时更新、周四提醒、看板作为唯一状态来源。

**被问到「能不能用 AI」时：** 周报数据来自系统，AI 写叙述和风险提炼。
