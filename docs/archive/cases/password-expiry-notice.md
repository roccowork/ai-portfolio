## 问题

密码 90 天过期的策略下，每到月初 IT 就会接到一批「电脑登不上」「邮箱连不上」的报修，尤其是长期在外的员工。

## 适用场景

- 适合：使用 AD 域、密码定期过期的公司
- 不值得：已经取消定期改密（NIST 新建议）、改用 MFA 的
- 前提：员工的邮箱或企业微信账号能和 AD 账号对应

## 工具选型

| 方案                  | 特点                   | 适用        |
| --------------------- | ---------------------- | ----------- |
| PowerShell + 任务计划 | 零成本                 | ✅ 方案采用 |
| ADSelfService Plus    | 商业，含提醒和自助重置 | 国内外都有  |
| Entra ID 密码策略     | 云身份                 | 外企        |
| n8n 定时流程          | 拖拽实现               | 可选        |

PowerShell 读取 AD 计算属性即可，十几行脚本，任务计划每天跑一次。

## 怎么做

- Windows 任务计划每天运行 PowerShell，读取每个账号的 `msDS-UserPasswordExpiryTimeComputed`
- 剩 7 天、3 天、1 天各提醒一次，消息里附「Ctrl+Alt+Del → 更改密码」和 VPN 用户的修改方法
- 服务账号（密码永不过期的）跳过，并单独列一份清单给 IT，确认是否合规
- 提醒发送记录写日志，方便统计效果

## 实施步骤

| 步骤 | 做什么                  | 怎么验证                |
| ---- | ----------------------- | ----------------------- |
| 1    | 写脚本读取密码过期时间  | 能列出 7 天内到期的账号 |
| 2    | 对接企业微信或邮件发送  | 测试账号收到提醒        |
| 3    | 7、3、1 天各提醒一次    | 同一阶段不重复提醒      |
| 4    | 服务账号单独列清单      | IT 收到服务账号清单     |
| 5    | 任务计划每天 09:00 运行 | 连续几天按时运行        |

## 关键代码

示例代码（简化），没有在生产环境运行：

```powershell
Get-ADUser -Filter { Enabled -eq $true -and PasswordNeverExpires -eq $false } `
  -Properties mail, "msDS-UserPasswordExpiryTimeComputed" | ForEach-Object {
  $expire = [datetime]::FromFileTime($_."msDS-UserPasswordExpiryTimeComputed")
  $days = ($expire - (Get-Date)).Days
  if ($days -in 7, 3, 1) { Send-Notice $_.mail $days }
}
```

## 效果指标

| 指标         | 做之前                       | 预期效果（估算） |
| ------------ | ---------------------------- | ---------------- |
| 密码过期报修 | 每月初一批（估算占报修两成） | 明显减少         |
| VPN 用户锁定 | 经常发生                     | 提前修改         |
| IT 处理时间  | 逐个重置                     | 员工自己改       |

把被动接报修变成主动提醒，是小公司 IT 最容易落地、效果最明显的自动化之一。

## 常见坑

- **细粒度密码策略的用户算错日期**：只按默认域策略计算。用 msDS-UserPasswordExpiryTimeComputed，它已考虑细粒度策略。
- **远程员工不知道怎么改**：不在域网络里。提醒里附 VPN 用户和网页修改的方法。
- **提醒被当作钓鱼**：格式像诈骗邮件。统一发件人，不放链接或只放内网链接。

## 面试怎么讲

30 秒讲法（方案思路；没有实际落地，面试时如实说明是设计过的方案）：

> 我会写一个 PowerShell 脚本，每天 9 点由任务计划运行，读取 AD 里每个账号的 msDS-UserPasswordExpiryTimeComputed，在剩 7、3、1 天时通过企业微信或邮件提醒本人，附上修改方法；服务账号单独列清单给 IT 确认。这是小公司 IT 最容易落地、效果最明显的自动化之一。

常见追问：

**问：NIST 对密码定期过期有什么新建议？**

答：不再建议强制定期修改，频繁改密会导致弱密码；建议用长密码、检测泄露密码并启用多因素认证。

**问：为什么用 msDS-UserPasswordExpiryTimeComputed？**

答：它是 AD 计算出的实际过期时间，已经考虑了细粒度密码策略。

**问：账号被锁定怎么排查来源？**

答：查域控安全日志事件 4740，找到锁定来源的计算机；常见是手机邮箱、映射盘、计划任务里的旧密码。
