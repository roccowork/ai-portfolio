## 问题

测试人员手工造数据要半天，数据量小发现不了性能问题；有人直接把生产数据拷到测试环境，客户个人信息就泄露了。

## 适用场景

- 适合：需要大量测试数据做功能测试和压测的团队
- 不值得：数据量很小、手工几条就够的
- 前提：了解表结构和业务规则

## 工具选型

| 方案           | 特点                 | 适用           |
| -------------- | -------------------- | -------------- |
| Python Faker   | 生成假数据，支持中文 | 国内外都常用   |
| 数据库脱敏工具 | 从生产导出并脱敏     | 国内商业产品多 |
| Mockaroo       | 网页生成             | 外企           |
| SQL 存储过程   | 数据库内批量生成     | DBA 常用       |

Faker 灵活、本地化好；需要真实分布时用脱敏导出。

## 怎么做

- 用 Faker 按字段生成有真实感的姓名、手机号、地址（中文本地化），按业务规则生成订单状态、金额分布
- 保持表之间的关联：先生成用户，再按用户生成订单和明细
- 需要真实数据分布时，从生产导出并脱敏：手机号、身份证、地址替换为假数据，保留统计特征
- 数据集版本化，测试和压测可以反复使用同一份

## 实施步骤

| 步骤 | 做什么                 | 怎么验证             |
| ---- | ---------------------- | -------------------- |
| 1    | 梳理表结构和关联关系   | 有一份 ER 图         |
| 2    | 写生成脚本，先小量验证 | 数据符合约束         |
| 3    | 按业务规则设分布       | 订单状态比例接近真实 |
| 4    | 批量导入测试库         | 十万级数据几分钟导完 |
| 5    | 版本化数据集           | 测试可重复使用       |

## 关键代码

示例代码（简化），没有在生产环境运行：

```python
from faker import Faker
fake = Faker("zh_CN")
users = [{"id": i, "name": fake.name(), "phone": fake.phone_number(), "city": fake.city()} for i in range(10_000)]
orders = [{"user_id": random.choice(users)["id"], "amount": round(random.lognormvariate(4, 1), 2),
           "status": random.choices(["paid", "shipped", "refunded"], weights=[6, 3, 1])[0]} for _ in range(100_000)]
```

## 常见坑

- **生成的数据违反业务约束**：只按字段类型随机。按业务规则生成，导入前校验。
- **批量插入太慢**：逐条 insert。批量插入或 LOAD DATA。
- **脱敏不彻底**：漏了备注、地址等自由文本字段。列出所有敏感字段，自由文本统一替换。

## AI 视角

**✨ AI 能增强**

- **AI 能做什么**：根据业务描述生成更真实的测试数据（地址、评论文本）
- **不该交给 AI**：数据约束和脱敏规则必须确定
- **怎么落地**：规则生成结构，AI 生成文本类字段

## 面试怎么讲

30 秒讲法（方案思路；没有实际落地，面试时如实说明是设计过的方案）：

> 我会用 Faker 按表结构和业务规则生成测试数据：中文姓名、手机号、地址都有真实感，订单金额和状态按真实比例分布，先生成用户再按用户生成订单保持关联。需要真实分布时从生产导出并脱敏。造数从半天变成几分钟，测试环境里也不再有真实客户信息。

常见追问：

**问：为什么不能直接用生产数据测试？**

答：违反个人信息保护要求，测试环境安全性低，泄露风险大。

**问：压测数据量多少合适？**

答：接近生产规模，否则索引、缓存命中率和生产差别大，结果没有参考价值。

**问：如何保证生成的数据可重复？**

答：设置随机种子，同一个种子生成同样的数据。

**被问到「能不能用 AI」时：** 数据结构和约束用规则保证，AI 生成更真实的文本类数据。
