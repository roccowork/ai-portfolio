## 问题

公司里有大量「A 系统发生了什么，就在 B 系统做什么」的小需求：表单提交后通知群里、每天把表格数据汇总发邮件、新客户进 CRM 后建任务。每个都排期开发太慢，每个都写脚本又没人维护。n8n 这类工作流平台国内外企业都在用，拖拽就能把表单、表格、通知、各种 API 串起来，非开发人员也能改流程。

## 适用场景

- 适合：有很多「A 系统发生了什么，就在 B 系统做什么」类需求、又没有开发资源的团队
- 不值得：只有一两个简单流程（写个脚本即可）
- 前提：要连接的系统有 API 或 Webhook

## 工具选型

| 方案                             | 特点                 | 适用            |
| -------------------------------- | -------------------- | --------------- |
| n8n                              | 开源可自建，节点丰富 | 国内外都常用 ✅ |
| Zapier / Make                    | SaaS，集成最多       | 外企常用        |
| 宜搭、简道云、飞书多维表格自动化 | 国产低代码           | 国内常用        |
| Node-RED                         | 偏物联网             | 开源            |

选 n8n：可以自建，数据不出公司；需要时能写 JS 代码节点，比纯拖拽平台灵活。

## 怎么做

- **部署**：和本站同一个 k3s 集群，Argo CD 从 Git 同步（`deploy/apps/n8n/`），镜像版本由 Renovate 自动提 PR 升级
- **数据**：SQLite + 加密凭据的密钥放在同一个 PVC，每天用 restic 加密备份到 R2，和云盘、访问统计共用备份脚本；执行记录只保留 14 天，数据库不会越长越大
- **安全**：n8n 第一次打开时谁先访问谁就能注册管理员。管理界面外面加了一层 Traefik 基本认证，Secret 没建之前界面无法访问；表单和 Webhook 路径单独放行
- **示例流程**：一个表单提交后推送到企业微信群，用来验证部署；具体的业务流程（如 IT 报修）见各自的案例

## 实施步骤

| 步骤 | 做什么                              | 怎么验证                   |
| ---- | ----------------------------------- | -------------------------- |
| 1    | 部署 n8n（K8s + PVC + 备份）        | 能打开管理界面             |
| 2    | 外层基本认证，防止被抢注管理员      | 未建 Secret 时界面无法访问 |
| 3    | 导入示例工作流并填入企业微信 key    | 提交表单后群里收到消息     |
| 4    | 公开路径 /form/、/webhook/ 单独放行 | 外部能访问表单             |
| 5    | 每天备份数据库和加密密钥            | 备份任务成功               |

## 关键代码

以下为节选。管理界面和公开路径分成两个 Ingress，公开路径更长，Traefik 优先匹配：

```yaml
# 管理界面：基本认证
traefik.ingress.kubernetes.io/router.middlewares: n8n-redirect-https@kubernetescrd,n8n-basic-auth@kubernetescrd
---
# 表单和 Webhook：不加认证
paths:
  - path: /webhook/
  - path: /form/
```

## 常见坑

- **第一次打开谁都能注册管理员**：n8n 初始化时没有登录保护。外面加一层基本认证，上线后立即注册。
- **恢复后凭据无法解密**：只恢复了数据库，没恢复 config 里的加密密钥。两个文件从同一个快照一起恢复。
- **n8n 2.x 默认禁止表达式读取环境变量**：安全加固。密钥放在 n8n 的凭据里，而不是环境变量。

## AI 视角

**✨ AI 能增强**

- **AI 能做什么**：用自然语言描述流程，AI 生成工作流草稿；n8n 已有 AI 节点

## 面试怎么讲

30 秒讲法（方案思路；没有实际落地，面试时如实说明是设计过的方案）：

> 我写好了 n8n 的完整部署清单：Argo CD 管理，SQLite 和加密密钥放在同一个 PVC，每天 restic 备份到 R2；管理界面外加一层 Traefik 基本认证，防止上线后被别人抢先注册管理员，表单和 Webhook 路径单独放行。示例流程是表单提交后推送到企业微信。验证后为了节省服务器内存先下线了，清单保留在仓库里。

常见追问：

**问：低代码平台和写脚本怎么选？**

答：流程简单、经常变、业务人员要参与的用低代码；逻辑复杂、要测试、性能要求高的写代码。

**问：n8n 的数据要备份什么？**

答：数据库（工作流、凭据、执行记录）和加密密钥文件，缺一不可。

**问：自建和 SaaS（Zapier）怎么选？**

答：数据敏感、要连内网系统、量大的选自建；追求省心、集成多的选 SaaS。

**被问到「能不能用 AI」时：** n8n 自带 AI 节点，可以把文本理解、摘要放进工作流的某一步。
