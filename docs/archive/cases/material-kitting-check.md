## 问题

生产线开工后才发现缺一个小零件，整条线停下等料；计划员每天手工核对几百个物料，经常漏。

## 适用场景

- 适合：多物料装配型生产（电子、机械、家电）
- 不值得：物料很少或单一原料的生产
- 前提：BOM 准确，库存和采购在途数据可靠

## 工具选型

| 方案            | 特点             | 适用        |
| --------------- | ---------------- | ----------- |
| ERP 的 MRP 运算 | 标准物料需求计划 | 国内外都有  |
| Python 齐套检查 | 按工单精确检查   | ✅ 方案采用 |
| APS 高级排程    | 排产和齐套一体   | 中大型工厂  |
| Excel 手工核对  | 现状             | 容易漏      |

MRP 算的是总需求，齐套检查要精确到每个工单开工时物料是否到齐；可以在 MRP 之外补充。

## 怎么做

- 读取未来 3 天的生产计划，按 BOM 展开出每个工单需要的物料和数量
- 对比可用库存（扣除已分配给其他工单的）和预计到货的在途物料
- 列出缺料清单：缺哪个物料、缺多少、影响哪些工单和开工时间
- 每天早上发给采购和计划员，按影响开工时间排序

## 实施步骤

| 步骤 | 做什么                  | 怎么验证       |
| ---- | ----------------------- | -------------- |
| 1    | 确认 BOM 和库存数据准确 | 抽查核对       |
| 2    | 读取生产计划和在途      | 数据完整       |
| 3    | 实现 BOM 展开和分配     | 和手工核对一致 |
| 4    | 生成缺料清单            | 按开工时间排序 |
| 5    | 每天推送采购和计划      | 跟进到货       |

## 关键代码

示例代码（简化），没有在生产环境运行：

```python
need = defaultdict(float)
for wo in plan.next_days(3):
    for comp in bom.explode(wo.item, wo.qty):
        need[(comp.part, wo.id)] += comp.qty
for (part, wo_id), qty in need.items():
    available = stock.available(part) + po.arriving_before(part, wo_start(wo_id))
    if available < qty:
        shortage.append({"物料": part, "缺": qty - available, "工单": wo_id})
```

## 效果指标

| 指标       | 做之前             | 预期效果（估算） |
| ---------- | ------------------ | ---------------- |
| 停线等料   | 经常               | 开工前发现       |
| 计划员核对 | 每天几小时（估算） | 自动             |
| 采购催货   | 被动               | 按影响排序主动催 |

缺料在开工前几天就被发现，停线等料大幅减少。

## 常见坑

- **BOM 不准**：设计变更没同步。BOM 变更流程和 ERP 同步。
- **库存账实不符**：领料没及时出账。定期盘点，异常差异追查。
- **多个工单抢同一批物料**：没有分配逻辑。按开工顺序预分配。

## 面试怎么讲

30 秒讲法（方案思路；没有实际落地，面试时如实说明是设计过的方案）：

> 我会每天读取未来 3 天的生产计划，按 BOM 展开每个工单需要的物料，对比扣除已分配后的可用库存和开工前能到货的在途，列出缺哪个物料、缺多少、影响哪些工单，按开工时间排序发给采购和计划员。缺料在开工前几天就被发现。

常见追问：

**问：BOM 是什么？**

答：物料清单，描述一个产品由哪些零部件、各多少组成，可以多层展开。

**问：MRP 和齐套检查的区别？**

答：MRP 计算一段时间的总物料需求生成采购建议；齐套检查确认具体工单开工时物料是否都到齐。

**问：库存不准怎么办？**

答：先盘点和追查差异原因，否则所有自动计算都不可靠。

**被问到「能不能用 AI」时：** 齐套计算必须精确，用规则。
