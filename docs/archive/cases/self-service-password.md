## 问题

「忘记密码」「账号被锁」通常占 IT 报修的两到三成，每次都要 IT 手动处理，下班后员工只能等第二天。

## 适用场景

- 适合：使用 AD、员工几十人以上、密码类报修多的公司
- 不值得：已经用 SSO + MFA 并有官方自助重置的（如 Entra ID SSPR）
- 前提：员工有绑定的手机或企业微信，能可靠验证身份

## 工具选型

| 方案                      | 特点                      | 适用        |
| ------------------------- | ------------------------- | ----------- |
| 自写网页 + PowerShell     | 可控，零成本              | ✅ 方案采用 |
| Entra ID SSPR             | 微软官方自助重置          | 外企常用    |
| ADSelfService Plus        | 商业，功能全              | 国内外都用  |
| LTB Self Service Password | 开源，适合 OpenLDAP 和 AD | 开源        |

有 Entra ID 直接用官方 SSPR；纯本地 AD 的小公司用开源方案或自写页面。

## 怎么做

- 自助页面放在内网（或 VPN 后），员工输入工号，系统给企业微信或绑定手机发验证码
- 验证通过后在页面设置新密码，后台用专用服务账号（只有重置密码和解锁权限）调用 AD
- 新密码按公司策略校验复杂度；同一账号每天最多自助 3 次，防止被滥用
- 每次操作通知本人（「你的密码刚被重置，如非本人操作请联系 IT」）并记录日志

## 实施步骤

| 步骤 | 做什么                                 | 怎么验证                     |
| ---- | -------------------------------------- | ---------------------------- |
| 1    | 创建服务账号，只委派重置密码和解锁权限 | 该账号不能做其他操作         |
| 2    | 自助页面放在内网或 VPN 后              | 外网无法访问                 |
| 3    | 企业微信验证码验证身份                 | 错误验证码无法继续           |
| 4    | 重置密码、解锁，校验复杂度             | 新密码能登录                 |
| 5    | 通知本人并记录日志                     | 本人收到「密码已被重置」通知 |

## 关键代码

示例代码（简化），没有在生产环境运行：

```powershell
# 后台调用：用只有「重置密码 + 解锁」权限的服务账号执行
Set-ADAccountPassword -Identity $login -Reset `
  -NewPassword (ConvertTo-SecureString $newPwd -AsPlainText -Force) -Credential $svcCred
Unlock-ADAccount -Identity $login -Credential $svcCred
Set-ADUser -Identity $login -ChangePasswordAtLogon $false -Credential $svcCred
```

## 效果指标

| 指标           | 做之前                 | 预期效果（估算） |
| -------------- | ---------------------- | ---------------- |
| 密码类报修     | 占报修两到三成（估算） | 大幅减少         |
| 下班后忘记密码 | 只能等第二天           | 随时自助         |
| IT 处理时间    | 每次 5～10 分钟        | 0                |

密码类报修大幅减少，员工随时能自己解决；配合密码到期提醒效果更好。

## 常见坑

- **身份验证太弱被冒用**：只验证工号和生日。用绑定的企业微信或手机验证码，限次数。
- **服务账号权限过大**：用了域管理员。只委派特定 OU 的重置密码和解锁权限。
- **重置后其他设备不断用旧密码锁定账号**：手机邮箱、映射盘保存了旧密码。重置成功页提示更新各设备上的密码。

## 面试怎么讲

30 秒讲法（方案思路；没有实际落地，面试时如实说明是设计过的方案）：

> 我会做一个内网自助页面：员工输入工号，系统给绑定的企业微信发验证码，验证通过后设置新密码；后台用一个只委派了重置密码和解锁权限的服务账号调用 AD，新密码按策略校验复杂度，同一账号每天最多 3 次；每次操作通知本人并记录日志。

常见追问：

**问：AD 权限委派是什么？**

答：把某个 OU 上的特定权限（如重置密码）授予特定账号，而不是给它域管理员。

**问：自助重置最大的风险是什么？**

答：身份验证被绕过导致账号被盗；所以验证方式要可靠、要限次数、要通知本人。

**问：账号频繁被锁定怎么排查？**

答：查域控 4740 事件找到来源计算机，常见是手机邮箱、计划任务、映射盘里保存的旧密码。

**被问到「能不能用 AI」时：** 身份验证不能交给 AI。
