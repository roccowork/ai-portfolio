## 问题

外企面试和日常工作都要读英文文档、写英文工单，但背单词 App 很难坚持，词汇也不贴合运维工作。

## 适用场景

- 适合：想坚持学专业英语、又没有整块时间的人；团队也可以用来做技术分享提醒
- 不值得：已经有固定学习习惯和工具的
- 前提：有企业微信群机器人（或钉钉、飞书）

## 工具选型

| 方案                 | 特点                       | 适用               |
| -------------------- | -------------------------- | ------------------ |
| 自写 CronJob（本站） | 词库贴合运维、复用现有通道 | ✅ 本站选用        |
| 背单词 App           | 词库大、有复习算法         | 词汇不贴合运维     |
| n8n 定时流程         | 拖拽实现                   | 需要多运行一个服务 |

自写：复用告警转发器的发送函数和群机器人，不增加任何服务和密钥，一个 CronJob 就够了。

## 怎么做

- 词库 `words.json`：100 个运维常用词（rollback、outage、failover、drift……），每个配一句短例句和中文，例句尽量取自自己做过的实验
- CronJob 每天洛杉矶时间 07:30 运行，按当地日期算出今天是第几组，同一天重跑结果相同，不需要保存任何状态
- 复用告警转发器的发送函数和同一个企业微信群机器人，不新增任何密钥
- 单元测试检查：词库字段完整、不重复；20 天覆盖全部单词；跨时区（UTC 已是第二天、洛杉矶还是当天）组号不变；消息不超过企业微信 4096 字节

## 关键代码

```js
/** 当天是第几组（从 0 开始），按当地日期计算，同一天多次运行结果相同 */
export function groupIndex(now, total, timeZone = TZ) {
  const groups = Math.ceil(total / PER_DAY);
  const days = Math.floor(Date.parse(`${localDate(now, timeZone)}T00:00:00Z`) / 86_400_000);
  return days % groups;
}
```

## 常见坑

- **跨时区时组号不对**：服务器按 UTC 算日期，洛杉矶还是前一天。用 Intl.DateTimeFormat 按洛杉矶时区算当地日期，测试覆盖了这种情况。
- **脚本被直接运行时不执行**：判断「是否直接运行」时用了被导入模块的路径。把当前模块的 import.meta.url 传进 isMain。

## 面试怎么讲

30 秒讲法：

> 为了每天坚持学运维英语，我在集群里加了一个 CronJob，每天早上推 5 个运维常用词和例句到企业微信，100 个词 20 天一轮。它按当地日期计算组号，没有任何状态；复用告警转发器的发送函数，不新增服务和密钥。单元测试覆盖了跨时区和消息长度。这也说明了一套通知通道可以复用给很多自动化。

常见追问：

**问：为什么不保存「今天发到第几组」？**

答：用日期计算组号是无状态的：重跑、重试、换节点都不会重复或跳过，不需要数据库。

**问：CronJob 的 timeZone 字段有什么用？**

答：K8s 1.27 起 CronJob 支持 timeZone，按指定时区解释 schedule，不用自己换算 UTC，夏令时也会自动处理。

**问：怎么扩展？**

答：加词只改 words.json；可以加周日复习、按难度分级，或者换成从文档里自动摘取高频词。

**被问到「能不能用 AI」时：** 词库是固定的，AI 可以根据当天的词生成工作场景对话练习。
