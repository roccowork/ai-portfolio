## 问题

运营每天手动打开几十个竞品页面看价格，看漏了竞品降价，自家的销量就掉了。

## 适用场景

- 适合：电商、零售、对价格敏感的业务
- 不值得：价格不常变、竞品很少的
- 前提：竞品价格在公开页面可见，遵守网站条款

## 工具选型

| 方案                     | 特点           | 适用         |
| ------------------------ | -------------- | ------------ |
| Playwright 脚本          | 能处理 JS 渲染 | ✅ 方案采用  |
| 商业价格监控服务         | 数据现成       | 电商常用     |
| 电商平台开放接口         | 合规稳定       | 有权限时优先 |
| Requests + BeautifulSoup | 静态页面       | 简单场景     |

有官方接口优先用接口；只能看页面时用 Playwright，并控制频率、遵守 robots 规则。

## 怎么做

- 维护一份对标商品清单：自家商品 → 竞品公开页面链接
- 每天两次用浏览器打开页面，读取价格和促销文案，存入历史表
- 价格变化超过 5%、或竞品价格低于自家价格时通知运营，附价格趋势
- 只抓取公开页面、控制频率，遵守网站的服务条款和 robots 规则

## 常见坑

- **页面改版导致抓取失败**：选择器变了。抓取失败时告警，及时更新选择器。
- **频繁访问被封**：访问太快。控制频率，遵守 robots 和服务条款。
- **价格显示依赖地区或登录**：不同条件下价格不同。固定访问条件，记录抓取环境。

**✨ AI 能增强**

- **不该交给 AI**：价格变化判断必须确定

常见追问：

**问：网页抓取要注意哪些合规问题？**

答：遵守 robots 和服务条款、只抓公开数据、不绕过登录和反爬措施、控制频率、不抓个人信息。

**问：动态页面怎么抓？**

答：用 Playwright 等浏览器自动化工具等待渲染完成，或者找页面调用的公开接口。

**问：如何保证抓取稳定？**

答：稳定的选择器、失败重试和告警、监控抓取成功率。

**被问到「能不能用 AI」时：** AI 能在页面改版时识别价格，减少抓取脚本的维护。
