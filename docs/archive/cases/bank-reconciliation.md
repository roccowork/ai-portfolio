## 问题

财务每天把几百条银行流水和订单一条条对：客户合并付款、分批付款、手续费扣减，对一次要大半天，还经常对错。

## 适用场景

- 适合：收款笔数多、客户经常合并或分批付款的公司
- 不值得：每月只有几笔收款的
- 前提：能导出银行流水和系统应收记录

## 工具选型

| 方案                           | 特点               | 适用         |
| ------------------------------ | ------------------ | ------------ |
| Python + pandas                | 灵活，处理复杂匹配 | ✅ 方案采用  |
| 财务软件对账模块（金蝶、用友） | 和账务一体         | 国内常用     |
| 银企直连                       | 自动获取流水       | 需要银行开通 |
| RPA 机器人                     | 模拟人工操作       | 国内常用     |

Python 能处理合并付款、手续费差额这类复杂匹配，规则可测试；我做的办公自动化工具里已实现了流水和日记账的对账。

## 怎么做

- 每天导入银行流水（网银导出的 Excel，或银企直连接口）和业务系统的应收记录
- 先精确匹配：金额一致、日期相差 3 天内、付款方名称匹配（去掉「有限公司」等后缀后比较）
- 再处理复杂情况：一笔流水对多张订单（合并付款）、金额相差在手续费范围内
- 匹配不上的生成差异清单（未到账、多收、无法识别），财务只处理这部分

## 实施步骤

| 步骤 | 做什么                         | 怎么验证                   |
| ---- | ------------------------------ | -------------------------- |
| 1    | 统一两边的字段和格式           | 金额、日期、付款方格式一致 |
| 2    | 精确匹配：金额 + 日期 + 付款方 | 大部分记录被匹配           |
| 3    | 复杂匹配：合并付款、手续费差额 | 剩余记录进一步减少         |
| 4    | 生成差异清单                   | 财务只处理差异             |
| 5    | 每天定时运行                   | 每天早上有对账结果         |

bank["key"] = bank["付款方"].map(normalize) + "|" + bank["金额"].round(2).astype(str)

## 常见坑

- **付款方名称不一致**：「某某有限公司」和「某某公司」。标准化名称，去掉后缀后比较。
- **一笔对多笔的组合爆炸**：穷举所有组合太慢。限定日期范围和候选数量。
- **同金额多笔误配**：只按金额匹配。加日期和付款方，再用摘要相似度。

## AI 视角

**✨ AI 能增强**

- **AI 能做什么**：匹配付款方名称的各种写法；解释差异原因
- **不该交给 AI**：金额匹配必须精确
- **怎么落地**：AI 辅助名称匹配和差异解释，结果由财务确认

## 面试怎么讲

30 秒讲法（方案思路；没有实际落地，面试时如实说明是设计过的方案）：

> 我会每天导入银行流水和系统应收记录，先精确匹配：金额一致、日期相差 3 天内、付款方名称标准化后一致；再处理合并付款和手续费差额。匹配不上的生成差异清单，财务只处理这部分。我做的办公自动化工具里已经实现了流水和日记账的配对、日期逐步放宽和摘要相似度选择。

常见追问：

**问：对账匹配为什么要逐步放宽条件？**

答：先用最严格的条件配最确定的，再放宽处理剩下的，减少误配。

**问：什么是银企直连？**

答：企业系统和银行系统通过接口直接对接，自动获取流水和发起付款，不用手工导出。

**问：财务自动化的风险控制？**

答：自动只做匹配和标记，资金操作仍需人工审批；所有结果可追溯。

**被问到「能不能用 AI」时：** 金额匹配用规则，AI 帮处理「某某公司」和「某某有限公司」这类名称差异。
