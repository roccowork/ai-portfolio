## 问题

物流和外贸每天要处理大量单据：海运提单、装箱单、报关单、送货签收单、入库单。格式各家不同，有的还是手写或盖章的扫描件，全靠单证员一张张手工录入系统，一张几分钟，忙的时候积压，还容易录错数字；签收单上写着「少 2 箱」没人注意到，月底对账才发现。

## 适用场景

- 适合：每天处理几十张以上单据的物流公司、外贸公司、仓库
- 不值得：单据很少，或者已经全部电子化对接（EDI）的
- 前提：单据能拍照或扫描；系统里有对应的订单数据可以核对

## 工具选型

| 方案                                        | 特点                             | 适用        |
| ------------------------------------------- | -------------------------------- | ----------- |
| 云 OCR 卡证票据识别（阿里云、腾讯云、百度） | 标准单据有现成模板               | 国内常用    |
| AWS Textract、Azure Document Intelligence   | 通用文档理解                     | 外企常用    |
| 多模态大模型直接读图提取                    | 不需要为每种格式做模板，适应性强 | ✅ 方案采用 |
| 人工录入                                    | 现状                             | 慢，易错    |

格式固定的标准单据用云 OCR 模板，便宜稳定；格式五花八门的单据用多模态大模型，按字段定义直接提取，新格式不用重新做模板。

## 怎么做

- **收集**：单据通过手机拍照（小程序）、扫描仪、邮件附件进入统一的收件箱
- **识别类型**：AI 先判断是哪种单据（提单、装箱单、报关单、签收单），选择对应的字段定义
- **提取字段**：按字段定义输出结构化数据——单号、日期、收发货人、货物名称、件数、重量、体积、柜号；签收单额外提取手写备注（如「少 2 箱」「外箱破损」）
- **自动核对**：和 ERP / WMS 里的订单比对：单号能否匹配、件数和重量是否一致；置信度低的字段标黄
- **入账**：全部一致的自动入账；有差异或低置信度的推送给单证员，界面上左边是原图、右边是提取结果，修改确认即可
- 原图和提取结果一起归档，便于审计和纠纷时查证

## 关键代码

示例代码（简化），没有在生产环境运行：

```python
SCHEMAS = {
    "delivery_receipt": {"order_no": "送货单号", "consignee": "收货单位", "items": "货物明细（名称、件数）",
                         "signed_by": "签收人", "remarks": "手写备注，如少货、破损"},
    "bill_of_lading": {"bl_no": "提单号", "vessel": "船名航次", "container_no": "柜号",
                       "packages": "件数", "gross_weight_kg": "毛重"},
}
doc_type = llm.classify(image, list(SCHEMAS))
data = llm.extract(image, SCHEMAS[doc_type], with_confidence=True)  # 看不清的字段返回 null，不猜
order = erp.find_order(data["order_no"] or data["bl_no"])
diffs = compare(order, data)
if not diffs and min(data.confidence.values()) > 0.9:
    erp.post_receipt(order, data, image)  # 自动入账
else:
    review_queue.add(image, data, diffs)  # 原图 + 提取结果 + 差异，人工确认
```

## 效果指标

| 指标                 | 做之前           | 预期效果（估算）       |
| -------------------- | ---------------- | ---------------------- |
| 每张单据录入时间     | 几分钟           | 几秒（自动）或确认即可 |
| 录入错误             | 偶有，对账才发现 | 自动核对，差异即时提醒 |
| 签收异常（少货破损） | 月底对账才发现   | 单据上传当天提醒       |

单证员从录入转为处理差异，签收异常当天就能跟进，减少对账纠纷。

## 常见坑

- **AI 把看不清的数字猜出来**：模糊的件数被猜成别的数字。要求看不清就返回空，低置信度的字段人工确认。
- **只识别不核对**：录入快了但错误照样进系统。必须和订单数据核对，有差异就不自动入账。
- **拍照质量差**：歪斜、反光、截掉一半。小程序拍照时检测清晰度和完整性，不合格当场重拍。
- **手写备注被忽略**：签收单上最重要的往往是手写的「少 2 箱」。专门提取备注字段，有内容就提醒。
- **单据含敏感信息**：收发货人电话、地址。传给外部模型前按政策脱敏，或使用私有部署的模型。

## AI 视角

**🤖 AI 是核心**

- **AI 能做什么**：读懂格式各异、带手写和印章的单据，判断单据类型，按字段定义提取信息，不需要为每种格式做模板
- **不该交给 AI**：核对规则、自动入账的条件、差异的处理决定
- **怎么落地**：AI 识别提取，程序和订单核对，一致的自动入账，差异和低置信度的人工确认

## 面试怎么讲

30 秒讲法（方案思路；没有实际落地，面试时如实说明是设计过的方案）：

> 我会让单据通过拍照、扫描、邮件附件进入统一收件箱，先由 AI 判断单据类型，再按字段定义提取单号、件数、重量、收发货人和手写备注，看不清的字段返回空不猜。提取结果和 ERP 里的订单自动核对，一致且置信度高的自动入账；有差异的推给单证员，左边原图右边结果，确认即可。每种单据先用 30 张样本评估准确率。

常见追问：

**问：OCR 和大模型识别有什么区别？**

答：传统 OCR 识别文字，还需要为每种格式写规则把文字对应到字段；多模态大模型能理解单据结构，直接按字段输出，新格式不用重做模板。标准单据用 OCR 更便宜。

**问：怎么保证数据准确？**

答：要求输出置信度、看不清返回空；和订单系统核对；有差异或低置信度的人工确认；原图归档。

**问：IDP 是什么？**

答：Intelligent Document Processing，智能文档处理：分类、提取、校验、入系统的整个流程自动化，不只是 OCR。

**被问到「能不能用 AI」时：** 这个案例本身就是 AI；AI 读单据，程序核对，人处理差异。
