## 问题

镜像里的基础系统和依赖包会不断爆出新漏洞，没人检查的话，线上跑着带已知高危漏洞的镜像很常见，审计时也拿不出证据。

## 适用场景

- 适合：用容器部署、有安全合规要求的团队
- 不值得：几乎不更新的内部镜像（但仍建议定期扫描）
- 前提：镜像构建在 CI 里

## 工具选型

| 方案                  | 特点                          | 适用         |
| --------------------- | ----------------------------- | ------------ |
| Trivy                 | 开源，扫描镜像、文件系统、IaC | 国内外都常用 |
| Grype + Syft          | 扫描 + SBOM                   | 开源         |
| Harbor 内置扫描       | 推送时自动扫描                | 自建仓库     |
| Snyk / 云厂商镜像扫描 | 商业，修复建议多              | 外企 / 云上  |

选 Trivy：单个命令、速度快、能生成 SBOM，在 CI 和定时任务里都容易用。

## 怎么做

- CI 里构建完镜像后跑 `trivy image`，只拦「CRITICAL 且已有修复版本」的漏洞，避免没法修的漏洞卡住发布
- 同时生成 SBOM（软件物料清单），出现新漏洞时能快速查到哪些镜像受影响
- 定时任务每周重扫线上正在运行的镜像，新出现的漏洞发到企业微信
- 配合 Renovate 自动升级基础镜像，大部分漏洞会被自动修掉

## 实施步骤

| 步骤 | 做什么                         | 怎么验证           |
| ---- | ------------------------------ | ------------------ |
| 1    | CI 构建后运行 trivy image      | 报告列出漏洞       |
| 2    | 只拦 CRITICAL 且已有修复版本的 | 有高危时流水线失败 |
| 3    | 生成 SBOM 并存档               | 每个版本有 SBOM    |
| 4    | 每周重扫线上镜像               | 新漏洞通知到群     |
| 5    | 配合 Renovate 升级基础镜像     | 漏洞数量持续下降   |

## 关键代码

示例代码（简化），没有在生产环境运行：

```bash
# 只拦「严重且已有修复版本」的漏洞；同时生成 SBOM 存档
trivy image --severity CRITICAL --ignore-unfixed --exit-code 1 "$IMAGE"
trivy image --format cyclonedx --output sbom.json "$IMAGE"
```

## 效果指标

| 指标             | 做之前 | 预期效果（估算） |
| ---------------- | ------ | ---------------- |
| 线上已知高危漏洞 | 不知道 | 发布前拦截       |
| 审计证据         | 没有   | 每次扫描有记录   |
| 新漏洞响应       | 被动   | 每周重扫         |

把「有没有高危漏洞」从人工检查变成每次发布的硬性门槛，审计时有扫描记录可查。

## 常见坑

- **大量没法修的漏洞卡住发布**：上游还没出修复版本。加 --ignore-unfixed，只拦能修的。
- **误报**：漏洞不影响实际使用的功能。用 .trivyignore 记录忽略原因和到期日。
- **漏洞库下载慢**：CI 每次下载数据库。缓存漏洞库，或用镜像加速。

## AI 视角

**✨ AI 能增强**

- **AI 能做什么**：解释漏洞是否真的影响本项目（是否调用了有漏洞的函数）
- **不该交给 AI**：拦截规则按严重级别确定
- **怎么落地**：扫描结果交给 AI 做可达性分析，作为豁免的参考

## 面试怎么讲

30 秒讲法（方案思路；没有实际落地，面试时如实说明是设计过的方案）：

> 我会在 CI 构建镜像后运行 Trivy，只拦严重级别且已有修复版本的漏洞，避免没法修的漏洞卡住发布；同时生成 SBOM 存档，出新漏洞时能快速查到哪些镜像受影响。每周重扫线上正在运行的镜像，新漏洞发到群里；配合 Renovate 自动升级基础镜像，大部分漏洞会被自动修掉。

常见追问：

**问：什么是 SBOM？**

答：软件物料清单，列出镜像里所有软件包和版本，像食品配料表；出现新漏洞时能快速判断受影响范围。

**问：为什么只拦已有修复的漏洞？**

答：没有修复版本时拦截也没用，只会卡住发布；先记录，等上游修复后再处理。

**问：怎么减少镜像漏洞？**

答：用精简基础镜像（distroless、alpine）、多阶段构建不带编译工具、定期升级基础镜像。

**被问到「能不能用 AI」时：** 扫描和拦截是规则，AI 帮判断漏洞是否真的可被利用，减少无效修复。
