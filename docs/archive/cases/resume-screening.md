## 问题

HR 每天看几百份简历，大部分明显不符合；约面试要在候选人和面试官之间来回沟通时间，一个面试要发好几条消息。

## 适用场景

- 适合：招聘量大、渠道多的公司
- 不值得：一年招几个人的小团队
- 前提：岗位要求能写出明确的硬性条件

## 工具选型

| 方案                           | 特点           | 适用     |
| ------------------------------ | -------------- | -------- |
| Moka、北森招聘                 | 国产 ATS       | 国内常用 |
| Greenhouse、Workday Recruiting | 外企 ATS       | 外企常用 |
| Calendly 类预约工具            | 候选人自选时间 | 外企常用 |
| 邮件 + 表格                    | 现状           | 耗时     |

招聘量大用 ATS；初筛只按硬性条件筛除，最终判断由人做，避免算法偏见。

## 怎么做

- 多个渠道的简历统一进入招聘系统，解析出学历、工作年限、技能、期望城市
- 按岗位的硬性条件初筛（工作地点、年限、必备证书），只做筛除明显不符合的，不做最终判断
- 合格简历推给用人部门确认；确认后候选人收到链接，在面试官空闲时间里自选
- 自动发日历邀请和面试提醒，面试后提醒面试官填写评价

## 实施步骤

| 步骤 | 做什么         | 怎么验证               |
| ---- | -------------- | ---------------------- |
| 1    | 统一简历入口   | 各渠道简历进入同一系统 |
| 2    | 配置简历解析   | 关键字段准确           |
| 3    | 写硬性条件规则 | 只筛明显不符合的       |
| 4    | 接入面试官日历 | 候选人能看到可选时间   |
| 5    | 自动邀请和提醒 | 面试按时进行           |

## 关键代码

示例代码（简化），没有在生产环境运行：

```python
def hard_filter(cv, job):
    reasons = []
    if cv.years < job.min_years: reasons.append(f"工作年限 {cv.years} 年，要求 {job.min_years} 年")
    if job.city not in cv.cities: reasons.append("期望城市不符")
    missing = set(job.required_skills) - set(cv.skills)
    if missing: reasons.append(f"缺少必备技能：{'、'.join(missing)}")
    return reasons   # 为空表示通过初筛，最终由人判断
```

## 常见坑

- **算法歧视**：用年龄、性别、学校等作为筛选条件。只用与岗位相关的硬性条件，不做自动淘汰的最终判断。
- **解析错误导致误筛**：简历格式各异。被筛掉的简历保留原因，HR 抽查。
- **候选人个人信息保护**：简历长期保存。明确保存期限，到期删除。

## AI 视角

**✨ AI 能增强**

- **AI 能做什么**：理解简历和岗位的匹配度，生成面试问题
- **不该交给 AI**：淘汰决定必须人做，避免歧视
- **怎么落地**：AI 给匹配分析和面试问题，人决定是否面试

## 面试怎么讲

30 秒讲法（方案思路；没有实际落地，面试时如实说明是设计过的方案）：

> 我会让各渠道的简历统一进入招聘系统，解析出年限、技能、期望城市，只按岗位的硬性条件筛除明显不符合的，并记录原因供 HR 抽查；合格的推给用人部门确认，确认后候选人在面试官的空闲时间里自选，自动发日历邀请和提醒，面试后提醒填写评价。

常见追问：

**问：自动筛简历有什么风险？**

答：可能引入歧视或误筛；只用和岗位相关的条件、保留原因、人工抽查，最终判断由人做。

**问：ATS 是什么？**

答：招聘管理系统，管理职位、简历、面试流程和录用。

**问：怎么缩短招聘周期？**

答：减少简历积压、自动约面试、及时收集面试评价、定期看各环节耗时。

**被问到「能不能用 AI」时：** AI 帮做简历匹配分析，但淘汰决定必须人做，避免算法歧视。
